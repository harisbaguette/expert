**상업용 전문가 에이전트를 자체 개발한다면, 실행 SDK 하나를 채택하고 직종별 판단·고객 데이터·완료 판정을 자체 코드로 소유하는 구성을 우선 권한다.** Python에서는 Pydantic AI와 Strands가 우선 비교 후보다. API 서비스까지 빨리 갖추려면 Agno, TypeScript에서 실행 과정을 세밀하게 바꾸려면 Pi가 대안이다. DeerFlow는 완성형 제품을 개조할 때의 유력 후보이자 기능별 재사용 대상으로 남긴다.

27개 후보를 실행 기반, 완성형 제품·기능 참고, 사용 범위에 제약이 있는 프로젝트로 정리했다. 2026년 9월 30일 기준 공식 저장소·문서·라이선스에 근거한다. 기능은 기본 브랜치 설명이고, 확인 판본은 별도로 표시했다. 둘의 기능 범위가 같다는 뜻은 아니다. 실제 업무 성공률과 유지보수 비용을 비교하기 전에는 어느 하나를 최선으로 확정할 수 없다.

Pydantic AI Harness는 별도 저장소를 본체로 **통합 중**이다. 새 구현을 시작할 때는 이전 저장소를 기준으로 고정하지 말고 본체의 `src/pydantic_ai_harness`를 본다. 기존 Harness는 0.x 버전 정책상 minor 업데이트에서도 API가 바뀔 수 있다. 코어의 안정성 정책과 동일하게 취급하지 않는다. 중단 후 복구도 단순 대화 저장과 다르며, 내구성 있는 실행에는 선택한 백엔드의 구성·운영이 따른다. [통합 안내·버전 정책](https://github.com/pydantic/pydantic-ai-harness), [실행 복구 문서](https://pydantic.dev/docs/ai/capabilities/durable_execution/overview/).

Pi는 `pi-ai`, `pi-agent-core`, `pi-durable`을 구분해서 선택한다. 특히 `pi-durable`은 API가 예고 없이 바뀔 수 있는 실험 기능이며, 기본 저장 구현에는 프로세스 간 잠금이 없다. 이를 곧바로 여러 서버가 공유하는 작업 엔진으로 간주하면 안 된다. [복구 모듈 설명](https://github.com/earendil-works/pi/blob/main/packages/durable/README.md), [격리 안내](https://github.com/earendil-works/pi#security).

Agno에는 별도의 MIT [Agent UI](https://github.com/agno-agi/agent-ui)가 있지만 이는 채팅 UI다. 업체가 제공하는 전체 관리 화면과 구분해야 한다. 이 UI의 README에는 Agno 2.x 호환 안내가 남아 있어, 현재 3.x 실행기와 결합하려면 호환 확인이 필요하다. [UI 라이선스](https://github.com/agno-agi/agent-ui/blob/main/LICENSE).

MIT·Apache의 고지 보존은 상용화 자체를 막는 조건이 아니다. MIT는 복사본·상당 부분에 저작권과 허가문을 남기는 것이 핵심이고, Apache 2.0은 배포 시 라이선스·관련 고지·변경 표시와 해당되는 NOTICE 등을 보존한다. 소스 라이선스가 업체의 상표 사용이나 외부 API 이용 권한까지 주지는 않는다. [MIT 원문 예시](https://github.com/pydantic/pydantic-ai/blob/main/LICENSE), [Apache 2.0 원문](https://github.com/strands-agents/harness-sdk/blob/main/LICENSE.APACHE).

**제약 코드의 참고는 공개된 기능·사용 흐름에서 우리 요구사항을 정리하고 자체 구현하는 방식으로 한다.** 원본 코드를 복사하거나 AI에게 변환시킨 결과에는 원본의 권리·조건이 남을 수 있다. 이름 변경이나 자동 재작성만으로 독립 구현이 되지는 않는다. 허용된 코드 재사용과 기능 참고를 구분하고, 실제 가져오는 코드·에셋·종속성의 출처와 적용 조건을 함께 보관한다.
