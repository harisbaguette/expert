# 재료의 세부 책임 57개

[목표 문서로](../전문가%20에이전트%20정의.md)

## 쓰는 법

재료는 능력을 실행할 기능과 책임의 목록이다. 개수와 폴더 모양은 합격 조건이 아니다. 각 업무에서 필요한 기능을 고르고, 입력·출력 계약과 검증 증거로 구현 여부를 확인한다. 공통 규칙은 [실행과 데이터](runtime.md), 최종 성과 판정은 [평가와 대체 판정](evaluation.md)에 둔다.

재료 상태는 `id`, `responsibility_key`, `scope_revision`, `applicability`, `activation_condition`, `condition_dependencies`, `dependencies`, `execution_triggers`, `implementation_status`, `verification_status`, `reason`, `owner`, `evidence`로 관리한다. 적용 여부는 required·conditional·not_applicable, 구현 상태는 planned·implemented, 검증 상태는 unverified·passed·failed·stale다. 과거의 verified 표시는 implemented와 유효한 passed 증거로 이관한다. not_applicable은 이유를 기록하고 구현·검증 상태를 null로 두며 합격 건수에 넣지 않는다. condition_dependencies는 조건 확인에 필요한 진단·관측의 의존, dependencies는 본 실행의 의존이다. 조건부 기능이 켜지면 해당 경로에서는 필수이며 의존 재료도 함께 확인한다. 실행 중인 코드가 남아 있어도 증거가 만료되면 검증은 stale가 된다.

### 재료의 적용 구분

본문과 세부 정의는 책임의 사용 방식을 **상시·단계별·조건부**로 구분한다. 아래 재료별 「적용 구분·시점」과 [본문 대응표](#본문과-세부-책임의-대응)를 함께 따른다. 하나의 세부 재료 안에서도 격리 책임은 상시 유지하고 도구 호출은 해당 단계에 수행할 수 있다. 그림·HTML·정의 2는 정본에서 생성하고 대응 검사를 통과한 열람본을 사용한다.

| 구분 | 뜻 |
|---|---|
| 상시 | 모든 업무의 진행 전반에서 유지·적용하는 책임. 매 순간 도구를 호출하거나 같은 검사를 반복한다는 뜻은 아니다 |
| 단계별 | 모든 업무의 접수·자료 확인·계획·검증·납품 등 해당 단계에서 수행하는 책임. 보통 그 단계에서 처리하고, 자료·전제·결과가 바뀌면 다시 수행한다 |
| 조건부 | 업무 특성이나 진행 중 상황에 따라 필요한 기능. 해당 조건이 충족되면 필수이며, 활성화에 필요한 의존도 함께 갖춘다 |

이는 개별 업무의 적용 여부(required·conditional·not_applicable)나 구현 상태와 다른 구분이다. 본문의 상시·단계별·조건부는 독자를 위한 요약 표시이며 실행 스위치로 사용하지 않는다. 실제 조립은 적용 여부·활성 조건과 `execution_triggers`를 각각 기록한다. 예를 들어 이관 필요성은 계속 판단하지만 실제 요청은 사유 발생 때만 전송하고, 회사 규칙은 해당 조직 업무에만 적용하되 적용되는 동안 계속 지킨다. 조건이 불명이면 확인 경로를 남긴다. 사용하지 않는 기능과 반드시 갖춰야 하는 판정·대체·검증 경로를 구별한다. 단계별을 ‘최초 1회만 확인하고 다시 보지 않음’으로 구현하지 않는다.

### 하위 책임과 지원 증거

ID는 M01–M57를 유지한다. 아래처럼 독립적으로 실패·변경·검증될 수 있는 부분은 `responsibility_key`로 구별한다. 나머지는 해당 ID의 `core`를 사용한다. 키는 실제 능력의 개수가 아니라 책임을 추적하는 식별자다.

| ID | 하위 책임 키 | 별도로 확인할 것 |
|---|---|---|
| M10 | connection / isolation | 프로그램 접속·호출·응답 / 실행 공간·파일·네트워크·고객 격리 |
| M18 | evidence / version | 주장을 지지하는 근거의 신뢰성·적합성 / 관측·효력·정정·사용 판본 |
| M27 | legal / professional | 관할·행위별 법적 의무 / 역할·관계별 직업상 의무 |
| M28 | agreement / platform | 합의 범위·변경권·종료 후 의무 / 외부 서비스·계정·제출 경로의 조건 |
| M54 | experiment / simulation | 실제 관측·표본·대조·개입 / 모형·가정·보정·현실과의 차이 |

각 키에는 담당·입력·출력·적용 조건·수행 시점·의존·실패 후 담당과 지원 증거를 붙인다. 증거는 `업무 범위 + 하위 책임 + 모델/도구/환경/자료 판본 + 수행한 작업 + 결과·검사 + 유효 조건`에 연결한다. 상위 재료의 합격은 이번 경로에 필요한 모든 하위 책임의 유효한 합격을 요구한다. 선택 기능의 합격으로 필수 기능의 실패를 상쇄하지 않는다. 구현됨·시험 통과·이번 업무에 적합함은 각각 확인한다.

M03·M25처럼 본문에서 한 줄로 설명한 책임도 내부 상태를 합치지 않는다. 장애 뒤 데이터가 복원된 증거와 복원된 사건 상태가 현재 사실·권한에 맞는 증거는 따로 필요하다. 여러 자료·직무에 걸친 유효성 변경은 M20·M25가 영향받는 증거를 stale로 바꾸고 M35·M49가 재검토·재시험 범위를 정한다.

### 직무별 조립

공통 정의를 재사용하고 **직무 정의와 개별 위임 조건을 적용**한다. 여러 전문 분야가 필요한 업무는 정의를 함께 연결하되, 충돌을 마지막 값으로 덮어쓰지 않는다. 아래는 새 재료가 아니라 기존 재료를 채우는 공통 형식이다.

| 직무 정의에서 채울 것 | 담당 재료 |
|---|---|
| 세부 업무·대상·난도·관할·목표·권한·외부 의존 | M17·M27·M31·M33·M36·M39 |
| 핵심 객체·관계·방법·질문·판단 지점·예외·숙련 사례 | M18·M21·M22·M25·M34·M35 |
| 입력·산출·행동·전문 도구·작업 환경·재사용 자산 | M07·M09·M10·M52·M53·M54·M55·M56 |
| 상대·채널·언어·관계·설명·교육·협상·개입 | M08·M23·M38 |
| 조건부 기능·의존·대체 경로·공동 작업·전환·복구 | M02·M03·M04·M25·M35·M41·M50·M57 |
| 완료·인수·허용 결론·실패 기준·성과·비교 평가 | M36·M40·M42–M49·M51 |

기능 선택은 직무명이나 파일 확장자만으로 정하지 않는다. 실제 요구·작업·환경으로 적용을 판단하고 필요한 재료·자산·도구·외부 수행의 의존을 빠짐없이 연결한다. 조건을 모르면 미적용으로 넘기지 않고 확인할 정보와 해당 경로의 대기를 남긴다. 새 사실·요구·권한·환경 변경 때 관련 선택을 다시 계산한다.

계통은 재료의 주된 출력과 책임으로 구분한다. 구현 도구·저장 위치·호출 시점이나 다른 계통에서 그 결과를 사용한다는 이유로 소속을 바꾸지 않는다. 한 책임은 한 재료가 소유한다. M56은 시스템 처리, M57은 운영 감시·복구, M21은 업무 방법, M22는 숙련 선택, M35는 이번 업무의 설계·순서, M55는 재사용 자산, M09는 제작, M10은 실행 환경, M40은 인수다. 코드·파일은 공유할 수 있으나 같은 내용을 여러 정본에 복사하지 않는다. 기존 책임으로 표현할 수 없는 입출력·판정이 확인될 때만 재료 추가를 검토한다.

[조립 계약](runtime.md#직무-조립-계약)에 따라 누락·충돌·의존과 조건별 경로가 정리되면 정의가 완성된다. 재료의 구현·실증 상태와 실제 전문가 대체 판정은 별도로 관리한다.

세부 책임은 환경 10, 자료·검색 11, 지식·경험 2, 기억·상태 2, 규칙·권한 9, 행동 체계 5, 실무 8, 검증·평가 8, 학습·개선 2로 합계 57개다. 본문의 설명 항목 59개와는 아래 대응표로 연결한다.

현재 적용 범위는 화면·문서·시스템·통신 안에서 끝나는 업무다. 설계·분석에 필요한 현장 원자료를 읽는 것과 새로운 실측·시공·시술·촬영·실물 인도를 직접 수행하는 것을 구별한다. 후자는 이번 구축과 대체 판정의 범위 밖이다. 기존 직무 사례는 당시의 범위·가정을 보존하며 현재 지원 범위를 자동으로 넓히지 않는다.

## 구조 기준선

기준선 v2는 **본문 59개 항목·세부 책임 M01–M57·9계통**이다. v1에서 재료 수는 유지하고 하위 책임의 상태·지원 증거와 실행·대기·변경·대체 판정의 연결을 보완했다. 고정 대상은 책임의 의미, 입력·출력과 실패·대기·복구의 연결이다. 직무별 지식·판단 방법·도구·규칙 원문·계정·고객 조건·수치는 기존 책임 안에서 갱신한다. 새 내용이나 어댑터가 생겼다는 이유로 재료 ID를 추가하지 않는다.

기존 책임으로 소유할 수 없는 구체적인 입력·출력이 실제로 발견될 경우에만 근거와 영향을 검토해 구조 판본을 바꾼다. 이는 알려진 빈자리를 미루는 절차가 아니며 이번 검토의 발견·해결·남은 실증 범위는 [기준선 검토](reviews/material-baseline-review.md)에 기록한다. 새 상황을 무조건 M50에 배정해 책임 누락을 숨기지 않는다.

각 재료의 하위 작업도 `입력·선행 조건 → 담당 작업 → 출력·검증 → 실패/불명 시 담당·재개 조건`을 가진다. 같은 코드와 기록을 공유해도 업무 결정의 소유자는 하나로 정한다. 정상 경로뿐 아니라 취소·일부 성공·응답 유실·복구 실패·권한 철회·검사 불가를 다룬다. 역할을 확정한 사실은 구현·전문가 대체의 합격을 뜻하지 않는다.

## 본문과 세부 책임의 대응

본문의 59개 설명 항목과 세부 책임 M01–M57의 공식 대응이다. 본문은 쉬운 이름과 사용 관점으로 묶고, 세부 정의는 입출력·검증 책임을 추적한다. 별칭 변경을 새 기능 추가로 세지 않는다. 각 책임은 한 곳에서 정의하고 본문·상세 구상·실행 계약에서 참조한다.

M03·M25와 M12·M13은 본문에서 각각 한 행으로 설명한다. M41은 표 앞의 업무 처리 흐름과 실무 도입문으로 설명하며 상시 책임을 유지한다. M10은 도구 연결과 격리 실행, M18은 근거 평가와 시점·판본, M27은 법·의무 기준과 직업 윤리·의무, M28은 계약과 플랫폼·제출처 규정, M54는 실제 실험과 모의 시험으로 각각 두 행에 나눠 설명한다. 따라서 `57 − 2(설명 통합) − 1(흐름 설명문) + 5(설명 분리) = 59행`이다. ID는 M01–M57를 유지하되 나눈 하위 책임은 각각 입력·적용 조건·검증 증거를 추적한다.

아래 구분은 본문에 표시한 책임의 적용 방식이다. M10의 도구 호출은 단계별, 격리 책임의 유지는 상시이므로 같은 세부 ID가 두 행에서 다른 구분을 갖는다. M03의 상세 소속인 환경과 M25의 기억·상태도 본문에서는 현재 진행 상태 한 행으로 설명한다. 이름·행 수·배치를 단순 문자열 일치로 검사하지 않고 이 대응과 책임 경계를 대조한다.

## 학습·개선

검증·평가가 제공한 실패·시험·성과를 받아 원인과 보완 대상을 찾고, 지식·규칙·도구·정의를 지속 개선한다. 시험 실행과 성과 측정은 M49·M51을 호출하며 그 책임을 복제하지 않는다.

|---|---|---|---|---|
| M48 실패 원인 분석 | 복수 원인 가설을 검증하고 실제 수정 대상·영향 범위를 정한다 | 오류 분류·원천 대사·재현 방법·수정 담당 | 도구 버그·환경 변화·판단 실패를 구분하며 근거 없는 원인 확정을 하지 않는다 | **조건부**<br>실패·오류·기대 미달이 발견되면 원인 분석 |

## 연결 확인

각 업무의 기능 연결은 입력 → 해석 → 판단 → 권한 → 실행 → 외부 확인 → 결과와 후속 성과로 이어져야 한다. 시스템 처리에는 M56, 운영 장애에는 M57을 연결한다. 모든 대기에는 재개 신호·기한·담당을, 실패에는 복구/대체/종료의 다음 담당을 연결한다. 재료마다 담당 모듈 또는 외부 서비스와 증거 참조를 붙여 누락된 연결을 찾는다. 모듈 이름이 재료 이름과 다르다는 이유로 실패시키지 않는다.

공통 재료도 업무별 검증은 필요하다. 예를 들어 저장 기능 코드는 같아도 기한·보존·기억의 의미가 다르고, 모델은 같아도 필요한 판단 능력과 데이터 이동 조건이 달라진다. 둘째 직무에 그대로 적용할 수 있는지는 실측으로 결정한다.

## 전문 작업의 연결

요구·설계 명세(M35·M36) → 자료·구조 읽기(M07)·업무 자산(M55) → 필요한 데이터 처리(M52)·계산(M53)·실험(M54)·제작(M09) → 대상별 검증(M42·M46) → 납품·인수(M40)로 잇는다. 전 과정의 실행 환경은 M10, 상태·변경 영향은 M25, 새로운 기능 확보는 M50이 맡는다. 파일 없는 거래·서비스 운영은 M10의 외부 상태와 M36·M51의 성과로 끝을 확인한다.

각 기능은 형식·프로그램/버전·작업 종류·환경별 지원·미지원·미검증 조건과 증거를 가진다. 구현 상태(planned·implemented), 검증 상태(unverified·passed·failed·stale), 실제 지원 범위는 구별한다. 새 능력은 기존 시험의 통과만으로 인정하지 않는다. 공통 입출력 계약은 [실행과 데이터](runtime.md#전문-작업과-산출물-계약), 대상별 인수 시험은 [평가 규약](evaluation.md#전문-작업의-평가-범위)을 따른다.

## 복합 업무의 연결

사건·당사자·쟁점·증거·가설의 상태(M18·M25)에서 통합 전략(M34)을 세우고, 조건부 계획(M35)을 공동 작업(M04)으로 실행한다. 당사자별 권한·정보 경계(M27·M31·M32)와 결합 손실(M33·M53·M54)을 전 과정에 적용한다. 상대 반응(M38)·새 관측·검증(M43)으로 전략을 갱신하며, 현실에서 확보하지 못한 증거와 전문 개입(M39)을 완료 판정에서 숨기지 않는다.

57개는 책임을 추적하는 세부 정의의 개수이며 본문은 이를 59개 설명 항목과 업무 흐름으로 풀어 쓴다. 업무별 연결·상태·제약과 실제 실행 증거가 있어야 해당 범위의 능력을 주장할 수 있다. 세부 계약은 [복합 업무의 상태·전략·협력](runtime.md#복합-업무의-상태전략협력), 직무별 업무 검토는 [166개 직무 검토](reviews/occupation-work-review.md)를 따른다.
