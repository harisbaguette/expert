# 재료 55개

[목표 문서로](../전문가%20에이전트%20정의.md)

## 쓰는 법

재료는 능력을 실행할 기능과 책임의 목록이다. 개수와 폴더 모양은 합격 조건이 아니다. 각 업무에서 필요한 기능을 고르고, 입력·출력 계약과 검증 증거로 구현 여부를 확인한다. 공통 규칙은 [실행과 데이터](runtime.md), 최종 성과 판정은 [평가와 대체 판정](evaluation.md)에 둔다.

업무 정의의 재료 상태는 `id`, `applicability`, `implementation_status`, `reason`, `owner`, `evidence`로 기록한다. 적용 여부는 required·optional·not_applicable, 구현 상태는 planned·implemented·verified다. 해당 없음의 구현 상태는 null로 두고 제외 이유를 쓴다. required인데 미구현이면 그 재료가 필요한 업무 경로를 열지 않는다. optional을 켠 경우에도 해당 기능과 다른 기능에 주는 영향을 검증한다.

‘구현됨’은 기능이 존재한다는 뜻, ‘검증됨’은 명시한 조건에서 시험했다는 뜻이다. 마지막 열의 검증은 재료 수준의 확인이며 업무 대체 합격을 대신하지 않는다.

기존 M01–M51 ID는 유지하고 M52 데이터 처리·M53 계산·분석·최적화·M54 실험·시뮬레이션·M55 업무 자산을 추가한다. 계통별 재료 수는 환경 14, 자료·검색 10, 지식·경험 3, 기억·상태 2, 규칙·권한 8, 행동 체계 7, 실무 1, 검증·평가 6, 학습·개선 4로 합계 55개다.

모델 공급자의 기능·캐시·가격은 어댑터와 기술 결정 기록에서 관리한다. 모든 모델이 같은 캐시 구분점·수명·추론 설정을 가진다고 가정하지 않는다. 추론 강도를 건마다 또는 단계마다 고정할지는 실제 품질과 캐시 동작으로 결정한다.

실시간 통로에서 검색이 필요하면 비동기로 조회하고 불확실성을 드러낸다. 만남 전 자료만 보도록 고정해 새 사실에 대응할 수 없게 만들지 않는다. 되돌릴 수 없는 약속은 사전 위임의 범위 안에서만 하며, 범위 밖이면 확인 뒤 답할 시간을 확보한다.

## 연결 확인

각 업무의 기능 연결은 입력 → 해석 → 판단 → 권한 → 실행 → 외부 확인 → 결과와 후속 성과로 이어져야 한다. 재료마다 담당 모듈 또는 외부 서비스와 증거 참조를 붙여 누락된 연결을 찾는다. 모듈 이름이 재료 이름과 다르다는 이유로 실패시키지 않는다.

공통 재료도 업무별 검증은 필요하다. 예를 들어 저장 기능 코드는 같아도 기한·보존·기억의 의미가 다르고, 모델은 같아도 필요한 판단 능력과 데이터 이동 조건이 달라진다. 둘째 직무에 그대로 적용할 수 있는지는 실측으로 결정한다.

## 전문 작업의 연결

요구·설계 명세(M35·M36) → 자료·구조 읽기(M07)·업무 자산(M55) → 필요한 데이터 처리(M52)·계산(M53)·실험(M54)·제작(M09) → 대상별 검증(M42·M46) → 납품·인수(M40)로 잇는다. 전 과정의 실행 환경은 M10, 상태·변경 영향은 M25, 새로운 기능 확보는 M50이 맡는다. 파일 없는 거래·서비스 운영은 M10의 외부 상태와 M36·M51의 성과로 끝을 확인한다.

각 기능은 형식·프로그램/버전·작업 종류·환경별 지원·미지원·미검증 조건과 증거를 가진다. 구현 상태(planned·implemented·verified)와 실제 지원 범위는 구별한다. 새 능력은 기존 시험의 통과만으로 인정하지 않는다. 공통 입출력 계약은 [실행과 데이터](runtime.md#전문-작업과-산출물-계약), 대상별 인수 시험은 [평가 규약](evaluation.md#전문-작업의-평가-범위)을 따른다.

## 복합 업무의 연결

사건·당사자·쟁점·증거·가설의 상태(M18·M25)에서 통합 전략(M34)을 세우고, 조건부 계획(M35)을 공동 작업(M04)으로 실행한다. 당사자별 권한·정보 경계(M27·M31·M32)와 결합 손실(M33·M53·M54)을 전 과정에 적용한다. 상대 반응(M38)·새 관측·검증(M43)으로 전략을 갱신하며, 현실에서 확보하지 못한 증거와 전문 개입(M39)을 완료 판정에서 숨기지 않는다.

55개는 기능의 개수다. 업무별 연결·상태·제약과 실제 실행 증거가 있어야 해당 범위의 능력을 주장할 수 있다. 세부 계약은 [복합 업무의 상태·전략·협력](runtime.md#복합-업무의-상태전략협력), 직무별 업무 검토는 [166개 직무 검토](reviews/occupation-work-review.md)를 따른다.
