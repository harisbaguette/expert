# 056. 외주 개발 (웹·앱)

유형: 위임형  
검토 방식: 단계별 사건·도구 응답을 가정한 작성자 탁상 모의; 실제 에이전트 실행 아님

**최종 판정: 목표·조건 조정 필요**

## 초기 복합 사건

예약 서비스 개발 중 중복 결제와 일정 충돌이 발견되고 발주자가 관리자 기능을 추가하면서 출시일은 유지하길 원함

## 단계별 전개

| 단계 | 내용 |
|---|---|
| 변화 1 | 결제 응답 유실과 예약 충돌이 재현됨 |
| 선택 1·재료 | M25·M35: 거래 불변조건·중복 방지·변경 범위부터 수정 |
| 변화 2 | 발주자가 추가 기능·출시일·예산 모두 고수하고 가능 작업량 초과 |
| 선택 2·재료 | M33·M35·M38: 필수 수정과 확장 요구의 자원 충돌 제시 |
| 첫 도달 상태 | 원래 모든 기능의 납기 충족 불가, 범위·시간·예산 조정 필요 |
| 첫 판정 | 목표·조건 조정 필요 |
