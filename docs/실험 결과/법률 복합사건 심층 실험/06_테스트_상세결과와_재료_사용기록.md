# LEGAL-001 테스트 상세 결과와 재료 사용 기록

이 문서는 기존 법률 복합사건 실험을 **증거 → 재료별 처리 → 판단·산출물 → 실제 검사 → 남은 한계**로 다시 연결한 별도 보고서다. 새 법률 사건이나 새 성능 시험을 실행한 성적으로 합산하지 않는다.

## 1. 판정과 읽는 법

**이번 사건에서 새 재료·수식 연산자가 반드시 필요한 반례는 확인하지 못했다. 그러나 모든 재료가 구현·검증됐거나 법률 사건이 해결됐다는 결과도 아니다.** 기존 책임 안에서 금액의 의미·범위, 서면의 시점·수신자·절차, 주총의 분모와 선행조건을 구체화했다. 법률 전문성·현장 취득·기관 수행과 독립 평가는 남았다.

실험 대상은 개인 의뢰인 강도윤의 관계회사 선급금60억원, 그 안의 개인 경유12억원, 회사의 손해배상 청구, 구속영장과 주총 문제다. 모든 인물·회사·증거·기관 반응은 가상이다. 법령·판례는 [기존 공식 근거 기록](02_법적_근거와_미확인사항.md)에 원문 링크와 적용 한계를 남겼다.

| 항목 | 실제 범위 |
|---|---|
| 가상 증거 | 24개 파일, 공개 단계0~10 지정 |
| 법률 쟁점 | 18개, 공격·방어·미확인 자료·재료 매핑 |
| 후속 변화 | 10개, 초기 포함 상태11개 |
| 작성한 실무 문서 | 7개 Markdown 파일 |
| 코드 검사 | C01~C24, 지정한24개 assertion 통과 |
| 결함 주입 | C24 안의 명시적 메타데이터5종; 별도5개 사건으로 세지 않음 |
| 외부 목표 | 마지막 가상 분기에서 영장 기각 실패 |
| 전문성 판정 | 독립 변호사 심사·블라인드 모델 평가 미실행 |

**통과의 단위는 각 검사 조건이다.** C06의 태그 비교와 C17의 일정 열거는 검증 깊이가 다르다. 24/24를 법률 정확도100%·전문가 대체율·사건 해결률로 읽으면 안 된다. 각 검사 상세에 실제로 실행한 것과 검사하지 않은 것을 함께 적었다.

## 2. 수식의 실제 대입

`A = Compose(M_required, G_case, C)`는 책임을 조립하는 개념식으로 사용했다. Python이 이 식을 읽어55개 모듈을 자동 호출한 것은 아니다. `run.py`는 작성자가 정한 사건 상태와 한정된 검사 함수다.

| 구성 | 이 사건에서 채운 내용 | 실제 근거 |
|---|---|---|
| M_required | 아래 재료별 대장에 실제 작성·코드 실행·가정·미실행으로 기록 | material_usage.json·재료 사용 CSV |
| G_case | 거래TX01~05 → 증거E01~24 → 쟁점I01~18 → 계산·전략·서면. 개인/회사와 공개 범위를 구별 | case.json·쟁점표·초안 문안 |
| C | 개인만 위임, 기소 전 절차, 실제 외부 송금·제출 없음, 주총·현금·검토시간의 가상 제약 | E01·E08·E09·E10·E22·E24 |

대표적인 연결은 M07로 읽은 가상 대사 E11 → M18의 출처·시점 → M25의 상태 변경 → M53의 원금 계산 → M34의 전략 수정 → M09의 문안 작성 → M35·M31의 문안 계약 → M42의 제한 검사 → M40의 사용자 전달이다. 이 연결에서 **법적 의미를 부여한 작업은 작성자의 판단**, **수치·명시된 메타데이터를 비교한 작업은 코드 실행**이다.

### 참여방식 집계

| 참여방식 | 재료 수 | 의미 |
|---|---:|---|
| 조회·판단·문서 작성 | 24 | 원문 조회·사건 해석·문안·기록 작성에 사용. 전문 판단 검증을 뜻하지 않음 |
| 코드로 일부 기능 실행 | 16 | 책임의 일부를 로컬 코드로 실행. 재료 전체 구현 합격이 아님 |
| 가상 조건·설계에만 반영 | 9 | 입력·계획의 가상 조건으로만 반영. 해당 전문 기능은 실제 실행 안 함 |
| 이번 실험에서 미실행 | 6 | 이번 사건에서 실행 증거 없음 |

한 재료는 대표 참여방식 한 곳에 집계했다. 같은 검사에 여러 책임이 연결돼도 검사 수를 중복으로 늘리지 않는다. 코드 실행이라고 표기된 재료도 세부 한계를 읽어야 한다.

### 6.1 다섯 결함을 넣은 실제 검증 함수

`validate_artifact()`는 공개 단계·기준값·절차·수신자·금액 목적을 검사한다. 정상 후보의 내부 수신을 허용한 뒤 하나씩 결함을 넣어 거부되는지 확인했다. 따라서 모든 것을 무조건 차단하는 검사와 구분된다.

| 결함 | 바꾼 값 | 관측 오류 |
|---|---|---|
| 미래 정보 | 단계9 문안에 단계10의 E23 추가 | future_evidence |
| 과거 근거 | 현재 납품22 대신28을 basis에 입력 | stale_basis |
| 절차 불일치 | 미구속용 문안을 기소 전 구속 상태에 적용 | wrong_procedural_phase |
| 수신자 위반 | 개인 내부용 문안을 회사 대리인에게 전달하는 후보 | unauthorized_recipient |
| 금액 의미 전용 | 원금 대사값의 use_as를 criminal_gain으로 변경 | amount_meaning_mismatch |

이 검증은 문안의 **별도 메타데이터**를 사용한다. 본문의 법적 주장·수치·증거 인용을 자동 추출해 태그와 대조하지 않았다. 실제 문안에 잘못된 금액을 쓰고 태그만 올바르게 입력하면 놓칠 수 있다. 이 연결을 추가 검증해야 한다.
