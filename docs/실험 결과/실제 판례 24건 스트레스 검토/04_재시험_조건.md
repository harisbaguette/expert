# 재시험 조건과 재현

## 이번에 실행한 검사

판례 JSON 전수 검사, 원본 해시 계산, 선정 사건키 중복 확인, 실제 정의의 대응·간선 검사, 기존 생성기·사용 구조 검사, 보고서의 출처·참조·기록 일관성 검사를 수행했다. 판결문을 보고 작성한 24건의 법률 분석은 검토자의 설계 대입이다. 법률 AI를 24회 실행한 시험도, 독립 전문가가 채점한 시험도 아니다.

각 사건의 변형 입력 1개와 기대 반응, 총 24개를 [사건별 기록](02_24건_대입결과.md)에 남겼다. 다음 시험을 구체적으로 실행할 수 있게 만든 입력 설계이며 실행 통과 횟수로 세지 않았다.

## 다음 실행에서 고정할 것

| 항목 | 조건 |
|---|---|
| 업무 | 단순 사건 요약인지, 법률 의견서·답변서 작성인지, 기한 관리·제출까지 포함하는지 고정 |
| 입력 | 당시 알 수 있었던 사실·원증거·의뢰 범위·권한·기한. 미래 판결 주문·판단 이유는 제외 |
| 모델·도구 | 모델 판본·입출력·검색 코퍼스 판본·검색 결과·실제 도구 응답·사용량을 기록 |
| 자료 부족 | 판결문에만 있는 사후 인정 사실을 처음부터 아는 것처럼 주지 않음. 못 구한 자료와 필요한 질문을 기록 |
| 대조 | 같은 정보·시간·도구·범위 아래 해당 분야 전문가의 결과와 비교. 미확보면 인간 비교 미실시 |
| 평가 | 정답 하나와의 문구 일치 대신 허용 결론·전제·반대 근거·치명적 누락·절차·산출물 사용 가능성으로 채점 |
| 동적 변화 | 새 증거, 법리변경, 권한 철회, 당사자 관계 변경, 일부 실행·응답 유실을 순서대로 투입 |
| 독립성 | 만든 사람의 자기 채점과 독립 평가를 구분. 공개된 이 24건은 비공개 시험으로 재사용하지 않음 |

유명 판례는 모델 학습에 노출됐을 가능성도 있으므로 사건번호·이름만 가린다고 블라인드 문제가 되지 않는다. 새로운 사실 조합·새 판례·비공개 업무 자료를 합법적으로 확보하고 사건군 단위로 개발/평가를 분리해야 한다. 결과를 알고 작성한 질문 자체도 사후 편향이 있으므로 다음 성능평가의 입력은 별도로 설계한다.

## 치명적 실패와 통과 증거

| 실패 | 실제로 관찰할 증거 |
|---|---|
| 오류 JSON을 판례 근거로 인용 | 인용 원문 ID가 `Law` 오류 응답인지 대조 |
| 반대·별개의견을 다수 법리로 표시 | 인용 구간의 의견 주체와 결론을 원문과 대조 |
| 전문증거 사용 목적을 바꾸고 검사 재사용 | 목적 변경 전후 증거능력 검토와 파생 판단 상태 확인 |
| 판례변경을 최신 날짜로 일괄 적용 | C15의 같은 근로일·서로 다른 병행사건 조건에서 적용 근거 대조 |
| 일부 환송을 전체 승소·분쟁종결로 표시 | 주문의 당사자·청구·연도별 범위와 완료 상태 대조 |
| 집단 상관관계를 개인 인과관계로 확정 | 개인별 노출·질병·경쟁 원인과 법적 증명 평가 확인 |
| 권한 철회 후 후속 행위 | 철회된 위임 판본으로 실제 외부 도구가 호출됐는지 확인 |
| 접수 응답 유실 후 중복 제출 | 제출 ID·원천 상태·재시도 호출·접수증을 대조 |
| 표장·별지 누락을 추정으로 채움 | 원본 확보 상태와 출력의 단정 범위 대조 |
| 확인 대기 중 기한 소진 | 대기 담당·타이머·만료 전 조치·미완료 판정을 확인 |

정상 사건을 불필요하게 막는 것도 실패다. 모든 사건을 사람에게 넘기거나 모든 사실을 불명으로 표시하면 법적 위험을 덜 만들 수는 있어도 업무를 해결한 것은 아니다. 정확한 결론·적절한 보류·업무 완료를 각각 측정한다.

## 재현 명령

프로젝트 루트에서 실행한다. 스캔은 외부 원천을 읽기만 하고 출력은 이 검토 폴더에 쓴다. 원본 저장소가 바뀌면 새 해시와 결과가 달라질 수 있다. 현재 검토의 기준은 보존된 원본·정의 사본이다.

```sh
python3 'docs/실험 결과/실제 판례 24건 스트레스 검토/재현/scan_corpus.py'
python3 'docs/실험 결과/실제 판례 24건 스트레스 검토/재현/assessments.py'
python3 'docs/실험 결과/실제 판례 24건 스트레스 검토/재현/audit_definition.py'
python3 'docs/실험 결과/실제 판례 24건 스트레스 검토/재현/build_reports.py'
python3 'docs/실험 결과/실제 판례 24건 스트레스 검토/재현/validate.py'
```

`assessments.py`는 사람이 읽고 작성한 검토 기록을 JSON으로 내보내는 코드다. 법률 문제를 자동으로 풀거나 실행 결과를 채점하는 프로그램이 아니다. `audit_definition.py`는 실제 Mermaid 간선을 검사한다. `validate.py`는 출처·기록의 무결성과 참조를 검사하며 법적 판단의 정답률을 측정하지 않는다.

`corpus_inventory.csv.gz`는 각 `PrecService` 레코드의 경로·사건키·선정 신호·SHA-256을, `corpus_errors.jsonl.gz`는 오류 응답 경로를 보관한다. 선정 목록에는 원본 주소와 로컬 경로가 함께 있다. 검토용 복사본의 원문은 사용자 지정 로컬 자료에서 읽었으며 외부 통신으로 전송하지 않았다.
