# 설계를 좌우하는 바깥 사실 7건 조사

대상: `파일-폴더-구조.md`, `공장 구현 설계.md` 비판에서 확인하지 못한 사실. 조사일 2026-10-23.

## 핵심 발견
1. 홈택스는 세무사 한 명의 인증서로 여러 수임 고객을 다룰 수 있음. 다만 고객마다 동의를 받아야 하고, 신고기간 안에 다시 내면 마지막 신고만 유효함. 자동 수집을 막는 조문은 국세청 고시에 없지만, 국세청은 대량 스크래핑을 실제로 차단하고 있음.
2. 로앤비(Thomson Reuters 약관)는 스크래핑, 자동 수집, API 연결, AI 학습을 명시적으로 금지함. 반면 판결 본문과 법령은 영리 목적이어도 자유롭게 쓸 수 있음. Anthropic 상용 API는 입력을 학습에 쓰지 않고 기본 30일 안에 지우며, ZDR은 영업팀 계약이 있어야 켜짐.
3. 인공지능기본법 과태료는 법령이 아니라 과기정통부 방침으로 유예되고 있음. 가장 이른 부과 시점은 2027-01-22이고, 10월 23일 기준 연장이나 종료 발표는 찾지 못함. 카카오톡 개인 대화는 내보내기 파일로만, 비즈니스 채널 상담은 상담톡(공식 딜러사 API)으로만 받을 수 있음. Podman Machine에는 추가 디스크를 붙이는 옵션이 없고, `rm`을 하면 VM 안의 볼륨도 함께 지워짐.

조사일은 모두 2026-10-23임. 등급 표기는 원문 확인(1차 원문을 직접 받아 대조), 2차 출처, 미확인임.

### 1. 홈택스 세무대리인 계정
- **수임 방식** (원문 확인): 「홈택스 이용에 관한 규정」(국세청 고시, 2025-05-27 시행) 제55조②는 "세무대리인은 수임납세자가 인증서, 서면신청 등의 방식으로 세무정보 제공 및 조회에 동의를 해야만 홈택스에서 … 조회할 수 있다"고 정함. 같은 조 ①항에 따라 세무대리인은 수임납세자의 사업자등록번호 등을 입력하고 "세무정보 이용 동의서를 제출받아 보관하여야" 함.
- **등록 절차** (원문 확인): 한국세무사회 안내 PDF(발행일 표기 없음)의 절차는 이 순서임.
  1. 세무대리인이 "세무대리인 사업자용 공동인증서"로 로그인해 신고대리 납세자를 등록함.
  2. 납세자가 "세무대리정보 → 나의 신고대리 수임 동의"에서 동의함. 간편인증으로 로그인해도 되고, 세무서에 서면으로 내도 됨.
- **한 계정으로 여러 고객**: 수임납세자를 고객마다 입력하는 구조이므로 가능하다고 판단함. 다만 "여러 명"이라고 적은 조문은 없어 구조에서 추론한 것임.
- **자동화 약관**: 고시 전문에서 자동화, 스크래핑, 비정상 접근, 과부하를 검색했으나 해당 조문이 없음. 홈택스 웹 이용약관 원문은 받지 못함(미확인).
  - 실무에서는 국세청이 차단함. 머니투데이(2025-05-20)에 따르면 "국세청은 지난 7일부터 삼쩜삼 등 민간 세무 플랫폼의 홈택스 접속을 차단했다". 국세청은 이를 "전자정부법에 따라 홈택스 시스템의 안정적인 운영을 위한 조치"라고 설명함.
  - 세정일보(2025-05-28) 보도: 5억1600만원 규모의 스크래핑 대응 ISP 사업을 발주함.
  - 이데일리(2026-09-24) 보도: 국세 API 과금안(월 50만원 등록비 등)이 검토됨.
- **설계에 주는 영향**: 수임 동의를 받은 고객만 조회 대상으로 삼아야 함. 홈택스 자동 조회는 신고기간에 예고 없이 막힐 수 있으므로 사람이 화면에서 하는 조회를 기본으로 두고, 자동 수집은 보조 경로로만 써야 함.

- **반대 근거**: 판결 본문 자체는 자유롭게 쓸 수 있음. 그러나 저작권법 제93조②는 DB의 일부라도 "반복적이거나 특정한 목적을 위하여 체계적으로" 복제하면 상당한 부분을 복제한 것으로 봄. 상용 DB에서 공개 판결만 골라 대량으로 긁어도 위험함.
- **설계에 주는 영향**: 상용 DB와 주석서는 사람이 열람하고 필요한 부분만 인용하는 방식으로만 써야 함. 사내 RAG용 원문 창고는 법령정보 API와 판결 공개 자료만으로 채워야 함.

### 3. Anthropic API(상용)
- **보관 기간** (원문 확인): "we automatically delete inputs and outputs on our backend within 30 days of receipt or generation"(privacy.claude.com). 예외는 Files API, ZDR 계약, 이용정책 위반, 법적 요구임. 위반으로 표시된 경우 입력과 출력은 최대 2년 보관함.
- **학습 사용** (원문 확인): 상용 약관(2025-06-17판)에 "Anthropic may not train models on Customer Content from Services."라고 되어 있음. 개인정보 안내 문서도 상용 제품의 입력과 출력을 기본적으로 학습에 쓰지 않는다고 함. 예외는 피드백(엄지 버튼)을 보낸 경우임.
- **ZDR 조건** (원문 확인): 영업팀에 요청해야 하며 "ZDR is enabled per organization"임. 적용되면 응답을 돌려준 뒤 프롬프트와 응답을 저장하지 않음.
  - 적용되지 않는 것: 코드 실행 등 표에서 "No"로 표시된 기능, CORS, Claude for Excel, Teams와 Enterprise 화면.
  - Claude Fable 5, Fable 5.1, Mythos 5, Mythos 5.1은 "require 30-day data retention and are not available under ZDR unless expressly authorized"임. 이 모델을 쓰려면 별도 작업공간에서만 30일 보관을 켤 수 있음.
- **설계에 주는 영향**: 고객 자료를 보내는 경로는 ZDR이 켜진 상용 조직으로만 하고, 코드 실행 도구와 Covered Model은 고객 자료 경로에서 빼야 함.

### 4. 인공지능기본법 제31조 과태료 부과 시작 시점
- **과태료 근거** (원문 확인): 제43조①1호에 따라 "제31조제1항을 위반하여 고지를 이행하지 아니한 자"에게 3천만원 이하의 과태료를 부과함(법률 제21311호, 2026-07-21 시행본). 제31조②③(결과물 표시) 위반은 제43조 과태료 항목에 없음.
- **유예** (원문 확인): 과기정통부는 법 시행일 2026-01-22에 "최소 1년 이상 규제를 유예한다"고 발표함(korea.kr, 2026-01-21). MSIT 영문 공지도 "grace period of at least one year before administrative fines"라고 밝힘. 시행령 부칙(2026-08-20판)에는 과태료 유예 조문이 없음. 법적 근거가 아니라 행정 방침이라는 뜻임.
- **결론**: 가장 이른 부과 시점은 2027-01-22임. 그전에도 인명사고, 인권훼손 같은 "극히 예외적인 경우"에는 사실조사를 할 수 있음.
- **반증 시도**: 연장이나 종료를 공식 발표했는지 한국어와 영어로 찾았으나 찾지 못함. CEO스코어(2025-12-24)는 정부가 "유예기간을 추가로 연장하는 방안도 열어두었다"고 보도함.
- **설계에 주는 영향**: 고지 의무는 2026-01-22부터 이미 생김. 첫 화면 고지를 지금 구현하고, 결과물 표시는 과태료와 관계없이 넣어야 함.

### 5. 중복 제출 방지 장치
- **홈택스** (원문 확인): 요청 번호로 중복을 막는 장치는 없고, 덮어쓰는 방식임.
  - 고시 제15조①: "같은 신고기간에 … 다시 전자신고하는 경우에는 최종 전자신고한 내용이 정당하게 신고된 것으로 본다". 예외는 인지세 선납이며, 이 경우 보낸 것이 모두 유효함.
  - 제13조: 접수증을 출력해 보관해야 함. 제16조: 법정기한 후 2일 안에 삭제를 요청할 수 있음. 기한이 지난 뒤에는 수정신고로 고침(국세상담센터 FAQ).
- **4대보험 EDI**: 건강보험 EDI 도움말(원문 확인)에는 신고문서 목록에서 "접수 / 정상 / 반송" 처리결과를 조회하는 기능만 있음. 중복 신고를 반송하는 규정은 공식 문서에서 찾지 못함. 노무 블로그(2차)에는 잘못 표시한 신고는 공단이 반려한다고만 나옴.
- **전자소송** (원문 확인, 2차 게재처): 재판예규 재일 2012-1 제22조①은 "전자적으로 서류를 제출한 이후에는 임의로 철회하거나 … 수정등재 할 수 없다"고 정함. 제18조⑤에 따르면 중복 서증은 법원사무관이 사후에 점검함. 제24조에 따라 접수확인서(사건번호, 접수일시)를 이메일과 문자로 보냄. 사용자 설명서(2026-10-12 수정)에는 제출서류 조회와 접수증 출력 기능이 있음.
- **설계에 주는 영향**: 세 시스템 모두 재시도를 안전하게 받아 주지 않음. 제출 전에 제출 기록과 접수번호를 조회하는 단계를 우리 쪽에 둬야 함. 특히 전자소송은 되돌릴 수 없으므로 사람의 최종 승인을 받은 뒤 한 번만 제출해야 함.

### 6. 카카오톡 상담 기록 받기
- **개인 대화 내보내기** (원문 확인):
  - Android: '텍스트만 보내기'(이메일 전송) 또는 '모든 메시지 내부저장소에 저장'.
  - iOS: '모든 메시지 도큐멘트로 저장하기'. 압축 파일로 저장되며, 풀면 "대화 및 미디어 파일"이 들어 있음.
  - Windows와 Mac: txt 파일로 저장됨.
  - CSV 형식은 공식 문서에 없음.
- **비즈니스 채널** (원문 확인):
  - 상담톡은 공식 딜러사를 통해서만 공급되는 API 상품임. "오직 상담톡 API를 통한 이용자와 상담원간의 1:1 채팅 수발신 내역만 조회할 수 있습니다". 상담원 시스템은 직접 만들어야 하고, 상담톡을 쓰기 시작하면 "기존 채팅 이력과 이용자별 메모는 더 이상 조회할 수 없게 됩니다".
  - 관리자센터의 1:1 대화는 서버에 3년 보관됨. 그러나 내보내기 기능이나 API는 찾지 못함.
- **설계에 주는 영향**: 기존 대화는 고객이나 직원이 내보낸 파일(txt, zip)을 올리는 방식으로 받아야 함. 앞으로의 상담 기록은 딜러사 상담톡을 거쳐 실시간으로 쌓아야 함. 상담톡으로 바꾸기 전에 기존 이력을 따로 보관해 둬야 함.

### 7. Podman Machine(macOS)
- **별도 디스크** (원문 확인): `podman machine init`의 옵션 전체(main 소스 `cmd/podman/machine/init.go`, 최신 릴리스 v6.1.4는 2026-10-12)에는 `disk-size`, `image`, `volume`, `usb` 등이 있음. 두 번째 디스크를 붙이는 옵션은 없음. `--volume`은 "Podman mounts host-dir in the host to machine-dir"로, 디스크 이미지가 아니라 호스트 폴더를 공유하는 기능임.
- **rm 때 볼륨 삭제** (원문 확인): `podman machine rm`은 "its image file on the filesystem"을 지움. `--save-image`를 붙이면 이미지를 남김. 이름 붙은 볼륨은 VM 디스크 안에 있으므로 함께 사라짐. 2차 출처(stephane-robert 블로그)에도 "après un podman machine rm, tous les volumes ont disparu"라고 나옴. `--volume`으로 공유한 호스트 폴더는 삭제 목록에 없으므로 남는다고 판단함(문서에 명시는 없음).
- **설계에 주는 영향**: 지켜야 할 자료(사건 자료, 색인)는 호스트 폴더에 두고 `--volume`으로 연결해야 함. VM 디스크는 언제든 버릴 수 있는 것으로 설계해야 함.
