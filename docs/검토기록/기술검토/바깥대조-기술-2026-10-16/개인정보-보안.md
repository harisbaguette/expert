# 개인정보, 보안, 공정성 검사 기술 바깥 대조

**결론**

- 여덟 가지 가운데 일곱은 그대로 쓰고, Fairlearn 하나만 statsmodels로 바꾼다.
- 그대로 쓰는 일곱 가지 모두 세 환경에 사내 설치할 수 있고, 일하는 중에 바깥 서비스를 부르지 않는다. 세 환경은 ① PC 하네스와 사내 상주 프로그램, ② 사내 GPU 서버, ③ 사내 서버와 DGX Spark다.
- 설정에서 바꿀 것은 셋이다. Presidio는 새 저장소 주소와 이미지 주소로 바꾼다. Betterleaks는 v1.9.x로 고정한다. OpenDP의 노출 한도 장치는 시험 기능이라, 실행 프로그램이 쓴 한도를 따로 기록해 한 번 더 막는다.

| 지금 선택 | 판정 | 결정적 이유 |
|---|---|---|
| Presidio (번호 모양 개인정보) | 유지 | 한국 번호 인식기 다섯 개가 들어 있고 MIT다. 번호 앞뒤에서 찾는 낱말은 영어뿐이라 한국어 낱말은 직접 더한다 |
| veil-pii-ko-lite (이름, 주소, 기관) | 유지 | 실제 한국어 대화 평가(KDPII)에서 공개된 비교 가운데 가장 높다. 0.934로, 다른 모델은 0.45~0.52다 |
| pycanon (같은 값 조합의 줄 수 등) | 유지 | 파이썬으로 검사만 하는 도구 가운데 필요한 세 기준을 모두 계산하는 것은 이것뿐이다 |
| ACRO (통계표 최소 인원) | 유지 | 영국의 보안 연구 자료실들이 실제로 쓰는 표 점검 도구다 |
| OpenDP (여러 번 내보내는 통계의 잡음) | 유지 | 노출 한도를 넘는 요청을 거절하는 장치가 들어 있다 |
| Betterleaks (비밀값 검사) | 유지 | Gitleaks 원작자가 이어 만든 실제 프로젝트다. 바깥에 묻는 기능은 기본으로 꺼져 있다 |
| Fairlearn (쏠림 판정) | 교체 → statsmodels | 필요한 신뢰구간은 이미 쓰는 statsmodels가 내고, Fairlearn이 아니면 못 하는 일이 없다 |
| 숨긴 글과 자료 속 지시 (새 대화와 화면 비교) | 유지 | 전용 탐지 모델은 글을 따로 떼어 판정해, 평가를 한쪽으로 끌어가는 문장을 찾거나 계약 의무 문장을 빼지 못한다 |

## 판정 순서

후보는 다섯 단계로 걸렀다.

1. 세 환경에 모두 사내 설치할 수 있는가
2. 바깥 서비스가 끊겨도 멈추지 않는가
3. 공개 성능 평가가 있으면 그중 가장 높은가
4. 같은 일을 하는 부품을 이미 쓰고 있는가
5. 부품 수가 더 적은가

여기 나온 도구와 모델은 모두 CPU에서 돈다. 1단계에서 빠진 후보는 클라우드 전용 서비스뿐이다(Azure AI Language, Private AI, Lakera Guard, Theori αprism).

## 1. Presidio — 번호 모양 개인정보

**확인한 사실**

- 최신 버전은 2.2.364다(2026-07-22). 2026년에만 네 번 냈고 마지막 커밋은 2026-10-09다. MIT다.
- 저장소가 Microsoft에서 커뮤니티 조직 `data-privacy-stack/presidio`로 옮겨 갔다. Microsoft 저장소의 옛 도커 이미지는 더 갱신하지 않는다. 새 이미지는 `ghcr.io/data-privacy-stack/presidio-*`에 올린다.
- 한국 인식기는 다섯 개다. 주민등록번호, 외국인등록번호, 사업자등록번호, 여권번호, 운전면허번호를 찾는다. 기본 설정에서는 모두 꺼져 있어 켜야 한다.
- 주민등록번호는 2020년 10월 전에 받은 번호만 검증 숫자를 맞춘다. 맞지 않아도 '틀림'이 아니라 '모름'을 돌려준다. 그래서 2020년 10월 뒤에 받은 번호도 버려지지 않는다.
- 번호 앞뒤에서 찾는 낱말은 "Resident Registration Number", "RRN" 같은 영어뿐이다. 한국어 낱말을 더하는 수정안(2026-09-16)은 아직 반영되지 않았다.
- 일하는 중에는 바깥을 부르지 않는다. 언어 처리 모델은 설치할 때 한 번 받는다.

**견준 대안**

| 대안 | 결과 |
|---|---|
| veil-pii-ko-lite만 쓰기 | 주민등록번호를 18건 가운데 17건만 잡았다(재현율 0.944). 형식이 있는 번호는 정해진 규칙으로 빠짐없이 잡아야 해서 대신할 수 없다 |
| presidio-ko (개인이 만든 확장) | 전화번호와 계좌번호 인식기, 한국어 앞뒤 낱말 처리를 더했다. 개인 저장소라 들이지 않는다 |
| DataFog | 한국어를 지원한다는 말이 없다 |

**판정: 유지.** 설정의 저장소 주소와 이미지 주소를 새 조직으로 바꾼다.

## 2. veil-pii-ko-lite — 이름, 주소, 기관

**확인한 사실**

- Hugging Face `1T/veil-pii-ko-lite`에 실제로 있다. 2026-09-17에 처음 올렸고 2026-10-12에 마지막으로 고쳤다. 다운로드는 358회다. 개인 한 명이 만들었다.
- 한국어 문장 모델 KoELECTRA(110M)를 개인정보 32종에 맞춰 학습했다. Apache-2.0이고, CPU용 파일은 143MB다.
- 도커 이미지에 가중치가 들어 있어 네트워크 없이 뜬다.
- 2026-09-23 전 버전은 긴 문서에서 953자 뒤를 보지 못했다. 지금 버전은 고쳐져 있다.

**공개 성능**

아래 점수는 모두 만든 사람이 직접 쟀다. 점수(F1)는 잘못 잡지 않은 정도와 놓치지 않은 정도를 합친 값으로 1이 만점이다.

## 3. pycanon — 같은 값 조합의 줄 수, 민감한 값의 가짓수, 분포 차이

**확인한 사실**

- 최신 버전은 1.3.6이다(2026-08-13). 마지막 커밋은 2026-09-21이고 Apache-2.0이다. 스페인 IFCA 연구소가 만든다.
- 필요한 세 검사를 모두 계산한다. 같은 값 조합의 줄이 몇 줄인지(k-익명성), 묶음 안 민감한 값이 몇 가지인지(l-다양성), 묶음의 값 분포가 전체와 얼마나 다른지(t-근접성)다. 검사만 하고 값을 바꾸지는 않는다.

**견준 대안**

| 대안 | 결과 |
|---|---|
| ARX | Java 화면 프로그램이 중심이다. 마지막 릴리스는 2025-09-21이다. 파이썬 실행 프로그램에 넣기 어렵다 |
| sdcMicro | R 패키지이고 GPL-2.0이다. 활발하지만 R 실행 환경이 하나 더 든다 |
| anjana (같은 연구소) | 값을 넓은 구간으로 바꾸는 일까지 해 준다. 그러나 pycanon, numpy, pandas를 옛 버전 하나로 묶어 다른 부품과 버전이 부딪힌다 |

**판정: 유지.** 값을 넓은 구간으로 바꾸는 일은 실행 프로그램이 하고, 바꾼 뒤 pycanon으로 다시 센다.

## 4. ACRO — 통계표의 최소 인원

**확인한 사실**

- 최신 버전은 1.0.2다(2026-08-28). 마지막 커밋은 2026-10-15이고 MIT다.
- pandas의 표 만드는 함수와 같은 모양으로 쓴다(`acro.crosstab` 등). 셀마다 인원이 기준보다 적은지, 한두 사람이 합계를 거의 다 차지하는지 검사한다. 걸린 셀은 지우거나 반올림해 준다.
- 스코틀랜드 공공보건청의 국가 보안 자료실과 영국 의약품청의 진료 기록 자료원(CPRD)이 연구 결과물을 점검할 때 쓴다.
- 표 두 개를 서로 빼서 한 사람의 값을 알아내는 위험은 1.0.2에서도 검사하지 않는다. 코드는 이 항목에 늘 '통과'를 돌려주고 "다른 결과물과 직접 대조하라"는 안내만 붙인다.

**견준 대안**: sdcTable(R), τ-ARGUS(Windows 중심 독립 프로그램). 둘 다 실행 환경이 하나 더 든다.

**판정: 유지.** 표끼리 빼서 알아내는 위험은 같은 자료로 여러 번 내보내는 통계에 OpenDP로 잡음을 섞는 규칙이 막는다.

## 5. OpenDP — 여러 번 내보내는 통계의 잡음

**확인한 사실**

- 최신 버전은 0.16.0이다(2026-10-06). 마지막 커밋은 2026-10-15이고 MIT다.
- 0.14(2025-09)부터, 내보낼 때마다 쓴 노출 한도를 더하다가 정해 둔 한도를 넘는 요청을 거절하는 장치가 들어 있다.
- 다만 이 장치는 시험 기능(`contrib`)이라 따로 켜야 쓸 수 있고, 수학적 검토를 다 마치지 않았다. 요청이 늘수록 시간이 제곱으로 는다는 문제 보고(2026-08-26)도 아직 열려 있다.
- 이 장치는 프로그램이 떠 있는 동안만 쓴 양을 기억한다.

**견준 대안**

| 대안 | 결과 |
|---|---|
| Tumult Analytics 0.21.0 | 지금은 OpenDP 쪽이 관리한다. 한도 관리를 정식으로 하지만 PySpark 위에서 돌고 Python 3.13 미만만 된다 |
| Google differential-privacy | 저장소에 "공식 지원 제품이 아니다"라고 적혀 있다 |
| PipelineDP 0.3.1 | 대량 처리용이다. 2023년부터 2026년까지 새 버전이 없었다 |
| SmartNoise | SQL 위주이고 마지막 커밋은 2026-04-21이다 |

**판정: 유지.** 버전을 고정한다. 자료마다 쓴 한도는 실행 프로그램이 디스크에 기록하고, 내보내기 전에 그 기록으로도 한도를 넘는지 따로 검사한다.

## 6. Betterleaks — 비밀값 검사

**실제 있는 프로젝트인지**: 있다. Gitleaks를 만든 Zach Rice가 2026년 3월에 낸 후속작이고, BleepingComputer와 Help Net Security가 다뤘다. Gitleaks 저장소도 "새 기능은 넣지 않고 보안 패치만 낸다, Betterleaks로 옮겨 간다"고 밝힌다.

**확인한 사실**

- 정식 최신 버전은 v1.9.0이다(2026-09-29). v2는 아직 시험판이다(v2.0.0-rc.2, 2026-10-07). 마지막 커밋은 2026-10-15이고 MIT다.
- 찾은 비밀값이 아직 살아 있는지 바깥 서비스에 물어보는 기능은 기본으로 꺼져 있다.
- 문자열이 사람 말처럼 보이는지 재는 데 쓰는 표가 실행 파일 안에 들어 있어, 일하는 중에 아무것도 받지 않는다.
- v2는 설정 문법이 바뀐다. 예외 목록을 적는 방식이 식으로 바뀌고, 일부 옵션이 없어진다.

**공개 성능**: 원작자가 공개 비밀값 자료(CredData)로 잰 점수(F1)는 0.892다(2026-02-20). 같은 자료로 삼성이 2022년에 잰 표에서는 CredSweeper 0.859, 그때의 gitleaks 0.334였다. 여러 도구를 같은 자료로 새로 잰 독립 평가는 찾지 못했다.

**견준 대안**

| 대안 | 결과 |
|---|---|
| Gitleaks | 보안 패치만 낸다. 새 규칙이 들어오지 않는다 |
| TruffleHog | AGPL-3.0이다. 바깥에 묻는 기능이 기본으로 켜져 있다 |
| Kingfisher (MongoDB, Apache-2.0) | 가장 빠르다고 자사가 밝힌다. 바깥에 묻는 기능이 기본으로 켜져 있고, 잘 찾는지 잰 공개 점수가 없다 |
| Titus (Praetorian, Apache-2.0) | 저장소가 보관된 Nosey Parker를 잇는다. 공개 점수가 없다 |
| CredSweeper (삼성, MIT) | 활발하다. 점수가 Betterleaks보다 낮다 |
| detect-secrets | 마지막 릴리스가 2024-05다 |

**판정: 유지.** v2 정식판이 나올 때까지 v1.9.x로 고정한다.

## 7. Fairlearn — 쏠림 판정

**재료 별 구현이 요구하는 일**: 집단마다 좋은 결과를 받은 비율을 내고, 두 집단 비율 차이가 실제로 있을 범위(신뢰구간)를 낸다. 건수가 적은 집단에는 자료를 다시 뽑아 범위를 내는 방법(부트스트랩)을 쓰지 않고, 계산식으로 범위를 내는 Newcombe 방법을 statsmodels로 쓴다.

**확인한 사실**

- Fairlearn 최신 버전은 0.15.0이다(2026-10-12). 활발하다.
- Fairlearn이 내는 범위는 부트스트랩뿐이다. Newcombe 같은 계산식 방법은 없다.
- statsmodels 0.15.0(2026-08-27)의 `confint_proportions_2indep`는 두 비율 차이의 범위를 내고, 기본 방법이 Newcombe다.

Fairlearn이 아니면 못 하는 일이 없다. 집단별 비율은 집계 한 번이면 나온다. Newcombe 방법은 큰 집단에도 그대로 맞다.

**견준 대안**: AIF360(마지막 릴리스 2024-04), Aequitas(1.1.0, 2026-02). 이 일에 더해 주는 것이 없다.

**판정: 교체 → statsmodels.** 모든 집단에 `confint_proportions_2indep(method="newcomb")`를 쓴다. 부품이 하나 줄고, 집단 크기에 따라 두 방법을 나누던 일도 없어진다. 오류율 차이처럼 비율이 아닌 지표가 필요해지면 그때 Fairlearn을 다시 본다.

## 8. 숨긴 글과 자료 속 지시

**지금 방식**은 두 가지다.

- 자료를 화면에 보이는 그대로 그림으로 만든 뒤 글자를 읽어 낸다. 그 글과 파일 안에 든 글을 견주어, 화면에 안 보이는 글을 찾는다.
- 주 모델의 새 대화가 자료의 뜻을 읽는다. 이 대화에는 검색이나 실행 도구를 주지 않는다. 이 대화가 찾는 문장은 두 종류다. 하나는 자료를 읽는 AI에게 하는 지시이고, 다른 하나는 판단을 한쪽으로 끌어가려는 문장이다. 계약이나 법령의 의무 문장은 찾지 않는다.

**공개 도구와 모델**

시험 자료 이름의 뜻은 이렇다. AgentDojo와 τ-bench는 AI 에이전트가 도구에서 받은 글에 지시를 심어 둔 자료이고, BIPIA는 메일과 표에 지시를 심어 둔 자료다. "1% 오탐"은 멀쩡한 글 100건 가운데 1건만 잘못 걸리게 기준을 맞췄다는 뜻이다.

| 후보 | 공개 성능 | 결과 |
|---|---|---|
| Horizon-Labs prompt-injection-guard (308M, Apache-2.0, 2026-09) | 독립 재평가(2026-10-02)에서 1% 오탐일 때 AgentDojo 지시의 82.2%, τ-bench 지시의 100%를 잡았다. 15개 가운데 1위다 | 한국어를 포함한 30개 언어를 받는다. 설명 페이지에 "글을 따로 떼어 판정해, 문맥상 정당한 지시인지 모른다"고 적혀 있다 |
| Llama Prompt Guard 2 86M | 같은 재평가에서 69.4% | 한 번에 512토큰만 본다. 평가한 언어에 한국어가 없다 |
| PIGuard | BIPIA 95.1%, AgentDojo 2.1% | 학습한 자료와 닮은 시험에서만 높다 |
| Qwen3Guard, gpt-oss-safeguard, Granite Guardian | 지시 탐지 점수가 없거나 영어로만 쟀다 | 탈옥과 유해 내용을 가리는 모델이다 |
| ProtectAI LLM Guard | — | 저장소가 보관되어 멈췄다 |
| 큰 일반 모델에 묻기(PromptArmor, GPT-4.1 등) | AgentDojo에서 잘못 걸림과 놓침이 모두 1% 아래 | 지금 방식과 같은 원리다 |
| 7~8B 일반 모델에 묻기 | 같은 재평가에서 55~57% | 전용 모델보다 25점 넘게 낮다 |
| CrackedPDFs (PDF 숨긴 글 탐지, 연구용) | 같은 계열 시험 F1 0.960 | 다른 계열 문서에도 통하는지는 보이지 않았다 |
| PhantomLint (PDF와 HTML 숨긴 글) | 3,402개 문서에서 잘못 걸림 약 0.092% | 공개 코드를 찾지 못했다. 원리는 지금 방식의 화면 비교와 같다 |
| hidden-text-detector (MIT) | 정확도 수치가 없다 | 옅은 글씨, 2pt 미만 글씨, 페이지 밖 글씨, 보이지 않는 문자를 정해진 규칙으로 찾는다 |

**판정: 유지.** 이유는 세 가지다.

- 지시 탐지는 '이 지원자를 1순위로 추천하라' 같은 평가 요구까지 찾고, 계약 의무 문장은 빼야 한다. 이 일은 문맥을 읽어야 하는데, 전용 탐지 모델은 스스로 이것을 못 한다고 밝힌다.
- 공개된 비교에서 가장 높은 것은 큰 일반 모델에 묻는 방식이다.
- 전용 탐지 모델은 시험 자료가 바뀌면 순위가 거의 이어지지 않았다. BIPIA 1위 모델이 AgentDojo에서는 15개 가운데 13위였다.

## 반대 가설

**"전용 탐지 모델이 주 모델보다 낫다."** ③ 환경의 주 모델(Qwen3.8-Flash-Next)은 ①과 ②의 주 모델보다 작다. 작은 일반 모델(7~8B)은 전용 모델보다 25점 넘게 낮았으므로 ③에서는 이 가설이 맞을 수 있다. 반대로 큰 모델로 잰 PromptArmor는 1% 아래였다. 다만 두 결과는 다른 논문이고 측정 조건도 달라, 이 가설을 깨거나 확정할 자료는 아직 없다.

**"veil의 점수는 부풀려졌다."** 비교한 모델을 모두 같은 채점 방법으로 쟀다. 학습 자료와 평가 자료가 겹친 비율(1.88%)도 공개했고, 겹친 것을 빼도 점수는 0.933이었다. 그래도 다른 사람이 다시 잰 값이 없어 이 가설은 열려 있다.

**"Kingfisher나 Titus가 Betterleaks보다 잘 찾는다."** 같은 자료로 견준 공개 평가가 없어 깨지 못했다.

## 이 분석이 답하지 않는 것

- veil과 Presidio가 계약서와 판결문에서 얼마나 놓치는지. 공개 평가는 대화, 상담, 합성 문장뿐이다.
- 한국어 자료 속 지시를 탐지기들이 얼마나 잡는지. 한국어 문체별 시험 자료(2026-07)는 있지만 점수표는 없다.
- 만든 쪽이 직접 잰 점수의 치우침. veil, BCCard, Betterleaks, Kingfisher, Theori의 점수가 모두 그렇다.
- 검색과 다운로드 순위에 걸리지 않은 새 모델. 다운로드가 적은 모델은 빠졌을 수 있다.

## 가정

- 세 환경 모두 Python 3.11 이상, Docker, CPU용 ONNX Runtime을 설치할 수 있다.
- 실행 프로그램이 쓴 노출 한도와 판정 기록을 디스크에 남긴다.
- 기준값(최소 인원, 줄 수, 노출 한도, 허용 차이)은 업무 종류마다 운영하는 쪽이 정한다는 재료 별 구현의 규칙이 그대로다.

## 다음에 할 일

1. 사내 계약서와 판결문 200건에 이름, 주소, 기관을 표시해 veil이 놓치지 않는 비율을 잰다. 0.90에 못 미치는 라벨이 있으면 그 표본으로 veil을 고쳐 학습한다. Apache-2.0이라 허용된다.
2. 자료 속 지시 찾기 시험을 ③ 환경의 주 모델과 Horizon-Labs에 같은 자료로 함께 돌린다. 1% 오탐 기준에서 주 모델이 놓친 지시를 Horizon-Labs가 잡으면, Horizon-Labs를 주 모델 앞단에 더한다.
3. 사내 저장소 표본에 비밀값을 심어 Betterleaks v1.9, Kingfisher, Titus가 잡는 비율을 견준다. Betterleaks가 가장 높지 않으면 바꾼다. v2 정식판이 나오면 같은 표본으로 v1.9와 견준 뒤 옮긴다.
