# 판단 시스템을 저장·실행 구조에 옮긴 결과의 비판

**이전 설명과 보완은 반려다. 이미 설계한 판단 시스템을 저장소 설명으로 축소했고, 사용자가 실제 모델 입력을 물었는데 원본 보존의 필요성을 답했다. 표현 수정만으로 해결됐다고 한 것도 잘못이다.**

검토일은 2026-10-23이다. 범위는 `파일-폴더-구조.md`와 `공장 구현 설계.md`의 자료 가공·공급·판단·검증·변경 추적, 직전 답변과 검증 기록이다. 기준은 `전문 판단의 신뢰성.md`의 해결책 1–28과 기존 해결책 구조 Mermaid다. 해결책의 역할과 연결을 대조했으며 법률 사실의 외부 검증이나 모든 세부 예외의 전수 심사는 하지 않았다. 기존 그림 네 장은 앞서 직접 확인한 결과를 재사용했다. 저장 위치 그림이 전체 판단 시스템까지 검증했다는 증거로 쓰일 수 있는지를 다시 판단했다.

현재 대화에서 직접 수행했다. 독립 심사자나 실행 프로그램의 시험 결과로 표시하지 않는다.

## 발견한 결함

| 번호·심각도 | 결함과 증거 | 결과와 처방 |
|---|---|---|
| 1 · 즉시 수정 | 처음에는 ‘같은 원본을 참조한다’고 썼고, 직전 답변도 ‘원문은 보관과 검증의 기준으로 필요합니다’로 마무리했다. 사용자가 묻는 것은 판단 모델이 무엇을 받는가였다. 신뢰성 문서 238–247행은 의미 기준·가공·관계·검색·선별을 이미 정했다 | 보관 대상과 모델 입력을 혼동하게 했다. 구조 문서의 첫 문장·첫 표부터 **공통 시스템이 구성한 가공된 판단 입력**을 설명하도록 수정했다. 현재 구조 문서 20행의 ‘전문가가 실제로 받는 자료’에 저장 위치와 처리 역할을 연결했다 |
| 2 · 즉시 수정 | 온톨로지·관계·검색은 기존 구조 문서 4·6·7절에 이미 있었다. 그런데 기존 공장 문서의 `ContextSnapshot`은 근거·규칙의 버전 중심으로 적혀 있어, 정제 본문·파생 결과·관계·검사·선별 결과가 어떻게 실제 입력이 되는지 확인하기 어려웠다 | 명칭의 존재를 시스템 연결로 간주했다. 공장 문서 61행에 기존 해결책 28개의 입력·출력·담당 모듈을 연결했고, 114행의 `ContextSnapshot`에 실제 입력과 그 생성 근거를 명시했다 |
| 3 · 즉시 수정 | 직전 보완은 하이브리드 검색과 GraphRAG를 적고도 해결책 5의 Decision Model을 근거 공급에 연결하지 않았다. 기존 검증 기록의 대조 행에도 242행이 없었다 | 검색 순위 조정과 자료별 관련성 판정을 구별하지 못했다. 구조 문서 244행에 관련 자료 유지, 애매한 자료와 판단 못 함의 전달, 숨긴 글·조종 지시 발견 자료의 정제·표시·보존을 반영했다. 결론을 내리는 모델과도 구분했다 |
| 4 · 즉시 수정 | 기존 공장 문서 운영 절은 ‘실제로 인용한 knowledge_id와 버전만’ 의존 관계로 기록하고 ‘인용 문장과 새 원문’이 달라질 때만 모델 검토를 넣었다. 신뢰성 문서 261행은 근거·조건·진행 기록·앞선 판단과 후속 결과의 변경을 추적한다 | 인용문이 같아도 관계·효력·적용 기준이 바뀐 판단을 놓친다. 인용하지 않고 입력으로 사용한 근거도 빠진다. 공장 문서 260–264행과 구조 문서 258행에 실제 입력·기준·관계의 의존 관계와 재검토를 반영했다. 부칙·경과조치와 원인 미상 오류의 영향 범위도 복원했다 |
| 5 · 조속히 수정 | 앞선 그림 검사는 해상도·복사본 해시·링크·글자·폴더 포함 관계를 확인했다. 직전 문서 보완 검사는 특정 문구의 유무·표·이미지 링크 보존을 확인했다 | 그 검사는 시스템이 충실하게 옮겨졌다는 증거가 아니다. 기존 그림의 물리적 포함 관계가 틀렸다는 결함을 새로 만들지는 않았다. 이번에는 원본 설계와 역할·입력·출력·실패 시 복귀를 대조하고 아래 시나리오로 의미를 점검했다. 과거 검증의 범위를 확대해서 해석하지 않는다 |

다섯 결함을 위와 같이 수정했다. 별도의 경미한 결함은 이번 범위에서 추가로 판정하지 않았다.

## 복원한 이해

전문가는 다음 자료를 함께 받아 판단한다.

- 자료 관문을 통과한 본문과 필요한 앞뒤 문맥, 추출한 사실·관계·유효 기간.
- 근거의 출처·원문 위치·가공 버전·검사 상태·제거 표시·미확인 사항.
- 해당 업무의 기준·단계별 지시와 현재 유효한 진행 기록.

온톨로지는 의미와 검사 기준이고, 시간축 지식 그래프는 실제 대상·관계·기간을 담는다. 하이브리드 검색과 GraphRAG는 이 자료에서 근거를 찾는 기능이다. 관련성과 권한을 확인한 결과가 판단 입력이 되고, 모델이 조건·예외를 적용한 뒤 독립 검토·원문 대조·계산 검증을 거친다. 원본은 보존·판독·대조에 사용한다. 정제한 조문·판결 문장이 판단 입력에 포함되는 것을 ‘가공된 자료를 쓰지 않는다’고 해석해서도 안 된다.

자료 가공과 검색 기반 갱신은 신규·변경 자료에 수행한다. 실제 업무에서는 허용된 유효 버전을 조회해 입력을 구성한다. 전문가를 추가할 때 이 시스템 전체를 다시 만들지 않는다.

## 시나리오로 문서 대조

아래는 문서 규칙을 사람이 읽듯 대입한 점검이다. 구현 프로그램을 실행한 시험이 아니다.

| 상황 | 수정 문서가 요구하는 결과 | 근거 |
|---|---|---|
| 해지 조항의 효과가 특약·별첨에 달림 | 정제 본문을 검색하고 참조 관계로 특약·별첨을 보태 판단 입력에 포함 | 구조 1·7절, 공장 ‘근거 공급’ |
| 원본에 숨긴 글·조종 지시가 있음 | 본문을 정제하고 제거 표시를 보존. 관련 없음 판정만으로 자료 자체를 조용히 제외하지 않음 | 구조 6·7절, 공장 ‘자료 관문’ |
| 그래프에 연결이 없음 | 하이브리드 검색으로 보완하고 관계가 없다고 단정하지 않음 | 공장 ‘전문 판단 시스템을 실행에 연결’ |
| 같은 본문인데 판례 변경·효력 상태가 바뀜 | 글자 비교 결과와 관계없이 영향받는 판단을 재검토 | 공장 운영 절, 구조 7절 |
| 결과에 인용하지 않은 관계가 입력에 쓰인 뒤 정정됨 | 실제 입력의 의존 관계로 판단·후속 결과를 찾아 재검토 | 공장 `ContextSnapshot`과 운영 절 |
| 온톨로지 기준이 바뀜 | 관련 가공 결과·관계·판단 입력의 영향과 평가 사례를 확인 | 구조 4·7절, 공장 운영 절 |
| 다른 고객의 관계가 연결망에 존재 | 조회·관계 탐색·합류 단계에서 고객·범위 권한을 적용 | 공장 전 과정 규칙, 구조 3·7절 |
| 계산이 필요한 판단 | 검증된 계산 도구를 사용하고 계산 증거를 검사에 전달 | 공장 ‘판단’·‘검사’ |
| 검색·도구가 새 자료를 반환 | 자료 관문을 다시 적용한 후 판단 입력에 반영 | 구조 6절, 공장 전 과정 규칙 |
| 독립 재판단이 필요 | 기존 결론을 주지 않고 관리 프로그램이 제공하는 허용 자료로 재판단 | 공장 전 과정 규칙·‘다시 판단’ |

## 문서 채점

DOCUMENT 채점표의 설계 문서 기준을 적용했다. 점수는 이번 **시스템 반영 범위에 대한 작성자의 정성 평가**이며, 공장 전체 품질이나 구현 성능 점수가 아니다. 가중 평균은 Python으로 계산했다.

| 항목 | 가중치 | 수정 전 | 수정 후 |
|---|---:|---:|---:|
| 종류에 맞는 순서 | 22% | 5.0 | 9.2 |
| 읽은 뒤 할 수 있는가 | 22% | 4.0 | 9.0 |
| 구조 | 15% | 5.0 | 9.1 |
| 불필요한 채움 | 13% | 7.0 | 8.5 |
| 숫자·범위·근거 명시 | 12% | 8.0 | 9.2 |
| 읽기 쉬움 | 10% | 5.0 | 8.8 |
| 일관성 | 6% | 4.0 | 9.3 |
| 가중 평균 | 100% | **5.34 · 반려** | **9.02 · 문서 정합성 수락** |

‘숫자’는 처리 성능의 추정치를 추가하는 기준으로 쓰지 않았다. 해결책 번호의 대응과 실제 확인 범위를 평가했다. 반복을 피하려고 세부 규칙의 정본은 신뢰성 문서에 두고, 구조 문서는 저장 위치를, 공장 문서는 입력·출력과 담당 모듈을 맡겼다.

## 확인 결과와 한계

기준인 신뢰성 문서와 기존 해결책 도식은 변경하지 않았다. 신규·별도 판단 시스템이나 검색 서버도 추가하지 않았다. 수정은 구조 문서·공장 문서와 이 검토 기록에 한정했다. 기존 일러스트의 파일은 변경하지 않았다.

[검증 기록](판단시스템-구조반영-검증-2026-10-23.json)은 해결책 1–28 대응, 자료형·처리 단계·변경 규칙의 연결, 기준 문서·이미지 보존, 문서 링크와 표 구조를 구분해 기록한다. 시나리오 의미 검토와 자동 문서 검사를 구분했다. 실제 모델 입력, 접근 제어, 검색 재현율과 변경 전파의 동작은 구현 후 시험할 사항이며 이번 검사에서 통과했다고 주장하지 않는다.
