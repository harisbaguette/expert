
===== 업무 처리 흐름 =====
[묶음 PHASE_0] 시작 · 긴급 대응
  REQ: 요청
  SIGNAL: 신호 감지
  CHANCE: 기회 발견
  HARM: 지금 실제 피해·오류·장애가 진행 중이고 / 바로 막지 않으면 계속 커지는가?
  SAFE_ACTION: 지금 바로 할 수 있는 / 안전한 임시조치가 있는가?
  EMERGENCY_RULE: 미리 승인된 / 긴급 예외 조치가 있는가?
  FIRST_ACTION: 추가 피해부터 막기 / 문제 작업 중지 · 추가 결제나 전송 막기 / 영향 범위 분리 · 정상 상태 복구 · 임시 대체
  EMERGENCY_APPROVAL: 긴급 승인 요청
  EMERGENCY_EXEC: 정해 둔 긴급 조치 실행 / 실행하는 즉시 보고
  EMERGENCY_DECISION: 승인됐는가?
  APPROVED_ACTION: 승인된 조치 실행
  EMERGENCY_MONITOR: 권한 안에서 추가 피해를 막고 / 상태와 변화를 계속 기록
  EMERGENCY_CHECK: 추가 피해가 / 멈췄는가?
  OPPORTUNITY: 지금 놓치면 / 사라지는 기회인가?
  OPPORTUNITY_DEADLINE: 기회가 사라지는 시점을 / 업무 기한으로 등록
  CASE_TYPE: 이번 요청·신호가 / 새로운 건인가?
[묶음 PHASE_1] 접수
  LOAD_CASE: 진행 중인 건 불러오기 / 현재 상태 · 남은 일 · 기한 · 대기 사항 확인
  CASE_CHANGED: 기존 목표나 업무 범위가 / 바뀌었는가?
  INTAKE_CHECK: 한 건의 범위 확인 / 요청자의 권한 · 당사자 동의 · 이해충돌 / 업무 범위 · 보수 · 책임 조건 확인
  ACCEPTABLE: 지금 상태로 / 접수할 수 있는가?
  CONDITION_CHECK: 접수에 부족한 조건 확인 / 권한 증빙 · 당사자 동의 · 필요한 승인 / 업무 범위 조정 등
  CONDITION_REQUEST: 조건 보완 요청
  CONDITION_WAIT: 조건 충족 대기
  CONDITION_OK: 필요한 조건이 / 충족됐는가?
  CONDITION_DEADLINE: 보완할 기한이 / 남아 있는가?
  REJECT: 거절 / 거절 이유와 가능한 대안 안내
  REJECT_RECORD: ("접수·거절 기록 남기기")
  ACCEPTED: 접수 확정
[묶음 PHASE_2] 의도 파악
  INTENT_CLEAR: 요청·지시만으로 / 원하는 결과가 한 가지로 정해지는가?
  AMBIGUOUS: 모호한 부분과 / 빠진 지시를 구분
  INTENT_ASK: 되묻기 · 지시 확인 · 의도 확인
  INTENT_CONFIRMED: 원하는 결과가 / 확인됐는가?
  ASSUME_SAFE: 확인 없이 가정해도 / 결과 · 권리 · 비용에 큰 영향이 없는가?
  ASSUMPTION: 가정한 내용과 / 그 영향을 명시
  INTENT_WAIT: 답변 대기
[묶음 PHASE_3] 문제 정의
  PROBLEM_ANALYSIS: 원하는 결과를 막는 / 원인 · 제약 · 빠진 요소 확인
  DIRECT_SOLUTION: 요청받은 일을 그대로 하면 / 원하는 결과가 실제로 나오는가?
  REFRAME: 실제로 해결해야 할 문제를 / 다시 정의
  REFRAME_SCOPE: 새로 정의한 문제가 / 기존 의도나 범위를 바꾸는가?
  REFRAME_CONFIRM: 바뀐 목표 · 범위 · 완료 조건 확인
  PROBLEM_SCOPE: 풀 문제 · 풀지 않을 문제 / 업무 범위 확정
[묶음 PHASE_4] 자료 확인
  COLLECT: 필요한 자료를 직접 수집하고 / 가능하면 원문까지 확인
  CLASSIFY_DATA: 사실 · 주장 · 추정을 구분
  VALIDATE_DATA: 출처 · 시점 · 관할 · 판본 확인
  DATA_ENOUGH: 결론을 바꿀 핵심 사실이 / 확인됐거나 가정으로 표시됐는가?
  DATA_GAP: 빠진 정보와 / 확인 방법 정하기
  GET_DATA: 추가 조회 · 상대나 기관에 질문 · 실험
  DATA_FOUND: 추가 사실을 / 확인했는가?
  DATA_LIMIT: 확인할 수 없는 내용은 / 가정 · 근거 부족 · 입증 책임을 명시
[묶음 PHASE_5] 판단 · 계획
  OPTIONS: 가능한 방법과 대안 만들기
  COMPARE: 효과 · 비용 · 위험 · 부작용 / 상대의 예상 반응 비교
  KNOWN_CASE: 기존 규칙이나 사례로 / 판단할 수 있는가?
  NEW_METHOD: 원리와 유사 사례를 바탕으로 / 새 방법 설계
  SMALL_TEST_Q: 작은 범위에서 / 먼저 시험할 수 있는가?
  SMALL_TEST: 작게 시험하고 / 어떤 결과가 나오면 중단할지도 정함
  UNCERTAIN_PLAN: 불확실성을 명시하고 / 되돌리기 쉬운 방법을 우선
  SELECT: 실행 방법 선택
  EXECUTION_PLAN: 실행 순서 · 사건 간 영향 · 공동 작업 / 관측별 전환 · 복구 · 중단 기준을 정함
  PREMISE: 계획의 핵심 전제가 / 지금도 유지되는가?
  UPDATE_PLAN: 바뀐 조건을 반영해 / 판단 · 계획 다시 수행
  REPEAT_Q: 주기적으로 / 반복하는 업무인가?
  REPEAT_RULE: 주기 · 자동 실행 범위 · 한도 / 다음 점검 시점을 정함
  HUMAN_Q: 실행 전에 사람의 결정이 필요한가? / 되돌릴 수 없는 행동 · 사전 승인 필요 / 판단 불가 · 한도 초과 · 자격자 전속
  HUMAN_PREP: AI가 할 수 있는 조사 · 계산 · 작성 / 대안 비교 · 검증까지 먼저 완료
  DECIDER: 현재 결정권자가 / 권한이 있고 이해충돌도 없는가?
  DECISION_REQUEST: 권한 있는 사람에게 결정 요청
  ALT_DECIDER: 미리 정한 다른 결정권자에게 요청
  DECISION_RECEIVED: 기한 안에 / 결정이 왔는가?
  ESCALATE: 다음 승인권자에게 올림
  APPROVAL_GRANTED: 승인 · 진행 결정인가?
  DECISION_REJECTED: 반려 · 보류 사유와 / 남은 일 기록
[묶음 PHASE_6] 처리
  PRE_EXECUTE: 실행 전 시험 · 복구 수단 확보 / 권한 · 금액 · 손실 한도 자동 검사
  EXEC_ACTION: 실제 실행
  EXEC_STATE: 실행 직후 실제 상태와 / 상대 · 시스템 반응 기록
  EXEC_FAIL: 실행에 실패했는가?
  EXEC_LIMIT: 시간 · 비용 · 시도 횟수 등 / 정한 중단 한도를 넘었는가?
  REPEAT_FAIL: 같은 실패가 / 반복되고 있는가?
  STOP_HUMAN: 현재 상태 · 실패 원인 · 대안과 함께 / 사람에게 넘김
  RECOVER: 재시도 · 취소 · 원상복구
  STOP_DECISION: 다시 진행하기로 / 결정됐는가?
  LOCAL_REPLAN: 실패 원인을 반영해 / 방법과 실행 순서 다시 계획
  STOP_RECORD: 중단 상태와 / 남은 위험 기록
[묶음 PHASE_7] 검증
  ACTUAL_RESULT: 원천 시스템 · 상대 · 시장에서 / 실제 결과 확인
  RECALCULATE: 계산을 다시 하고 / 내 기록과 원천 기록 비교
  CROSS_CHECK: 독립 근거 · 다른 방법으로 반증 / 팀 간 이견 · 공통 오류 · 교차 영향 검토
  RISK_CHECK: 놓친 위험 · 빠진 대상 · 누락 항목 확인
  ISSUE: 수정해야 할 문제가 / 발견됐는가?
  ISSUE_CAUSE: 문제는 어디에서 / 생겼는가?
  REWORK_DATA: 자료를 다시 확인하고 / 이후 판단 · 처리를 다시 수행
  CAUSE_PLAN: 판단 · 계획의 문제인가?
  REWORK_PLAN: 판단 · 계획을 다시 하고 / 필요한 처리를 다시 수행
  CAUSE_EXEC: 처리의 문제인가?
  REWORK_EXEC: 잘못된 처리를 수정
  UNFIXABLE: 고칠 수 없는 문제는 숨기지 않고 / 영향 · 유효기간 · 재검토 시점을 기록
  REVERIFY: 수정 결과 다시 검증
[묶음 PHASE_8] 완료 · 보고
  COMPLETE: 처음 정한 완료 조건이 / 실제 상태에서 충족됐는가?
  CAN_FINISH: 추가 처리하면 / 완료할 수 있는가?
  REMAINING_WORK: 남은 일 처리
  PARTIAL: 완료된 부분 · 남은 일 / 완료하지 못한 이유를 구분
  REMAINING_VERIFY: 추가 처리 결과 검증
  DELIVER: 결과물 · 결론 · 근거 · 가정 / 미완료 사항 전달
  RESPONSE: 받는 사람의 반응은?
  REVISION_SCOPE: 기존 업무 범위 안의 / 수정인가?
  NEW_REQUEST: 새 목표 · 범위 · 완료 조건으로 / 다시 접수
  REVISION: 수정 처리
  REVISION_VERIFY: 수정 결과 다시 검증

  FINAL: 업무 종료
  WAIT: 대기 / 다음 신호가 오면 기존 건으로 재개

===== 사용 구조 1 단독 상황 =====
  start: <b>요청·변경·재개 신호 도착</b>
[묶음 REQUEST] 요청의 뜻과 완료 기준
  input0: <b>시작 신호</b> / <small>단계별 · 새 업무 또는 기다리던 업무에 / 신호를 연결</small>
  input1: <b>업무별 정보</b> / <small>단계별 · 대상·기한·요청 내용·현재 / 조건을 모음</small>
  input2: <b>지시·의도 파악</b> / <small>상시 · 무엇을 원하는지와 허용한 범위를 / 확인</small>
  input3: <b>문제·목표·완료 조건</b> / <small>상시 · 해결할 문제와 완료를 증명할 / 결과를 정함</small>
