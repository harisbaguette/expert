## 유지한 선택과 그 이유

- **StatsForecast 유지:** 비교 기준과 통계 예측을 한 라이브러리로 처리할 수 있다. Naive·SeasonalNaive·AutoETS는 공식 구현에 있으며, AutoETS는 수준·추세·계절 성분을 선택한다. 모든 업무에서 AutoETS가 최고라는 뜻은 아니다. 실제 적용은 업무별 검증 결과로 정한다. [공식 모델 문서](https://nixtlaverse.nixtla.io/statsforecast/src/core/models.html)
- **Chronos 두 모델의 역할만 정리:** 28M Small과 120M 모델의 존재·Apache-2.0 조건은 확인됐다. 작은 모델부터 검증하는 순서는 PC에서 불필요한 모델 설치·실행을 줄이기 위한 설계 판단이다. 작은 모델이 더 정확하거나 모든 장비에서 더 빠르다고 실측한 것은 아니다. [공식 저장소](https://github.com/amazon-science/chronos-forecasting), [Small 모델 카드](https://huggingface.co/autogluon/chronos-2-small)
- **TimesFM 3 제외 유지:** 현재 공개 라이선스는 상업적 의사결정·고객 납품에 사용되는 평가를 허용하는 조건이 아니다. 단순 배포 제외만으로는 충분하지 않다는 이전 수정은 맞다. 이번 확인에는 PR 초안이 아닌 공식 `main/LICENSE`를 사용했다. [공식 라이선스](https://huggingface.co/google/timesfm-3.0-pytorch/blob/main/LICENSE)
- **포함률·폭·Winkler 점수 유지:** 포함률만 최대화하는 잘못된 선택을 막는다. 90%는 이 문서에서 정한 기본값이며 모든 업무의 최적값이라는 주장이 아니다. 필요한 포함률은 시험 전에 정한다. [평가 방법](https://otexts.com/fpp3/toolbox.html)

## 확인의 한계와 남은 구현 검증

PyPI의 StatsForecast 2.1.1에는 Windows x64, macOS x64·ARM64, Linux x64·ARM64용 배포 파일이 있다. Chronos 패키지는 운영체제 공통 Python 배포이며 PyTorch 등 의존성이 필요하다. 각 환경의 전체 의존성·성능까지 검증됐다는 뜻은 아니다. [StatsForecast 배포 정보](https://pypi.org/project/statsforecast/2.1.1/#files), [Chronos 배포 정보](https://pypi.org/project/chronos-forecasting/2.3.2/)

공식 모델 설정의 자료형과 분위수도 확인했다. 두 Chronos 모델 모두 `float32` 설정과 0.05·0.95 분위수를 제공하므로 90% 구간의 양 끝을 지정할 수 있다. 이것은 실제 90% 포함률이 검증됐다는 뜻이 아니다. [Chronos-2 설정](https://huggingface.co/amazon/chronos-2/blob/main/config.json), [Small 설정](https://huggingface.co/autogluon/chronos-2-small/blob/main/config.json)

이번에는 모델을 설치·실행하지 않았다. 실제 업무 자료의 정확도·구간 보정, 세 운영체제의 실행 시간·메모리, 업무 흐름 시뮬레이션의 현실 적합성은 구현 단계에서 확인해야 한다. 현재 문서도 이를 통과하기 전에는 검증된 예측으로 제공하지 않도록 규정한다.
