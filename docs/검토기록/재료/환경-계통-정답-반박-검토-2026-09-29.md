| ②③ Temporal 자식 워크플로 | 가벼운 조각에는 이벤트 기록이 따로 쌓여 무거움. activity로 충분하다는 반론. | 유지. 모델 바퀴를 여러 번 도는 긴 조각이면 자식 워크플로가 맞음. | — |
| ③ "처리량에서 음성 몫을 뺀 만큼" | 숫자로 떨어지지 않음. vLLM 동시 배치 수와 KV 메모리 실측으로 정해야 함. | 조건부 | — |

- 빠진 원칙: 하위 에이전트가 또 하위 에이전트를 부르는 깊이 한도. Claude Code 기본은 3층이라, 층마다 10개면 최대 1,000개까지 퍼질 수 있음(S7).

### 8. 실시간 대화

| 대상 | 가장 센 반대 | 판정 | 근거 |
|---|---|---|---|
| ②③ 주 모델(생각 기능 끔) | 같은 문서 AI 모델 절에는 "다른 모델은 실시간 음성 대화에 쓴다"고 되어 있음. 문서 안에서 정면으로 부딪침. ③ Spark에서는 큰 모델이 첫 소리까지 걸리는 시간 예산을 넘길 가능성이 높음. | 바꿈(문서 안 모순) | 정의 1, 1060줄 |
| TTS Magpie TTS Multilingual | 공개 가중치 판은 영어 화자 5명뿐이고 스트리밍 언급이 없음. 발표된 지연 수치는 NIM 서빙 스택 기준임. 한국어는 2026-07에 추가된 "기준선" 품질(CER 2.69%). Qwen3-TTS는 Apache-2.0, 한국어 전용 화자(Sohee), 스트리밍 첫 소리 97ms. | 바꿈. 대안은 Qwen3-TTS-12Hz(0.6B/1.7B). 한국어로 직접 들어 보고 확정. | S9, S10, S11 |
| ASR Qwen3-ASR-1.7B | Whisper 계열이 더 검증됐다는 반론. | 유지. 한국어를 포함한 30개 언어, 모델 하나로 스트리밍과 일괄 처리를 다 함. | S27 |
| ②③ 글 대화 LiveKit | 글 대화에는 음성 중계(WebRTC) 서버가 필요 없고 웹소켓이나 SSE로 충분함. 음성 기준 셋은 글 대화의 답을 고르지 않음. | 조건부. 음성과 같은 세션을 쓸 때만 LiveKit. | 문서 내부 대조 |
| 기준 3 "끼어들면 멈춤" | 모델의 성질이 아니라 LiveKit Agents의 음성 감지·턴 판단 기능이라 ASR·TTS 후보를 가르지 못함. LiveKit 턴 감지 v1 전체 모델은 LiveKit Cloud에서만 돌고, 자체 설치하면 공개 가중치인 v1-mini를 씀. | 기준 결함 + 사실 보충 | S28 |
| 기준 2 한국어 공식 지원 | Magpie·Qwen3-TTS·ASR이 모두 통과함. 스트리밍·첫 소리까지의 지연·라이선스처럼 후보를 가르는 기준이 없음. | 기준 결함 | S9, S11 |

- 빠진 원칙: 첫 소리까지의 지연 목표(ms)가 수단 고르기 기준에 없음.
- 빠진 원칙: 녹음을 얼마나 보관하고 언제 지우는지.

### 9. 시험 환경

| 대상 | 가장 센 반대 | 판정 | 근거 |

| ① 작업 나무 격리 + 시험용 열쇠 | 작업 나무는 파일만 가르고 같은 사용자 계정·환경 변수·키체인·`~/.aws`를 함께 씀. 샌드박스 기본 읽기 범위가 전체라 실제 열쇠가 보임. 기준 2("열쇠를 따로 둔다")에 글자대로 미달함. | 바꿈. 대안은 별도 운영체제 사용자, dev container, VM. | S1 |

| ②③ 다른 열쇠·계정의 시험용 인스턴스 | 없음 | 유지 | — |
| ③ 시험 모델 따로 + 자원 상한 | GB10 통합 메모리에서는 컨테이너 메모리 상한이 먹히지 않았다는 사용자 보고가 있음(120GB 이상 폭주). 128GB에 주 모델·음성 모델 셋·시험 모델을 함께 올리기는 어려움. | 조건부. 실제로 되는 쪽은 "운영이 쉬는 시간에만" 올리는 방식임. | S29 |
