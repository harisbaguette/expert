# 재료별 구현 기술 재검토 — 2026-10-20

15번에 이어 나머지 미확정 재료 **75개를 검토하고 30개를 수정했다.** 확정된 환경·1·49·50번, 정의 1과 전문 판단의 신뢰성은 수정하지 않았다. 15번의 개별 조사 결과도 유지했다.

기존 선택이 전부 구식인 것은 아니다. 더 큰 문제는 **새 후보를 비교한 근거 부족, 중복 실행, 도구 기능과 업무 전체의 혼동, 실행·검증 조건의 누락**이었다. 최신 모델을 찾는 것과 제품에 채택할 수 있는지를 구분했다.

공식 문서·모델 카드·공개 코드를 조사한 결과다. 모델 실행, 한국어 업무 성능 비교, 세 운영체제의 제품 설치 시험까지 끝났다는 뜻은 아니다.

## 공통 구현을 반박한 근거

| 구현 | 공식 근거와 판단 |
|---|---|
| PostgreSQL·DBOS | DBOS는 현재 SQLite도 지원한다. PostgreSQL을 택하는 이유는 DBOS의 필수 의존성이어서가 아니라 검색·고객 분리·후속 서버 구성을 함께 처리하기 위해서다. [DBOS DB 연결](https://docs.dbos.dev/python/tutorials/database-connection) |
| 취소·기한·재개 | DBOS의 실행 제한 시간에는 대기열 시간이 포함되지 않는다. 취소도 외부 시스템의 행동 취소와 같지 않다. 변동 입력은 단계 결과로 저장해야 재실행이 일관된다. [DBOS Workflows](https://docs.dbos.dev/python/tutorials/workflow-tutorial) |
| 한국어 낱말 검색 | pg_textsearch 1.5.0은 2026-10-01 안정 릴리스이며 문구·조건 검색과 복구 관련 개선이 있다. 아직 초기판이라는 이유로 배제할 근거는 없다. [릴리스](https://github.com/timescale/pg_textsearch/releases/tag/v1.5.0) |
| 검색과 접근 권한 | pg_textsearch의 BM25 통계에는 RLS로 가려진 행도 포함된다. 고객·열람 범위별 통계를 분리해야 한다. pgvector의 근사 검색은 필터 뒤 결과가 부족할 수 있어 반복 탐색·정확 검색을 함께 둔다. [pg_textsearch](https://github.com/timescale/pg_textsearch), [pgvector](https://github.com/pgvector/pgvector#filtering) |
| DB 고객 분리 | 테이블 소유자·관리자·BYPASSRLS는 일반 사용자와 동작이 다르다. 비소유자 작업 계정, 강제 RLS와 연결 재사용 시 고객 설정 초기화가 필요하다. [PostgreSQL RLS](https://www.postgresql.org/docs/current/ddl-rowsecurity.html) |
| 여러 OS | Podman은 Windows·macOS에서 Linux VM을 사용한다. 공식 macOS 자동 시작 예도 로그인 때 실행하는 LaunchAgent다. 서비스 이름을 나열하는 것만으로 로그인 전 복구를 보장할 수 없다. [Podman 설치](https://podman.io/docs/installation), [자동 시작](https://github.com/podman-container-tools/podman/blob/main/docs/tutorials/macos_autostart.md) |
| 지식 추론 | OWL·SHACL의 확정된 역할은 유지했다. RDFLib만 적고 추론 실행을 생략하지 않도록 `owlrl`을 연결하고 도출 관계를 원문 사실과 나눴다. [OWL-RL](https://github.com/RDFLib/OWL-RL) |

## 구현 전 남은 검증

| 확인할 것 | 통과해야 할 결과 |
|---|---|
| 한국어 실제 자료 | 중요 근거·금액·이름·조건·예외·개인정보의 누락을 유형별로 비교. 제작사 평균 점수로 대체하지 않음 |
| 실행 자원 | 지원할 OS·CPU·메모리별 실제 시간과 실패율. 모델을 불러온 성공만으로 업무 지원을 확정하지 않음 |
| 선택적 부품의 효과 | 재정렬·더 큰 모델·별도 생성 모델을 추가하기 전후의 품질과 비용 비교. 이득이 없으면 제외 |
| 복구 | 중단 시점마다 DB·필수 파일·권한·외부 거래가 맞는지 실제 복원 |
| 정책 증명 | 고정한 Cedar 표현·스키마에서 포함 관계 검사가 실제 작동하고 우회·권한 철회가 차단되는지 시험 |
| 부품 배포 | 선택한 정확한 코드·가중치·의존성의 사용·재배포 권한과 서명 검증 |

공개 모델의 존재와 기능은 확인했지만 실제 한국어 업무 비교를 하지 않은 후보를 ‘최선으로 검증 완료’라고 표시하지 않았다. 새 후보는 본문에서 비교·채택 조건까지 정했으며 자동 확정하거나 확정 문서로 옮기지 않았다.
