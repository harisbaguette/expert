# 15. 정보·자료 이해 — 기술 선정 재검토

2026-10-20 공식 문서·모델 카드·논문·평가표 대조.

**기존 구성을 최적이라고 확정할 근거는 부족하다. 전부 구식인 것도 아니다. 한국어 문서의 더 강한 후보를 빠뜨렸고, 음성 대조 모델은 최신 한국어 모델과 비교하지 않았다. 두 OCR 모델이 서로의 오류를 얼마나 잡는지도 확인되지 않았다.**

## 선정 결과

| 역할 | 이번 추천 | 판단 |
|---|---|---|
| 전자 문서의 원문·구조 추출 | Docling 유지 | OCR 모델의 점수로 대체 여부를 결정할 기능이 아니다. 원래 글·표·위치·숨김 요소의 보존이 우선 |
| 기본 이미지 판독 | MonkeyOCRv2-S-Parsing + PaddleOCR-VL-1.6 유지 | 소형 모델이고 한국어 공개 평가와 실행 경로가 있다. 두 결과를 동등하게 대조하며 최강 조합이라고 단정하지 않음 |
| 한국어 OCR 교체 우선 후보 | **PepperOCR-VL** | 동일 평가표의 한국어 성적이 더 높다. 실행 자원·배포 조건·원문 위치 연결을 충족하면 기존 둘 중 하나를 교체 |
| 기본 받아쓰기 | Qwen3-ASR-1.7B 유지 | 언어 구분과 여러 언어 처리가 필요하다. 한국어 단일 평가만으로 전체 역할을 교체하기 어려움 |
| 한국어 음성 대조 | **BuzzASR/korean으로 추천 변경** | 일반 Whisper large-v3보다 낮은 한국어 문자 오류율이 공개돼 있다. 다른 언어의 대조에는 기존 Whisper를 남김 |
| 음성의 시간 위치 | Qwen3-ForcedAligner-0.6B 유지 | 받아쓰기와 위치 추출은 다른 기능. 공식 Transformers용 `-hf` 배포본 사용 |
| 여러 사람의 발언 구분 | **pyannote Community-1 조건부 추가** | ASR과 Aligner만으로 화자 구분이 해결되지 않는다. 여러 화자를 구분해야 하는 자료에서만 실행 |
| HWP·페이지 표시·미디어 분리 | rhwp·pypdfium2·LibreOffice·FFmpeg 유지 | 원문 읽기, 화면 생성, 미디어 분리 도구다. 더 새 AI 모델이 이 역할을 통째로 대체하지 않음 |

이는 공개 근거로 정한 구현 추천이다. 실제 업무 자료에서 모델을 실행해 우열을 확인한 결과는 아니다. 15번을 확정 처리하지 않았으며, 기존 확정 문서는 수정하지 않았다.

## 기존 선택에 대한 비판

| 문제 | 왜 문제인가 | 반영 |
|---|---|---|
| 후보 비교 없이 도구 이름만 지정 | 기능이 있다는 사실은 최적이라는 근거가 아니다. 더 높은 한국어 성적의 후보가 이미 있다 | PepperOCR-VL과 BuzzASR을 비교에 포함하고 선택 이유 명시 |
| Paddle을 주 판독, Monkey를 대조로 고정 | 한국어 성적은 Monkey S가 더 높다. 충돌 때 Paddle을 우선할 근거가 없다 | 두 판독을 동등하게 취급 |
| 서로 다른 모델이면 독립 검증이라고 보기 쉬움 | Monkey의 학습용 정답 작성에 PaddleOCR-VL이 참여했다. 같은 오류를 배울 가능성이 있다 | 둘이 같은 오답을 내서 통과한 항목을 별도 측정 |
| 한국어 성능과 다국어·영어 성능 혼동 | 영어 순위나 전체 평균으로 한국어 계약서·회의록 품질을 대신할 수 없다 | 같은 평가의 한국어 결과와 평가 방식부터 확인 |
| Whisper large-v3를 무조건 대조용으로 고정 | 최신 한국어 추가 학습 모델과 비교하지 않았다 | 한국어 대조 추천을 BuzzASR로 변경 |
| 시간 위치는 있지만 화자 구분이 없음 | “누가 말했다”가 결론에 영향을 주는 회의·상담 기록을 완성할 수 없다 | 필요한 경우에만 pyannote 사용. 화자 번호와 실명은 구분 |
| FFmpeg로 장면을 나누면 영상 이해가 되는 것처럼 보임 | 장면 사이의 짧은 행동을 놓칠 수 있다 | 실제 확인 구간을 남기고 중요한 구간은 더 촘촘히 확인 |
| CPU 실행 가능성과 실용적인 속도가 섞임 | 설치 지침이나 모델 로딩 성공은 업무 시간 내 완료를 증명하지 않는다 | OS·CPU별 첫 실행·반복 실행·최대 메모리·실패율 비교 |
| 여러 환경 지원을 모든 처리가 CPU여야 한다는 뜻으로 좁히기 쉬움 | OS 독립성과 실행 자원은 다른 문제다. API와 GPU 경로도 비교 대상이다 | 공통 입출력 유지. GPU 요구 후보와 외부 API를 별도로 평가 |
| 도구에 내장된 OCR과 별도 OCR의 중복 실행 가능 | 같은 페이지를 불필요하게 다시 읽고 시간이 늘어난다 | 공통 읽기 기능이 실제 판독을 관리 |

원문 보존, 숨김 내용 분리, 중요값 검사, 실패 시 미확인 처리, 고객별 접근 권한은 기존 문서에 이미 있었다. 이번에 새로 만든 원칙처럼 취급하거나 삭제하지 않았다.

## 문서 판독 후보

### 같은 평가표에서의 한국어 성적

[MDPBench 공식 평가표](https://huggingface.co/spaces/Delores-Lin/MDPBench-leaderboard)의 2026-10-20 조회 결과다. 텍스트·수식·표 과제 점수를 페이지 단위로 집계한 값이며, **높을수록 좋다. 글자 정확도나 모든 업무의 성공률은 아니다.**

| 모델 | 한국어 점수 | 선택에 미치는 의미 |
|---|---:|---|
| **PepperOCR-VL** | **92.6** | 한국어 교체 후보에서 우선 검토할 근거가 충분함 |
| Kimi-K3 | 89.9 | 범용 대형 모델도 비교 대상이지만 작은 로컬 판독기의 직접 대체로 보기 어려움 |
| U2-OCR | 89.7 | 점수는 확인. 이번 조사에서 재현 가능한 공식 배포·호출 조건은 확보하지 못함 |
| **MonkeyOCRv2-S-Parsing** | **88.7** | 기존 선택을 구식이라고 버릴 근거가 없음 |
| MonkeyOCRv2-B-Parsing | 87.6 | 더 큰 모델로 바꾼다고 한국어 성적이 올라가지 않음 |
| **PaddleOCR-VL-1.6** | **86.3** | 유지 가능한 소형 후보. 최고 한국어 모델이라고 부를 근거는 없음 |
| PaddleOCR-VL-1.5 | 86.0 | 현 평가표에서는 1.6이 조금 높음 |
| ChandraOCR2 | 80.3 | 이 평가에서는 기존 조합보다 한국어 우위가 없음 |
| dots.mocr | 78.7 | 이 점수만으로 기존 모델을 교체할 이유가 없음 |
| MinerU-2.5-Pro-1.2B | 77.6 | 동일 |
| HunyuanOCR-1.5 | 75.7 | 동일 |
| GLM-OCR | 61.2 | 소형·최신이라는 이유로 한국어 기본값에 넣기 어려움 |

**평가표의 복사본도 최신이라고 믿으면 안 된다.** MonkeyOCRv2 README에 실린 Paddle 1.6 점수는 한국어 82.5였지만, 평가표 원본의 현재 값은 86.3이었다. 이 문서는 [평가표 원본 데이터](https://huggingface.co/spaces/Delores-Lin/MDPBench-leaderboard/blob/main/leaderboard.json)를 기준으로 썼다. Mistral OCR 4.0의 점수를 현재 4.1의 성적으로 옮겨 쓰지도 않았다.

| [ChandraOCR2](https://github.com/datalab-to/chandra) | 표·수식·필기 등 문서 판독과 다국어 지원 | 한국어 평가 우위가 확인되지 않았고 더 무겁다. 코드와 모델 가중치의 라이선스가 다르며 가중치는 별도 상용 조건이 있음 |

| [BizOnAI-OCR](https://github.com/ONTHEIT-AI/BizOnAI-OCR) | 한국어 공공 문서에 맞춘 모델과 평가 자료 | 한국어 특화 비교 후보. 개발진 자체 평가이며 비교 대상 Paddle의 버전이 명확하지 않아 Paddle 1.6보다 좋다고 단정할 수 없음 |
| [GravityOCR-KO](https://huggingface.co/trillionlabs/GravityOCR-KO) | 한국어용 후보, 공개 모델 카드 | 카드에 내부·비공개 모델이라는 표기가 남아 있고 정량 평가가 부족하다. 이름만으로 제품 기본 모델에 채택하지 않음 |
| [Mistral OCR 4.1](https://docs.mistral.ai/models/ocr-4-1) | 문서 구조·위치 정보를 제공하는 외부 서비스 후보 | 외부 전송이 허용되는 자료에서 비교할 가치가 있다. 무료 로컬 모델과는 배포·비용 구조가 다름. [공식 변경 이력](https://docs.mistral.ai/resources/changelogs)상 4.0은 2026-09-30 종료됐으므로 신규 선택에 4.0을 쓰지 않음 |

Pepper의 양자화 배포본이 있다는 사실만으로 위 점수와 CPU 속도가 유지된다고 볼 수 없다. 양자화·실행 엔진·입력 해상도를 바꾼 구성은 따로 평가한다. 공식 안내에 있는 반복 출력 재시도도 결과가 짧아졌다는 이유로 채택하지 않고 누락을 검사해야 한다.

### 두 모델이 같게 틀릴 가능성

[MonkeyOCRv2의 학습 자료 설명](https://github.com/Yuliang-Liu/MonkeyOCRv2)은 dots.mocr·PaddleOCR-VL·Qwen3-VL의 판독을 비교해 학습용 정답을 구성했다고 밝힌다. 이는 실제 오류가 반드시 같다는 증거는 아니지만, 구조가 다르다는 사실만으로 오류의 독립성을 주장할 수 없다는 근거다.

새 모델을 붙일 때는 단독 점수보다 **기존 조합이 놓친 중요한 오류를 잡는가**를 함께 본다. Pepper도 별도 Qwen 계열 모델이라고 해서 독립 검증이 보장되지는 않는다. 같은 원문을 서로의 답 없이 읽고, 둘이 같은 오답을 낸 항목을 정답 자료와 비교해야 한다.

## 음성 후보

### 한국어 대조용은 BuzzASR이 더 나은 후보

[BuzzASR/korean 모델 카드](https://huggingface.co/BuzzASR/korean)에 공개된 한국어 평가다. 문자 오류율은 **낮을수록 좋다.**

| 평가 자료 | 일반 Whisper large-v3 | BuzzASR/korean |
|---|---:|---:|
| FLEURS | 5.31% | 5.16% |
| Common Voice 25 | 6.01% | 4.24% |
| 두 자료 합산 | 5.72% | **4.61%** |

Whisper를 한국어로 추가 학습한 모델로, 2026-09-09 논문이 공개됐다. 개발진의 평가이며 학습 자료와 같은 계열의 시험 자료를 사용했다. 실제 회의의 겹친 말, 잡음, 고유명사, 한국어·영어 혼용에서 같은 개선을 보장하지는 않는다.

[논문 4.6절](https://arxiv.org/html/2609.09554v1)은 Qwen3-ASR와 Cohere의 오류율에는 정규화하지 않은 값을 썼다고 명시한다. 따라서 표에 함께 있는 숫자만으로 “Buzz가 Qwen보다 몇 % 정확하다”는 비교는 하지 않는다. **Whisper와의 개선 근거는 채택하되 Qwen 전체 교체의 근거로 확대하지 않았다.**

| 후보 | 적합한 역할 | 판단 |
|---|---|---|
| [Qwen3-ASR-1.7B](https://huggingface.co/Qwen/Qwen3-ASR-1.7B) | 언어 구분과 다국어 받아쓰기 | 기본 유지. 한국어 업무에서 절대 최강이라고 주장하지 않음 |
| [BuzzASR/korean](https://huggingface.co/BuzzASR/korean) | 중요한 한국어 발언의 두 번째 판독 | 추천 변경. 한국어 전용이므로 다른 언어 구간에는 사용하지 않음 |
| [Cohere Transcribe 03-2026](https://huggingface.co/CohereLabs/cohere-transcribe-03-2026) | 한국어를 포함한 14개 언어의 대체 ASR 후보 | 2B, Apache-2.0. 영어 평가 우위를 한국어로 확대하지 않음. 자동 언어 감지·시간 위치·화자 구분을 한 번에 제공하지 않으며 혼용 발언에도 제약이 있어 Qwen을 바로 대체하지 않음 |
| [Voxtral Transcribe 2](https://mistral.ai/news/voxtral-transcribe-2/) | 시간 위치·화자 구분을 함께 제공하는 외부 API | 서비스로 묶어 쓰면 부품을 줄일 수 있다. 배치 API 모델과 공개된 실시간 모델을 같은 배포물로 혼동하면 안 됨 |
| [ElevenLabs Scribe v2](https://elevenlabs.io/docs/overview/capabilities/speech-to-text) | 다국어 받아쓰기·시간 위치·화자 구분 API | 외부 전송이 허용되는 자료에서 품질·총비용 비교 후보 |
| [CLOVA Speech](https://www.ncloud.com/api-cms/service-product/static/clovaSpeech) | 한국어·영어 혼용, 장문 녹음과 화자 구분 API | 한국어 업무용 외부 서비스 비교에서 빼면 안 되는 후보. 이번 조사에서 동일 업무 자료의 경쟁 모델 대비 실측 우위는 확인하지 못함 |
| [Parakeet 1.1B RNNT Multilingual](https://build.nvidia.com/nvidia/parakeet-1_1b-rnnt-multilingual-asr/modelcard) | 한국어를 포함한 다국어 ASR | 한국어 미지원이라고 일괄 제외하면 틀리다. 다만 이 배포의 NVIDIA GPU·서버 실행 조건은 현재 일반 PC 기본 구성과 다름 |
| [Fun-ASR-MLT-Nano](https://huggingface.co/FunAudioLLM/Fun-ASR-Nano-2512) | 0.8B 다국어 경량 후보 | 한국어 지원은 MLT 변형에 있다. 일반 Nano와 구분해야 하며, 공개된 중·영 평가만으로 한국어 기본 모델 교체를 결정할 수 없음 |

**실행 방식도 갱신해야 한다.** Qwen은 현재 공식 [`Qwen3-ASR-1.7B-hf`](https://huggingface.co/Qwen/Qwen3-ASR-1.7B-hf) 배포본으로 Transformers 5.13 이상에서 직접 실행하는 경로를 제공한다. 모델 이름만 최신으로 적고 예전 전용 패키지와 라이브러리 조합을 계속 고정하는 방식은 피한다. 제품에는 실제로 함께 검증한 버전과 파일 지문을 고정한다.

**시간 위치와 화자는 별개다.** [Qwen3-ForcedAligner](https://huggingface.co/Qwen/Qwen3-ForcedAligner-0.6B-hf)는 글과 녹음의 위치를 맞추며, 지원 언어의 최대 5분 구간을 처리한다. [pyannote Community-1](https://huggingface.co/pyannote/speaker-diarization-community-1)은 서로 다른 화자의 구간을 나눈다. 실제 사람의 신원을 확인하는 기능으로 사용하지 않는다. CPU 실행·오프라인 사용 경로가 있으나 모델 취득 조건과 제품 배포 확인은 필요하다.

## 확정 전에 남은 실측

공개 문서로 확인한 것과 직접 실행한 것을 분리한다. 이번에는 모델 가중치를 받아 실행하거나 유료 API에 자료를 전송하지 않았다.

| 비교 | 확인할 결과 |
|---|---|
| 현재 OCR 두 개와 Pepper를 넣은 두 개 조합 | 같은 한국어 자료의 중요값·조건·표 연결 오류, 두 모델이 함께 틀린 항목, 원문 위치 보존 |
| Qwen + 일반 Whisper와 Qwen + BuzzASR | 중요한 한국어 발언의 누락·오인식, 잡음·혼용·겹친 발언에서의 변화 |
| 음성 정렬과 화자 구분 | 원본 녹음 기준 시간 오차, 화자와 발언의 잘못된 연결, 미확인 처리 |
| 실제 제품 실행 묶음 | Windows·macOS·Linux의 지원 CPU에서 설치·첫 실행·반복 실행·최대 메모리·실패 복구 |

일반 정확도만 높고 금액·날짜·조건의 미검출 오류가 늘어난 모델은 교체하지 않는다. 더 빨라도 필수 검사를 생략한 구성은 채택하지 않는다. 같은 품질이라면 실행 부품·처리 시간·총비용이 적은 구성을 고른다.

## 추가 피드백 반영 — 2026-10-20

| 보완 | 확인 근거와 본문 반영 |
|---|---|
| 원문 위치 | [Docling의 문서 구조](https://docling-project.github.io/docling/concepts/docling_document/)는 위치 정보가 있을 때 영역 좌표를 담을 수 있다. 모든 판독기가 좌표를 반환한다는 뜻은 아니다. [Pepper의 기본 출력](https://huggingface.co/sionic-ai/PepperOCR-VL#what-it-outputs)은 Markdown·HTML 표이므로 기존 영역 검출 결과와 연결하도록 했다. 페이지 번호·좌표 단위·기준점, 이미지 변형을 되돌리는 절차와 연결 검사 기준을 추가했다 |
| Pepper 실행·사용 조건 | [공식 모델 카드](https://huggingface.co/sionic-ai/PepperOCR-VL#license)의 bf16 실행 조건과 AGPL-3.0을 확인했다. 24GB 이상은 GPU 메모리 조건이며 모든 실행 방식의 최소값으로 확대하지 않았다. 제품에 적용되는 AGPL 의무 이행 또는 별도 상용 라이선스 확보를 채택 조건으로 명시했다 |
| 메모·숨김 내용 | [Docling의 자료형 정의](https://github.com/docling-project/docling-core/blob/main/docling_core/types/doc/document.py)에 내용 계층 구분이 있어도 모든 형식의 숨김 요소를 추출한다는 보장은 아니다. 누락 항목은 형식별 파서로 보완하고 원본의 항목 수·식별자·본문 연결을 대조하도록 했다 |
| OS별 실행 | [MonkeyOCRv2의 공식 CPU 지침](https://github.com/Yuliang-Liu/MonkeyOCRv2/blob/main/docs/cpu_support.md)은 Windows·Linux용이다. 제품의 공통 Linux 구성에 맞춰 Windows·macOS의 가상 머신을 포함한 실제 배포 경로를 각각 검증하도록 했다. 공통 입출력이나 모델 로딩 성공만으로 OS 지원을 확정하지 않는다 |

화자가 바뀌는 경계와 겹친 발언도 임의로 한 사람에게 배정하지 않도록 보완했다. 모델 구성은 유지했다. 문서 기준을 보완한 것이며, 모델 실행·세 OS의 제품 설치 시험은 수행하지 않았다.
