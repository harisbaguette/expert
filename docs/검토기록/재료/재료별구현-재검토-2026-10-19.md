# 재료별 구현 재검토 — PC 한 대의 하네스 시험

후속 검토: [기술 선택·중복·신뢰성 반영·가독성·lean 점검](재료별구현-5항목검토-2026-10-19.md). 아래 기록 이후 발견한 기능 누락과 중복 구현 가능성은 후속 검토에서 보완했다.

검토일: 2026-10-19. 대상은 `재료 별 구현.md`, 기준은 `전문가 에이전트 정의 1.md`의 목적과 79개 재료, 이번 대화에서 정한 시험 범위다.

**판정: 시험을 시작할 설계로 줄였지만, 전문성을 입증한 시스템은 아니다.** 문서에 적힌 장치의 구현과 실행 시험은 아직 남아 있다. ‘20년차를 대체한다’, ‘운영할 준비가 됐다’는 판정은 내릴 수 없다.

## 이번에 정한 범위

- PC 한 대에서 Claude Code와 Opus 5.5로 먼저 시험한다. 모델 없는 사내 서버까지 지금 만들지는 않는다.
- 공개·가상 자료와 가짜 상대 시스템을 쓴다. 시험 때문에 실제 고객의 직종 전체를 제외하지 않는다.
- 한 작업 대화에서 조사·판단·제작을 이어 간다. 검토는 별도 대화에 묶고, 코드로 끝나는 검사는 모델을 부르지 않는다.
- 실행 승인은 대상과 값을 확인해 예/아니오로 받는다. 전문 판단 검토와 법·계약상 자격자 검토는 구분한다.
- 같은 규칙의 설명을 구현 문서에 다시 복사하지 않는다. 재료의 번호와 구현 방법은 남긴다.

## 같이 고친 문서

`전문 판단의 신뢰성.md`에서는 승인과 직접 관련된 부분만 맞췄다. 실행 승인에서 결론 선작성·두 사람 승인을 일괄 요구하지 않도록 바꾸고, 필요한 전문 판단 검토는 유지했다. 발송·제출·지급은 이름이 아니라 실제 되돌릴 수 있는지와 사전 허락 범위로 가른다. 시험용 오류 건은 실제 업무에 섞지 않고 분리된 시험에서 쓴다.

신뢰성 문서의 완성 환경용 해결책을 이번 작은 시험에서 모두 구현했다는 뜻은 아니다. 전용 판독·온톨로지·상시 감시 등은 구현 문서의 보류 목록과 함께 보아야 한다. 이미지 파일과 다른 세션의 수정은 이 작업에서 바꾸지 않았다.

## 아직 ‘진짜 맞다’고 말할 수 없는 것

1. 시험 관리자·업무 도구·격리 설정은 설계만 있다. 실제 시작·중단·복구를 돌리지 않았다.
2. 현재 PC에서 사용량과 처리 시간을 재지 않았다. 새 흐름이 얼마나 절약하는지는 수치로 확정할 수 없다.
3. 숙련자 답과 비공개 과제를 확보해 비교하지 않았다. Opus 5.5의 해당 업무 성능과 장치의 추가 효과는 미확인이다.
4. 공개·가상 자료만 쓰는 시험으로 실제 고객 자료 처리, 법적 보관, 실서비스 배포를 검증할 수는 없다.

이번 완료 범위는 사용자의 결정 반영, 79개 재료의 대응 유지, 근거 없는 주장 정정, 구현 설계의 모순 축소다. 위 네 항목을 숨긴 채 완성 판정을 내리지 않는다.

## 문서 확인 결과

- 정의 1의 1~79번과 구현 문서의 제목·표를 대조했다. 누락, 정의 밖 번호, 이름 불일치, 재료 중복 정의는 각각 0개다.
- 변경 문서의 로컬 링크와 표 열 수를 확인했다. 기존 업무 지식 링크가 가리키던 앵커는 남겼다.
- 정의 1 원문은 변경하지 않았다. 신뢰성 문서의 승인 관련 수정이 남아 있는지도 확인했다. 다른 세션의 도식 교체는 별개 변경이다.
- 검증은 문서 구조와 설계 대조다. 모델을 실제로 호출하거나 고객 시스템을 시험하지 않았다.
