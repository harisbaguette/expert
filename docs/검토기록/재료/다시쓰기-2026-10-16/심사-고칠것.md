심사 둘: 검토자 눈(benan, 42절 가운데 확정 가능 11, 고치면 확정 31), 만드는 AI 눈(software-architect, 이대로면 돌아갈 가능성 35%, 고치면 75%).

## A. 구조를 바꾸는 결정 (주 대화가 정함)

1. **검색 도구는 PC MCP 서버에 둔다.** 질문 임베딩, 사내 서버에서 모델 없이 후보 조회, 재정렬, 모델에 돌려주기를 한 도구가 한 번에 한다. (사내 서버는 PC를 부를 수 없어 지금 판은 검색이 이어지지 않음: 31, 60, 505–508)
2. **Claude Code 없이 PC의 모델만 쓰는 일을 대기열의 한 종류로 둔다.** 앞선 결론 대조, 판례 추리기, 공개 법령과 판례 색인처럼 사내 서버 코드가 재정렬이나 임베딩을 써야 하는 일은 이 길로 PC에 넣고 상주 프로그램이 PC MCP로 처리해 돌려준다. (204–205, 318, 526, 532, 826)
3. **원문은 PC MCP 서버가 모델에 내주기 전에 사내 서버에 먼저 넣고, 받은 원문 번호를 함께 돌려준다.** 원문 저장의 주인은 이 하나다. (197, 213–214, 223, 226)
4. **사내 서버에서는 모델을 돌리지 않는다를 지킨다.** 내보내기 검사의 이름 찾기는 관계자 목록과 글자로 대조하는 코드로 하고, 목록 밖 이름은 독립 검사가 읽는다. 수신 서버 화면은 번호 검사와 관계자 이름 대조로 가린다. veil-pii-ko-lite는 PC MCP에서 모델에 넘기기 전에 가리는 데만 쓴다. (256, 366, 373)
5. **계산 코드를 사내 서버에서 다시 돌리지 않는다.** 실행 기록에 남은 계산 도구의 출력과 결과물의 숫자를 글자로 맞춘다. (587, 793)
6. **PC에만 있는 인증서가 필요한 바깥 행동은 시험 환경에서 맡지 않는다.** 바깥 행동은 모두 DBOS 단계 코드가 OpenBao의 비밀값으로 한다. (152, 360)
7. **단계 지시는 단계 기록 도구 한 곳에서만 준다.** 시스템 지시문에는 공통 원칙만, Skills에는 작업 요령만. 빠진 단계는 Stop 훅(답을 마치기 직전에 도는 자동 검사 장치)이 단계 기록 도구에 묻고, 있으면 끝내지 못하게 막아 같은 실행 안에서 채우게 한다. 실행을 통째로 다시 돌리지 않는다. (134, 213, 240, 262, 480)
8. **실패했을 때 다시 하기는 DBOS의 실패 종류별 표 하나에 둔다.** 시간 초과, 구독 한도, 제공사 장애, 거절, 형식 실패, PC 끊김마다 다시 할지, 횟수, 넘길 곳. 거절은 다시 하지 않고 바로 맡긴 사람에게 넘긴다. 다시 할 때는 기록된 마지막 단계부터 새 실행으로 잇는다. (88, 124, 126, 265, 867)
9. **실행 수 상한 5번 안에 들게 흐름을 고친다.** 맡긴 사람에게 물을 것은 받기 실행의 답에서 뽑아 일하기 전에 한 번에 묻는다. 흐름 표에 "고치기: 독립 검사에 걸린 항목만, 걸렸을 때만 1번, 시한 60분"을 더하고, 고친 결과는 내보내기 검사만 다시 돌린다. 진행 중에 온 새 자료는 다음 일하기 실행에서 훅 길로 본다. (74–82, 129, 159, 570, 653, 778, 781)
10. **Git**: 승인자가 서명한 Git 태그만 배포 대상으로 인정하고 받기 전에 서명을 확인한다. 사내 서버의 Git 저장소는 매일 감시 장비로 복사하고 되살리기 시험에 넣는다. (118, 309, 605, 852, 865, 898)
11. **검색 표는 고객 번호로 나눈 분할 표로 한다.** pg_textsearch는 분할마다 낱말 통계를 따로 잡는다. (505)
12. **시험 환경은 한 사람 PC 하나다.** PC별 대기열, 담당 PC 바꾸기, "모든 PC 같은 사양"은 뺀다. 시험 환경에서 누가 무엇을 맡는지 표를 하나 두고, 겸직하면 성립하지 않는 장치(두 사람 승인, 감시 장비 관리자 분리, 열쇠 3명 중 2명)는 사내 모델 환경으로 미룬다고 적는다. OpenBao는 사람 없이 열리게 한다. (7, 15, 61, 124, 146, 233, 653–665, 859, 918–927)
13. **업무 능력 시험**: Inspect는 과제 넣기와 채점만 하고, 실행은 운영과 같은 상주 프로그램이 한다. 가짜 상대 시스템과 시험용 DB 묶음을 부품 표에 넣는다. 공격 시험은 과제마다 3번, 바뀐 파일이 닿는 업무 종류만 다시 한다. 시험 한 번의 API 요금 한도 처음 값을 적는다. (899, 907–908, 941–944, 949)
14. **훅이 주 모델로 새 자료를 읽는 길**: 일하기 실행 안의 도구 없는 하위 에이전트가 먼저 읽어 지시가 있으면 경고를 붙인다. Claude Code를 새로 띄우지 않으므로 실행 수에 들지 않는다. 실패한 자료는 '지시 미확인'으로 표시하고 그 값에 기댄 행동은 권한 판정 창구가 막는다. (441)
15. **AI 모델 ✅ 절**: "다른 모델 여섯 가지" 대신 원래 원칙("OCR, 받아쓰기, 뜻 검색, 시계열 예측은 판단하는 모델이 아니라 도구라 이 규칙 밖")으로 되돌린다. 결과 검사 문장 바꾼 것은 둔다. 모델 고르는 거름에 "구독 한도 안에서 쓸 수 있는 모델"을 더한다(추가 요금이 붙는 모델이 뽑히지 않게).
16. **재료 번호를 되살린다.** 커밋 7fbdded가 원본에 넣은 번호(정의 1의 1~79)를 제목과 표의 재료 이름 칸에 모두 넣는다. 이름이 없던 덩어리 맨 앞에는 굵은 머리를 붙인다(예: 요청 접수 → **6. 시작 신호**, 모델에 줄 정보 → **3. 현재 작업 정보**, 판단 근거 → **69. 판단 근거 기록**, 숙련자 사례 → **24. 실전 경험·감각**, 사람에게 넘기기는 `### 42. 사람에게 넘기기` 제목). 번호와 이름은 `전문가 에이전트 정의 1.md`의 표에서 그대로 가져온다.
17. **장치별 효과 시험**: 막는 장치 넷 아래에 "모델을 거쳐 재는 장치" 표를 두고, 빠진 17줄(기준표, 시간축 지식 그래프, 법령과 판례 원문 저장소, 원본 시스템 조회, 문서 판독, 숨긴 글 검사, 자료 속 지시 찾기, 계산, 단계별 판단 절차, 늘 지킬 원칙, 기준 파일, 실행 기록, 진행 기록, 앞선 결론 목록, 이해충돌 조회, 변경 감시, 정해 둔 형식의 답)을 지금 부품 이름으로 짧게 되살린다. 원본 문장은 `git show 7fbdded:"재료 별 구현.md"`의 "장치마다 효과 재기" 표에 있다.

## C. 만드는 AI 눈의 나머지

- 125, 359: 훅은 내장 도구만, MCP 서버는 자기 도구만 권한 판정 창구에 묻는다. 차례 번호 검사는 창구 한 곳에서.
- 274–278: 건별 권한은 한도 값과 비교만, Cedar 분석 도구는 규칙을 바꿀 때만.

- 254, 858: 삭제 목록을 따로 두고, 되살린 직후 다시 지운다.

## D. 다른 문서와 어긋나는 곳 (보고만)

- 되돌릴 수 없는 행동의 범위: 기준 §4는 "법적으로나 물리적으로 되돌릴 수 없는 것만", 신뢰성 6-4와 넘기는 경우 표는 지우기, 보내기, 제출, 지급을 늘 되돌릴 수 없는 행동으로 다룸. 사용자가 기준 §4로 정했으므로 신뢰성 쪽을 고쳐야 함.
