# 재료별 구현 다시 쓰기 기준 (2026-10-16)

`재료 별 구현.md`를 절마다 나눠 다시 쓸 때 모든 작성자가 똑같이 따르는 결정이다. 사용자가 2026-10-16에 정했다.

## 1. 환경

- 지금 문서는 시험용 환경 하나만 다룬다: 한 사람 PC의 **Claude Code** 하나와, 모델을 돌리지 않는 사내 서버. Codex는 쓰지 않는다(Codex는 검사가 실패하면 막는 설정과 압축 끄는 설정이 없음).
- 궁극적으로는 사내 서버에서 모델을 돌리는 환경으로 만든다. 그래서 환경마다 달라지는 표는 `| 구분 | 에이전트 하네스 |`처럼 환경을 열로 둔 모양을 그대로 둔다. 나중에 열을 더할 자리다.
- 시험용이므로 실제 고객의 제3자 개인정보는 넣지 않는다. 시험용 자료나 쓰는 데 동의받은 자료만 쓴다. 구독 로그인은 운영자가 직접 시험하는 데에만 쓴다.

## 2. 부품 표 (이름은 이것만 쓴다)

| 부품 | 도는 곳 | 하는 일 |
|---|---|---|
| Claude Code | PC | 한 번 실행 안에서 주 모델을 부르고 도구를 쓴다 |
| 상주 프로그램 | PC | 수신 서버에서 자기 몫의 일을 받아 Claude Code를 실행하고, 결과를 돌려준다. 모델에 줄 정보를 골라 실행에 넣는 일도 여기서 한 번만 한다 |
| 훅(자동 검사 장치) | PC | Claude Code가 도구를 부르기 직전에 사내 서버의 권한 판정 창구에 묻고, 값만 보고 바로 가릴 수 있는 검사를 한다. 실패하면 막는다 |
| PC MCP 서버 | PC | 고객 파일 열기, 문서 판독, 음성 받아쓰기, 임베딩과 재정렬, 화면 조작(Playwright) |
| 수신 서버 | 사내 서버 | 요청과 알림을 받고, 일을 PC별 대기열에 넣고, 사람에게 묻는 결정 요청 화면과 사내 메신저 연결을 맡는다 |
| DBOS 단계 코드 | 사내 서버 | 한 건의 단계를 잇고, 끊기면 이어 가고, 사람 답을 기다리고, 밖으로 나가는 행동(송금, 발송, 제출, 기록 수정)을 요청 번호를 붙여 실행하고, 내보내기 전 검사를 돌린다 |
| 서버 MCP 서버 | 사내 서버 | 기억, 진행 상태, 판단 근거, 검색, 지식 그래프, 관계자 목록을 읽고 쓴다. 고객 번호는 서버가 낸 업무 토큰에서만 꺼낸다 |
| 권한 판정 창구 | 사내 서버 | Cedar로 허락할지 판정한다. 훅, PC MCP, 서버 MCP, DBOS 단계 코드가 모두 여기에 묻는다 |
| PostgreSQL | 사내 서버 | 모든 기록. pgvector와 pg_textsearch로 검색도 한다 |
| OpenBao | 사내 서버 | 비밀값과 암호 키 |
| Prometheus와 Alertmanager | 감시 장비(사내 서버와 다른 작은 장비 한 대) | 생존 신호와 경보 |
| pgBackRest | 사내 서버 → 감시 장비 | 백업과 되살리기 |

PC는 DB에 직접 붙지 않는다. 밖으로 나가는 행동은 Claude Code 안의 도구로 하지 않는다. 실행 안에서는 제안을 답에 적기만 하고, 실행은 DBOS 단계 코드가 한다.

## 3. 한 건의 실행 흐름과 실행 수 상한

Claude Code를 새로 띄우는 횟수는 한 건에 **기본 3번, 많아야 5번**이다. 넘을 것 같으면 맡긴 사람에게 알린다.

1. **받기**: 맡을지 확인(허용 목록, 이해충돌 조회)은 프로그램이 한다. 받은 자료 속 지시와 평가 요구 찾기는 도구 없는 실행 **1번**으로 그 건의 자료를 한꺼번에 본다.
2. **일하기**: 실행 **1번**. 판단 절차의 단계는 이 실행 안에서 차례로 한다. 필요하면 그 안에서 하위 에이전트를 쓴다. 사람의 답을 기다려야 하면 그 자리에서 끝내고, 답이 오면 사내 서버의 기록을 넣은 새 실행으로 잇는다(+1번).
3. **독립 검사**: 결과를 만든 실행과 따로 **1번**. 합격 기준 판정, 늘 지킬 원칙 판정, 인용이 주장을 뒷받침하는지, 받는 사람 입장에서 읽기를 한 번에 한다.
4. **다시 판단**: 틀렸을 때 피해가 감수할 위험을 넘을 수 있는 판단이 있을 때만 **1번**. 앞선 답을 보여 주지 않는다.
5. **내보내기 검사**: 모델 없이 프로그램이 한다. 인용 글자 대조, 계산 다시 하기, 번호 모양 개인정보, 보고와 실행 기록 대조.

뺀 것: Semantic Entropy(같은 물음 여러 번), 자료마다·인용마다·원칙마다 따로 띄우는 실행, 근거를 뺀 두 묶음 견주기를 늘 하는 것(의심될 때만 4번 안에서).

## 4. 사람의 승인

- 승인자는 프로그램이 미리 맞춰 본 실제 대상, 값, 근거를 보고 **예나 아니오**로 답한다.
- 되돌릴 수 없는 행동은 법적으로나 물리적으로 되돌릴 수 없는 것만이다. 미리 허락한 대상과 한도 안이면 묻지 않는다.
- 결론을 먼저 직접 쓰기, 틀린 곳을 넣은 시험 건 섞기, 두 사람 승인은 늘 하지 않는다. 운영하는 쪽 검사자가 무작위로 고른 건을 감사할 때만 한다.
- 법이 자격자의 판단을 요구하는 일만 자격자가 승인한다.

## 5. 되풀이 금지

- 읽는 사람은 같은 내용을 한 번만 읽어야 한다. `전문 판단의 신뢰성.md`와 `전문가 에이전트 정의 1.md`에 있는 "에이전트가 무엇을 해야 하나" 문장은 쓰지 않는다.
- 쓰는 것은 셋뿐이다. (가) 그 규칙을 어느 부품이 어떻게 지키게 하나, 한 줄. (나) 구현에만 있는 규칙(같은 알림 한 번만 받기, 재시도 횟수, 응답을 잃었을 때 처리 등). 이것은 지우지 않는다. (다) 지금 고른 것과 고른 까닭.
- "신뢰성 해결책 N을 따른다"처럼 다른 문서를 가리키는 문장은 쓰지 않는다.
- 같은 문서 안에서도 한 규칙은 한 자리에만 둔다.

## 6. 절의 모양

- 내용 종류는 같게: 원칙(있으면) → 고르는 기준 → 지금의 선택과 고른 까닭 한 줄 → 처음 값(숫자). 모양은 절마다 내용에 맞게 다르게 쓴다. 표만, 목록만으로 통일하지 않는다.
- "정해 둔 값"으로 끝내지 않는다. 처음 값을 숫자로 적고, 업무 종류마다 바뀌는 값이면 "업무 종류마다 운영하는 쪽이 바꾼다"를 덧붙인다.
- 제품마다 고른 까닭을 한 줄 붙인다. 견준 대안이 있으면 이름과 떨어뜨린 까닭을 짧게.
- 풀이가 필요한 말은 처음 나오는 곳에서 한 번만 하는 일로 푼다(예: 훅은 "자동 검사 장치").
- 설정 키, 명령 옵션, 파일 경로 같은 구현 잡일은 쓰지 않는다.
- 쉬운 한국어, 문장마다 한 가지, 말끝은 "~다".

## 7. 부품 정리

- 뺀다: Codex, Ceph RGW(대신 PostgreSQL에 덧붙이기만 되는 계정으로 넣고 건별 키로 암호화하고 해시 사슬로 지운 것을 찾는다), MonkeyOCRv2(결론을 좌우하는 셀만 주 모델이 잘라 낸 그림으로 다시 읽는다), d3(판단 전용 모델 역할은 재정렬 모델이 낸 "관련 있음" 확률로 한다), Catala(조문 번호를 붙인 Python과 기관이 낸 계산 사례 시험), SKOS, FIBO, PROV-O, OWL-Time, Semantic Entropy, PDF 글을 하나씩 지우고 다시 그리는 숨긴 글 검사.
- 남긴다: LinkML 한 벌에서 OWL 기준표, SHACL 검사, JSON 스키마를 뽑는 것(신뢰성의 온톨로지 해결책이 OWL과 SHACL을 쓴다), 하이브리드 검색과 GraphRAG(GraphRAG는 RAG만 쓸 때보다 나을 때만 켠다), 판독 모델 PaddleOCR-VL, 임베딩 Nemotron-3-Embed-8B, 재정렬 Qwen3-Reranker-4B, 음성 받아쓰기 Qwen3-ASR(교차 확인 Whisper), veil-pii-ko-lite, Betterleaks, Cedar, OpenBao, DBOS, PostgreSQL, Inspect.
- 익명성 검사(k-익명성 등)와 OpenDP 잡음은 사람마다 한 줄인 표나 통계를 밖에 내는 업무에만 건다.
- PC 사양: 모델용 메모리 32GB 이상(Nemotron 8B 약 16GB, 재정렬 4B 약 8GB, PaddleOCR-VL 약 2GB, Qwen3-ASR 약 4GB). 모든 PC를 같게 맞춘다.

## 8. 판단 수준

지금 장치는 틀린 것을 막는 쪽뿐이다. 실전 경험·감각 자리에 다음을 넣는다: 숙련자 사례 채집(결정 장면 면담, 숙련자가 고친 오답 묶음, 예외 사례), 그것을 단계 지시와 기준 파일로 옮기는 규칙, 작은 시험 단계에서 숙련자와 먼저 겨루는 일과 계속할지 가를 숫자 기준.
