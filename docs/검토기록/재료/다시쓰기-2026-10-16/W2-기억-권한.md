**원칙**

▶️ 모델은 서버 MCP 서버를 거쳐서만 기록을 읽고 덧붙이며, 고치거나 지우는 도구는 받지 않는다.<br>
▶️ 서버 MCP 서버는 덧붙이기 전에 그 건의 마지막 줄 번호가 읽을 때와 같은지 맞춘다. 다르면 받지 않고 다시 읽게 한다. 두 실행이 같은 건에 함께 쓰다가 한쪽 판단이 묻히는 것을 막으려는 것이다.

**지금의 선택**

| 기록 | 에이전트 하네스 |
| --- | --- |
| 장기 기억 | 사내 서버의 PostgreSQL. 고객마다 행 수준 접근 제어로 나눈다 |
| 진행 상태 | 사내 서버의 PostgreSQL. 덧붙이기만 한다 |
| 판단 근거 | 사내 서버의 PostgreSQL. 덧붙이기만 하고, 본문은 암호문으로 둔다 |
| 개인정보 | 사내 서버의 PostgreSQL. 기록과 떼어 둔 표에 암호문으로 둔다 |
| 앞선 결론 목록, 감시 목록 | 사내 서버의 PostgreSQL. PC마다 두면 그 PC가 맡은 건끼리만 맞춰 보게 된다 |
| 관계자 목록 | 사내 서버의 PostgreSQL. 고객 자료와 떼어 둔 표다. PC마다 두면 그 PC가 맡은 고객끼리만 대조하게 된다 |
| 모델에 줄 정보 | PC의 상주 프로그램이 위 기록에서 골라 실행에 넣는다 |

PostgreSQL을 고른 까닭: DBOS가 단계와 대기열을 이미 여기에 적고 검색도 pgvector와 pg_textsearch로 여기서 하므로, 기록 때문에 부품이 늘지 않는다.

### 장기 기억

**기억은 세 갈래로 나눠 담고, 그 고객의 갈래는 그 고객의 일에만 꺼낸다.**

▶️ 서버 MCP 서버는 기억을 세 갈래로 받는다. 그 고객만 가진 값과 조건과 계획, 다른 일에도 쓸 방법과 요령, 공개된 사실이다. 갈래, 나온 고객과 건, 출처, 유효 기간 가운데 하나라도 비면 받지 않는다.<br>
▶️ 고객의 사실과 조건을 적는 칸은 JSON 스키마의 허용값만 받는다. 병원 이름 같은 자유 글이 들어갈 자리가 없다.<br>
▶️ 꺼낼 때는 권한 판정 창구가 기억의 고객 표시를 보고 이번 건에 쓸 수 있는 것만 내준다. 행 수준 접근 제어가 한 번 더 거른다. 유효 기간이 지난 기억은 내주지 않는다.<br>
▶️ 방법과 요령 갈래는 실행에 넣지 않는다. 고객 정보를 지운 뒤 단계 지시, 기준 파일, 업무 지식의 변경으로 옮겨 가고, 시험과 승인을 거쳐 합쳐진 것만 쓰인다.<br>
▶️ 공개된 사실 갈래는 원문 번호와 함께 내준다. 내보내기 검사는 이번 실행에서 그 원문을 다시 읽은 기록이 없으면 그 사실을 근거로 치지 않는다.<br>
▶️ 서버 MCP 서버는 기억을 내줄 때마다 그 기억 번호를 이번 판단 기록에 적는다. 기억이 틀린 것으로 드러나면 이 번호로 그 기억을 쓴 판단을 찾는다.

**앞선 결론 목록은 "다른 고객의 일에 그 고객만의 갈래를 들이지 않는다"의 하나뿐인 예외다.** 아래 세 조건을 모두 채운 줄만 다른 고객의 판단과 맞춰 본다.

| 조건 | 지키게 하는 것 |
|---|---|
| 칸은 쟁점, 기준의 버전, 기준표 항목의 사실 값, 조건별 충족 여부, 결론 다섯뿐이고, 모두 허용값만 받는다 | 서버 MCP 서버가 JSON 스키마로 받는다. 자유 글 칸은 두지 않는다 |
| 같은 쟁점, 기준 버전, 사실 값 조합에 든 고객이 5곳 이상이다 | 올리기 전에 세는 코드가 센다. 모자라면 사실 값을 넓은 구간으로 바꿔 다시 세고, 그래도 모자란 줄은 그 고객의 건끼리만 맞춰 본다 |
| 이번 건을 먼저 판단해 기록한 뒤 대조에만 쓰고, 결론의 근거로는 쓰지 않는다 | DBOS 단계 코드가 일하기 실행의 판단이 기록된 뒤에 대조 단계를 돌린다. 내보내기 검사는 결과물이 앞선 결론 목록을 근거로 가리키면 내보내지 않는다 |

▶️ 앞선 결론이 틀렸으면 지우지 않고 바로잡는 줄을 덧붙인다. 서버 MCP 서버는 맞춰 볼 때마다 두 줄의 번호를 남겨, 틀린 결론과 맞춰 본 판단을 모두 찾게 한다.<br>
▶️ 고객 수의 처음 값은 5곳이다. 업무 종류마다 운영하는 쪽이 바꾼다.

### 진행 상태

**모델은 서버 MCP 서버의 덧붙이기 도구로만 쓰고, 서버 MCP 서버가 받기 전에 검사한다.**

▶️ 서버 MCP 서버가 쓰는 DB 계정에는 넣기와 읽기 권한만 있다. 그래서 틀린 줄도 바로잡는 줄과 그 까닭을 덧붙여서만 고친다.<br>
▶️ 판단 줄은 정해 둔 칸이 다 차고, 가리킨 원문 구절이 원문에 글자 그대로 있을 때만 받는다. 받지 못하면 DBOS 단계 코드가 다음 단계로 넘어가지 않는다.<br>
▶️ 도구로 받은 원문과 고객이 대화나 메일로 보낸 말은 서버 MCP 서버가 판단 근거 쪽에 그대로 넣는다. 진행 상태에는 원문 번호와 해시만 적는다. 모델은 사실을 옮겨 적지 않는다.<br>
▶️ 판단 줄마다 기댄 기록 항목, 원문 번호, 계산식, 규칙 해석, 거친 단계를 번호로 잇는다. 같은 원인으로 틀렸을 수 있는 판단을 이 번호로 찾는다.<br>
▶️ DBOS 단계 코드는 그 단계의 결정과 결과가 저장된 뒤에야 단계를 끝난 것으로 적는다. 저장하기 전에 끊기면 그 단계를 처음부터 다시 한다.<br>
▶️ 한 건을 마친 것과 상시 업무 자체를 끝낸 것은 다른 상태 값으로 적는다.

### 판단 근거

**판단 근거는 모델이 아니라 네 부품이 남긴다.** 모두 업무 번호 하나로 묶어 시간 순서대로 읽는다.

| 남기는 부품 | 남기는 것 |
|---|---|
| 상주 프로그램 | 실행에 넣은 시스템 지시문과 입력 전체. 실행 중에 나온 모델의 답, 도구 호출, 도구 결과 전체 |
| 권한 판정 창구 | 모든 판정 요청과 답 |
| DBOS 단계 코드 | 밖으로 나간 행동의 요청과 응답, 전달한 결과물의 최종 버전, 원본 시스템의 변경 기록. 변경 기록은 사람이나 다른 시스템이 바꾼 것까지 받는다 |
| 서버 MCP 서버 | 도구로 받은 원문, 고객이 보낸 말과 글, 결과물에 넣은 그림과 표를 받아 온 실행 기록 번호 |

**본문은 PostgreSQL에 덧붙이기만 하고, 건별 키로 잠그고, 해시 사슬로 몰래 지운 것을 찾는다.**

▶️ **덧붙이기만**: 판단 근거에 쓰는 계정은 모두 넣기와 읽기만 할 수 있다. 표를 만든 계정과 관리자 계정은 업무 프로그램이 쓰지 않는다.<br>
▶️ **건별 키**: 본문은 넣기 전에 OpenBao가 암호화한다. 키는 건과 보관 기간마다 하나이고, OpenBao 밖으로 꺼낼 수 없게 만든다. DB에는 암호문만 남는다.<br>
▶️ **해시 사슬**: 줄마다 앞 줄의 해시와 이 줄의 암호문을 합쳐 해시를 낸다. 평문으로 내지 않는 까닭은 짧은 개인정보를 해시에서 되짚을 수 있기 때문이다. 사슬은 표 전체에 하나다. 쓰기가 몰려 초당 100줄을 넘으면 건마다 나누고, 모든 사슬의 끝값을 묶어 남긴다.<br>
▶️ **끝값 남기기**: 하루 한 번 사슬의 끝값을 감시 장비에 남긴다. 감시 장비는 같은 때 사슬 전체를 다시 계산해 전날까지 남긴 끝값과 맞추고, 어긋나면 Alertmanager로 운영하는 쪽 책임자에게 알린다. 감시 장비의 관리자 권한은 사내 서버 관리자가 갖지 않는다. 서버 관리자가 줄을 지우고 사슬을 다시 만들어도 찾아내려는 것이다. 두 장비를 한 사람이 관리할 수밖에 없으면 끝값을 회사 밖 타임스탬프 서비스에서도 서명받아 남긴다. 밖으로 나가는 것은 해시 값뿐이다.<br>
▶️ **지우기**: 줄은 지우지 않는다. 키를 OpenBao에서 지워 내용만 되살릴 수 없게 하고, 지운 까닭을 새 줄로 덧붙인다. 그래서 지워도 사슬이 끊기지 않는다.

고른 까닭: 고치지 못하게 막기, 되살릴 수 없게 지우기, 몰래 지운 것 찾기를 이미 쓰는 PostgreSQL과 OpenBao로 다 한다. Ceph RGW의 고칠 수 없는 저장소는 부품이 하나 늘고, 몰래 지운 것을 찾는 일은 해시 사슬이 이미 해서 뺐다.

**기록을 남기지 못하면 실행하지 않는다.**

▶️ 권한 판정 창구는 판정 요청을 저장하지 못하면 거부로 답한다. 그래서 기록 없이 도는 도구 호출이 없다.<br>
▶️ 상주 프로그램이 실행 기록을 사내 서버에 30초 넘게 넘기지 못하면 그 실행을 멈춘다. 넘기지 못한 기록은 메모리에만 들고 있다가 버리고, PC 디스크에 남기지 않는다. 멈춘 단계는 DBOS 단계 코드가 다시 띄운다.<br>
▶️ OpenBao가 암호화하지 못할 때도 기록을 넣지 못하므로 같은 길로 멈춘다.

**그 밖의 규칙**

▶️ 긴 자료는 PC MCP 서버가 조각마다 번호를 붙여 내준다. DBOS 단계 코드는 실행 기록에 남은 번호를 조각 전체와 맞춰, 빠진 조각이 있으면 다음 단계로 넘기지 않는다.<br>
▶️ 행동의 까닭을 묻는 요청은 수신 서버가 받아, 그 행동 직전의 진행 기록과 실행 기록을 그대로 보여 준다. 모델을 거치지 않으므로 까닭을 새로 지어낼 수 없다. 기록이 없으면 기록된 까닭이 없다고 답한다.<br>
▶️ 상주 프로그램은 기록을 넘기기 전에 Betterleaks로 비밀값을 찾아 가린다. 인증 정보는 기록에 남기지 않는다.<br>
▶️ 서버 MCP 서버는 에이전트가 작업 폴더에 만든 파일과, 도구가 모델로 요약하거나 뽑아 돌려준 글을 원문으로 넣지 않는다.

### 개인정보

**떼어 둘 수 있는 개인정보는 떼고, 암호 키는 OpenBao 한 곳에 두 단위로 둔다.**

서버 MCP 서버는 기록에 들어오는 이름, 연락처, 번호 같은 개인정보 칸을 개인정보 표로 떼고, 기록에는 그 표의 번호만 남긴다.

| 키 단위 | 잠그는 것 | 지우는 때 |
|---|---|---|
| 건과 보관 기간 | 판단 근거 본문, 진행 상태에 떼지 못하고 남은 개인정보. 같은 건 안에서도 보관 기간이 다른 정보는 다른 키를 쓴다 | 보관 기간이 끝날 때. 본인이 삭제를 요구하면 그 사람이 나온 건의 키도 지운다. 법에 따라 보관해야 하는 건이면 그때까지 권한 판정 창구가 접근만 막고, 기간이 끝나면 지운다 |
| 정보 주체 | 개인정보 표에 떼어 둔 그 사람의 정보 | 본인이 삭제를 요구할 때 |

▶️ 키를 지우는 일은 되돌릴 수 없다. 보관 기간이 끝나 지우는 것은 미리 허락한 일로 DBOS 단계 코드가 한다. 본인 요구로 지우는 것은 운영하는 쪽 책임자가 결정 요청 화면에서 대상 건과 키 목록을 보고 '예'로 답한 뒤에 한다.<br>
▶️ 검색 색인과 지식 그래프의 문서 조각, 건의 Git 저장소, PC의 고객 폴더에 든 파일은 암호화하지 않은 사본이다. 키를 지울 때 그 건의 조각과 저장소와 파일도 함께 지운다.<br>
▶️ 검색 색인과 지식 그래프는 검색하려면 평문이어야 한다. 그래서 업무 DB와 떼어 둔 PostgreSQL에 두고, 그 백업은 7일만 보관한다. 지운 조각이 오래 보관하는 업무 DB 백업에 평문으로 남지 않게 하려는 것이다.<br>
▶️ 관계자 목록은 이해충돌을 확인할 의무가 남은 동안 정보 주체 키로 잠그지 않고 지우지도 않는다. 의무가 끝나면 지운다.<br>
▶️ 수신 서버의 화면은 사람에게 기록을 보여 줄 때 번호 검사 코드와 veil-pii-ko-lite가 찾은 개인 식별 정보를 가려 보여 준다. 다시 판단할 때 쓰는 모델 입력 전체는 가리지 않고 암호문으로 둔다. 기록을 볼 수 있는 사람은 업무 종류마다 Cedar 규칙으로 정한다.

### 모델에 줄 정보

**상주 프로그램이 실행을 띄울 때 한 번 고르고, 실행 안에서 더 필요한 것은 모델이 서버 MCP 서버로 찾는다.**

▶️ 시스템 지시문에는 모든 단계에 공통인 원칙과 그 실행이 맡은 단계의 지시만 넣는다. 한 번에 지킬 지시의 수를 줄이려는 것이다.<br>
▶️ 실행 안에서 하위 에이전트를 쓰면 그 지시문에도 공통 원칙을 똑같이 넣는다. 일을 나눠도 원칙이 빠지지 않게 하려는 것이다.<br>
▶️ 첫 입력은 자료 → 진행 상태의 조건과 미확인 사항 → 이번 단계의 물음과 지시 순서로 넣는다. 지금 주 모델의 제공사 지침이 긴 자료를 앞에, 물음을 끝에 두게 한다.<br>
▶️ 자료는 맡긴 사람의 지시와 다른 칸에 넣는다. 자료 속 글을 지시로 따르는 일을 줄이지만, 이것만으로 다 막지는 못한다.<br>
▶️ 서버 MCP 서버는 바로잡힌 항목을 바로잡은 값으로 내주고, 바로잡혔다는 표시와 적은 시각을 붙인다.<br>
▶️ 일하기와 검사 실행의 첫 입력은 모델이 한 번에 받을 수 있는 양의 절반을 넘지 않게 한다. 넘으면 자료를 다 넣지 않고 조각 목록만 넣어, 모델이 PC MCP 서버로 나눠 읽게 한다.<br>
▶️ 상주 프로그램은 실행이 쓴 입력 토큰 수를 지켜보다가 모델이 한 번에 받을 수 있는 양의 80%에 닿으면 실행을 멈추고, 사내 서버의 기록을 넣은 새 실행으로 잇는다. 이 실행도 실행 수에 센다. 처음 넣은 조건이 요약으로 바뀌지 않고 실행 끝까지 그대로 남게 하려는 것이다.

## 규칙과 권한

**원칙**

▶️ 허락할지는 사내 서버의 권한 판정 창구 한 곳이 Cedar 규칙으로 판정한다. 훅, PC MCP 서버, 서버 MCP 서버, DBOS 단계 코드가 모두 여기에 묻는다. 규칙이 한 벌이라 길마다 다르게 판정하는 일이 없다.<br>
▶️ 창구는 판정할 때마다 그 건의 권한, 승인, 이미 했거나 진행 중인 행동의 합계를 PostgreSQL에서 새로 읽어 Cedar에 넣는다. 미리 받아 두지 않으므로 권한을 거두면 다음 판정부터 바로 막힌다.<br>
▶️ 묻는 쪽은 답을 받지 못하면 막는다.

**무엇을 Cedar에 맡기나**

| 경우 | 맡는 쪽 |
|---|---|
| 대상, 금액, 기한, 받는 곳, 자료의 고객 표시처럼 값으로 가릴 수 있다 | 권한 판정 창구의 Cedar 규칙 |
| 요청이나 계약, 규정의 뜻을 해석해야 한다 | 주 모델. 원문과 이번 건의 사실을 함께 준다 |

Cedar를 고른 까닭: 건마다 준 규칙이 운영하는 쪽이 정한 최대 범위 안에 드는지 기계로 증명하고, 벗어나면 그 요청 예를 돌려주는 분석 도구가 있다. OPA는 이런 증명 도구가 기본으로 없어 뺐다.

**규칙을 바꾸고 올리는 길**

▶️ Cedar 규칙은 사내 서버의 Git 저장소에 두고, 운영하는 쪽만 바꿀 수 있다. 누가 무엇을 왜 바꿨는지는 Git 기록으로 남는다.<br>
▶️ 바꾼 규칙은 허용할 요청과 막을 요청의 시험 사례를 통과해야 창구에 올린다. 근거 원문이 개정되면 규칙과 시험 사례를 함께 고친다.<br>
▶️ 건마다 준 권한은 창구에 올리기 전에 Cedar 분석 도구로 최대 범위 안에 드는지 증명한다. 벗어나는 요청 예가 나오면 올리지 않고 그 예를 운영하는 쪽에 보여 준다.

**창구에 묻다 실패할 때**

| 묻는 쪽 | 기다리는 시간 | 다시 묻기 | 끝내 답이 없으면 |
|---|---|---|---|
| 훅 | 2초 | 하지 않는다 | 그 도구 호출을 막는다. 훅이 아예 돌지 못해도 막는다 |
| PC MCP 서버, 서버 MCP 서버 | 2초 | 하지 않는다 | 그 요청을 거부한다 |
| DBOS 단계 코드 | 2초 | 1초, 4초, 16초 뒤 세 번 | 행동하지 않고 단계를 대기로 돌린다. Prometheus가 창구의 생존 신호가 끊긴 것을 보고 경보한다 |

### 이번 업무에 적용할 규칙

**규칙을 가져오는 곳과 실행에 닿는 길**

| 재료 | 가져오는 곳 | 실행에 닿는 길 |
|---|---|---|
| **법·의무 기준** | 업무 지역과 분야의 법령, 판례, 해석례 | ▶️ 법령마다 위계와 시행일을 함께 받아 둔다<br>▶️ 위계가 다른 충돌은 프로그램이 상위법으로 정한다<br>▶️ 위계가 같으면 주 모델이 특별법 관계인지 가리고 독립 검사 실행이 다시 본다. 특별법이면 그것을, 아니면 프로그램이 나중 법을 앞세운다<br>▶️ 풀리지 않은 충돌은 DBOS 단계 코드가 그 충돌에 걸린 행동만 멈춘다 |
| **직업 윤리·의무** | 법, 계약, 전문단체 규정 | 기준 파일의 분야 층 |
| **에이전트 기본 원칙** | 운영하는 쪽이 쓴 공통 원칙 | 모든 실행의 시스템 지시문 |
| **조직 규칙** | 맡긴 조직의 인사 시스템과 결재 시스템 | 서버 MCP 서버의 조회 도구로 누가 결정하는지 읽는다. 위임이 바뀌면 DBOS 단계 코드가 기다리는 결정 요청의 받는 사람을 바꾼다 |
| **사용자 지정 규칙** | 맡긴 사람이 정한 조건 | PostgreSQL의 고객 규칙 표에 꼭 지킬 조건과 선호를 다른 칸으로 둔다. 조건을 정할 권한이 있는 사람이 낸 것만 받는다 |
| **플랫폼·제출처 규정** | 플랫폼과 제출처의 공식 안내 | 기준 파일에 둔다. 제출 직전에 DBOS 단계 코드가 공식 안내를 다시 받아 바뀌었는지 맞추고, 제출처가 주는 검사나 미리보기 기능이 있으면 쓴다 |

**기준 파일은 사내 서버의 Git 저장소에 두고, 에이전트는 읽기만 한다.**

▶️ 업무 종류마다 운영하는 쪽이 정하는 기준은 공통, 분야, 세부 업무의 층으로 나눈 기준 파일에 둔다.<br>
▶️ PC에는 읽기 전용 사본만 내려간다. 바꾸는 길은 Git 변경 요청 하나이고, 그 분야 전문가가 승인하지 않으면 합쳐지지 않게 막는다. 주 모델이 빠진 기준을 찾아도 이 변경 요청으로만 낸다.<br>
▶️ 항목마다 기댄 조문 번호를 적는다. 법령 변경을 받는 감시 단계가 그 번호와 맞춰 항목에 '다시 검토'를 표시하고, DBOS 단계 코드는 표시된 항목에 기댄 건을 끝내지 않는다.<br>
▶️ 일이 여러 업무 종류에 걸치면 상주 프로그램이 해당 기준 파일을 합쳐 넣는다. 꼭 들어갈 항목은 모두 합치고, 기본값이 다르면 확인을 더 요구하는 쪽을 쓴다.

**이해충돌 조회**

받기 단계에서 DBOS 단계 코드가 관계자 목록을 조회한다 → 후보가 없으면 맡는다 → 후보가 있으면 그 건을 판정 대기로 두고 운영하는 쪽 책임자의 결정 요청 화면에 올린다 → 책임자의 판정과, 판정이 요구한 동의가 기록된 뒤에야 일을 시작시킨다

▶️ 실행에는 충돌이 있는지만 간다. 어느 건과 겹치는지는 권한 판정 창구가 운영하는 쪽 책임자에게만 보여 준다.<br>
▶️ 조회하는 이름은 이번 건의 당사자와 관계자, 그들의 예전 이름과 다른 표기, 지배 관계에 있는 회사와 그 대표자다. 같은 건에 한쪽 편에서 만든 결과물이 있는지도 조회한다.<br>
▶️ 회사는 상호가 바뀌어도 그대로인 법인등록번호와 공시 고유번호로 찾는다.<br>
▶️ 번호로 찾지 못하는 사람과 회사는 이름이 같은 후보를 모두 남기고, 이름이 달라도 생년월일, 주소, 연락처, 대표자가 겹치는 후보를 더 찾는다. 그래서 맡을 때 당사자와 관계자의 이 네 가지를 함께 받는다.<br>
▶️ 자료를 넣는 단계에서 새 당사자나 관계자가 나오거나, 날마다 받는 공시로 이미 맡은 건의 관계가 바뀌면 다시 조회한다. 충돌이 나오면 DBOS 단계 코드가 그 건을 멈추고 책임자의 판정을 기다린다.

| 자료원 | 받는 것 | 받는 때 |
|---|---|---|
| 금융감독원 전자공시 | 대량보유 상황보고, 임원과 주요주주의 소유보고, 주요사항보고서 | 날마다 |
| 금융감독원 전자공시 | 정기보고서의 최대주주 현황, 임원 현황, 타법인 출자현황 | 보고서가 나올 때마다 |
| GLEIF의 모회사 관계 파일 | 해외 모회사 | 날마다 |
| 법인등기부 | 이번 건에 걸리는 비상장회사의 임원 | 일을 맡을 때 |
| 맡긴 사람 | 사업보고서를 내지 않는 비상장회사의 최대주주, 모회사, 출자한 회사 | 일을 맡을 때. 받지 못한 것은 확인하지 못한 관계로 표시해 책임자에게 알린다 |

### 권한과 예산을 실행에 적용하기

**업무 권한은 PostgreSQL의 권한 표에 두고, 권한 판정 창구가 판정할 때마다 읽는다.**

▶️ 누가 맡겼는지, 어떤 명의와 계정으로, 어느 대상에, 얼마까지, 언제까지인지를 건마다 적는다. 되풀이해 쓰는 위임도 같은 칸에 적는다.<br>
▶️ 자료 조회, 밖으로 나가는 행동, 결과 공개는 Cedar의 행동 종류를 따로 두어 따로 허락한다.<br>
▶️ 업무 종류, 미리 허락할 행동과 한도, 위급할 때 답할 사람과 할 조치가 비어 있으면 창구는 거기에 기대는 요청을 거부한다.<br>
▶️ 건마다 따로 받은 계정으로 행동한다. 계정을 나눌 수 없으면 DBOS 단계 코드가 그 계정에 잠금을 걸어 한 번에 한 건만 실행하고, 변경 기록이 남지 않는 곳은 행동 전후 상태를 저장해 비교한다. 그것도 할 수 없는 곳의 쓰기 행동에는 '되돌릴 수 없음' 표시를 단다.<br>
▶️ 창구가 권한 밖이라 거부하면 거부 까닭을 돌려준다. DBOS 단계 코드는 권한 안의 준비를 마친 뒤 더 필요한 권한을 결정 요청 화면에 올린다.

**승인은 권한 판정 창구가 읽어야 실행 권한이 된다.**

▶️ 되돌릴 수 없는 행동 종류에는 Cedar 규칙에 '되돌릴 수 없음' 표시를 단다. 창구는 이 표시가 붙은 행동이 미리 허락한 대상과 한도를 벗어나면, 승인 줄이 없는 한 거부한다.<br>
▶️ 창구는 결정 요청 화면에서 온 승인 줄만 승인으로 읽는다. 문서나 메일에 적힌 승인 문구는 실행 권한이 되지 않고, 다른 사람이 이미 결정했다는 증거로 쓸 때만 그 내용과 출처를 본다.<br>
▶️ DBOS 단계 코드는 실행 직전에 승인 번호와 실제로 실행할 대상, 값을 창구에 넣어 다시 묻는다. 창구는 승인한 대상과 값이 글자까지 같을 때만 허락한다.

**비용은 Claude Code 실행 수와 구독 사용량으로 잰다.** 실행 수는 DBOS 단계 코드가 세는 상한으로 막고, 구독 사용량과 유료 조회 금액은 아래처럼 DBOS 단계 코드가 PostgreSQL에서 세고 미리 잡는다. 남은 몫을 확인하는 일과 잡는 일은 한 번에 처리해, 여러 단계가 같은 몫을 함께 쓰지 못하게 한다.

| 한도 | 처음 값 | 재는 법 | 닿을 때 |
|---|---|---|---|
| 구독 사용량 | 실행 하나 20달러, 건 하나 60달러 | 실행이 끝날 때 Claude Code가 내는 토큰 수와, 주 모델 요금표로 환산한 금액을 더한다. 실행은 남은 몫을 상한으로 걸어 띄운다 | 남은 일까지 하면 넘을 것 같으면 다음 실행을 띄우기 전에 멈추고, 맡긴 사람에게 늘릴지 묻는다 |
| 유료 조회 금액 | 한 건에 3만 원 | 조회 전에 잡고, 결과를 확인한 뒤 정산한다. 결과가 분명하지 않으면 잡은 몫을 풀지 않는다 | 조회하기 전에 멈추고 맡긴 사람에게 묻는다 |

▶️ 두 처음 값 모두 업무 종류마다 운영하는 쪽이 바꾼다.<br>
▶️ 감수할 위험은 DBOS 단계 코드가 합산한다. 같은 기준 항목과 같은 계산 코드로 판단한 건을 끝난 것, 진행 중인 것, 기다리는 것까지 PostgreSQL에서 모아 건수와 피해 금액을 더한다. 한 건의 피해 금액은 기준 파일에 정한 방법으로 잰다.

### 실제 실행을 막거나 허용하는 장치

**행동마다 권한 판정 창구에 묻고, 실제로 행동하는 계정의 권한으로도 한 번 더 막는다.**

▶️ 훅은 Claude Code가 도구를 부르기 직전마다 창구에 묻는다. 훅이 실패하거나 시간을 넘기면 도구를 막도록 설정한다. 이 설정이 없으면 Claude Code는 실패한 훅을 건너뛰고 도구를 실행한다.<br>
▶️ 훅에만 맡기지 않는다. PC MCP 서버와 서버 MCP 서버는 요청마다 다시 묻고, DB 계정과 업무 계정에도 그 일에 필요한 권한만 준다.<br>
▶️ 밖으로 나가는 행동에 쓰는 업무 계정의 비밀값은 OpenBao에 두고 DBOS 단계 코드만 꺼낸다. PC와 Claude Code에는 그 비밀값이 없으므로, 창구를 거치지 않고 밖으로 나가는 길이 없다.<br>
▶️ 서버 MCP 서버는 자료에서 나온 값마다 어느 자료에서 왔는지 표시를 붙인다. 돈 받을 사람이나 보낼 곳처럼 업무 종류마다 정해 둔 값은 표시가 원본 시스템을 가리킬 때만 창구가 허락한다. 그래서 받은 자료에 적힌 값으로는 받는 사람이나 보낼 곳을 바꾸지 못한다.<br>
▶️ 권한을 거두면 그때 OpenBao가 그 건의 업무 토큰과 업무 계정 접속도 거둔다.<br>
▶️ 기준 파일, 시험, 대조할 원본은 PC에 읽기 전용으로만 내려간다. 시험의 정답과 채점 코드는 PC에 내려보내지 않는다.

**인증 정보**

▶️ 사람이 사내 로그인을 하면 상주 프로그램이 건마다 그 건의 권한만 담은 업무 토큰을 받는다. 업무 토큰은 OpenBao가 서명하고, 건 번호와 고객 번호, 끝나는 시각을 담는다.<br>
▶️ 업무 토큰은 실행이 끝나면 바로 거두고, 길어도 8시간이면 끝난다. PC 디스크에는 로그인 비밀값과 토큰을 두지 않는다.<br>
▶️ 상주 프로그램은 토큰을 훅과 PC MCP 서버에만 넘긴다. 모델 입력과 고객 폴더에는 넣지 않고, 셸 명령에는 보이지 않게 한다.

**밖으로 내보내기 전 검사는 DBOS 단계 코드가 모델 없이 돌리고, 하나라도 걸리면 내보내지 않는다.** 받는 사람 입장에서 읽는 일은 독립 검사 실행이 한다.

| 검사 | 하는 것 | 고른 것과 까닭 |
|---|---|---|
| 받는 곳과 자료의 주인 | 받는 곳이 맡을 때 등록한 곳인지, 첨부의 고객 표시가 받는 쪽과 맞는지, 결과물의 값이 받는 사람이 볼 수 있는 자료에서 왔는지 본다 | 권한 판정 창구. 값마다 붙은 출처 표시로 판정한다 |
| 비밀값 | 결과물과 첨부에서 열쇠, 토큰, 비밀번호를 찾는다 | Betterleaks. Gitleaks를 만든 사람들이 이어 만들고, 자연어 글에서 잘못 잡은 것을 거르는 기능이 있다. 찾은 비밀값이 살아 있는지 밖에 물어보는 기능은 끈다 |
| 번호 모양의 개인정보 | 번호마다 검증 숫자와, 번호 앞뒤의 '주민번호', '주민등록번호' 같은 한국어 낱말을 함께 본다. 2020년 10월 뒤에 받은 주민등록번호는 검증 숫자 규칙을 따르지 않으므로 검증에 실패해도 버리지 않는다 | 직접 쓴 검사 코드. Presidio는 한국어 낱말이 없고 그 수정안이 아직 검토 중이라 뺐다 |
| 이름, 주소, 기관 | 관계자 이름 목록과 대조하고, 탐지 모델이 찾은 자리를 표시한다. 내보낼지는 이 표시만 보고 정하지 않는다 | veil-pii-ko-lite. 대화와 상담, 양식 문장으로 학습하고 평가해 계약서나 판결문에서 얼마나 놓치는지 알려지지 않았으므로, 혼자 맡기지 않고 독립 검사 실행이 함께 읽는다 |
| 파일 속에 숨은 내용 | 수정 내역, 메모, 숨은 글자, 속성, 결과물에 넣은 파일을 꺼내 위 검사를 똑같이 돌린다 | 직접 쓴 검사 코드. 풀지 못하는 형식이 들어 있으면 내보내지 않는다 |
| 열 때 불러오는 주소 | 받는 쪽 프로그램이 읽는 방식대로 주소를 모두 찾아, 허용된 곳인지 창구에 묻는다 | 직접 쓴 검사 코드 |
| 남이 만든 자료와 겹치는 문장 | 조사와 어미, 어순만 바꾼 문장까지 찾는다. 비교 대상은 이번 업무에서 받아 실행 기록에 남은 자료다 | 직접 쓴 검사 코드 |

**모델 제공사로 가는 자료도 밖으로 나가는 자료다.** 그래서 업무 종류마다 기준 파일에 정한 '모델이 볼 필요 없는 개인정보'는 모델에 가기 전에 가린다. 받기 단계의 자료는 상주 프로그램이, 일하는 중에 읽는 자료는 PC MCP 서버가 가린다. 제출할 때 가리기 전 값이 필요하면 DBOS 단계 코드가 원래 값을 되넣는다.

**익명성 검사와 잡음은 사람마다 한 줄인 표나 사람 수를 센 통계를 밖에 내는 업무에만 건다.** 업무 종류의 기준 파일에 그런 결과물을 낸다고 표시한 업무다. 검사할 값 조합도 업무 종류마다 기준 파일에 정하고, 그 분야에 명단이나 통계가 새로 공개되면 다시 정한다.

| 검사 | 처음 값 | 걸리면 | 고른 것 |
|---|---|---|---|
| 같은 값 조합에 든 줄 수 | 5줄 이상 | 값을 넓은 구간으로 바꿔 다시 세고, 그래도 모자란 줄은 내보내지 않는다 | 직접 쓴 검사 코드 |
| 한 묶음 안 민감한 값의 가짓수 | 2가지 이상. 운영하는 쪽이 한 무리로 묶은 값은 한 가지로 센다 | 그 묶음을 내보내지 않는다 | 직접 쓴 검사 코드 |
| 한 묶음 안 값 분포가 전체 분포와 다른 정도 | 0.2 이하 | 그 묶음을 내보내지 않는다 | 직접 쓴 검사 코드 |
| 통계표 한 칸의 인원 | 10명 이상. 인원은 원본 자료에서 다시 센다 | 그 칸을 내보내지 않는다 | 직접 쓴 검사 코드 |
| 같은 자료로 여러 번 내는 통계 | 노출 한도 한 번에 0.5, 한 자료에 모두 2 | 계산된 잡음을 섞는다. 낼 때마다 쓴 노출 한도를 더해 2를 넘으면 더 내보내지 않는다 | OpenDP. 잡음과 한도 합산은 직접 짜면 틀리기 쉬워, 공개 검증을 거친 라이브러리를 쓴다 |

앞의 네 검사는 값 조합마다 묶어 세면 나오는 값이라 따로 도구를 두지 않는다. 처음 값은 업무 종류마다 운영하는 쪽이 바꾼다.

### 분리 실행

**한 실행이 닿는 자료를 PC 폴더, 사내 서버 DB, 권한 판정의 세 층에서 그 고객의 것으로 묶는다.**

**PC: 실행마다 그 고객의 폴더 밖을 읽지 못한다.**

▶️ 고객마다 PC에 폴더 하나를 두고, 그 안에 건마다 Git 저장소를 하나씩 둔다. 원격 저장소는 사내 서버에 둔다. 원본은 판단 근거 쪽에 암호문으로 있으므로 Git에 넣지 않는다.<br>
▶️ 한 PC가 여러 고객을 맡아도, 상주 프로그램은 실행마다 그 고객의 폴더를 작업 폴더로 띄우고 그 밖은 파일 도구와 셸 모두 읽지 못하게 막는다. 훅은 도구 호출마다 경로를 권한 판정 창구에 넣어 한 번 더 막고, PC MCP 서버는 파일을 열 때 업무 토큰의 고객과 폴더를 맞춘다.<br>
▶️ 고객 폴더 안의 원본 폴더는 실행이 읽지 못하고 PC MCP 서버만 연다.<br>
▶️ 바깥에서 온 파일은 PC MCP 서버가 네트워크를 끊은 격리 환경에서 연다.<br>
▶️ 셸 명령은 Claude Code의 샌드박스 안에서만 돌고, 바깥 연결이 없다. 샌드박스를 켤 수 없으면 실행을 시작하지 않고, 샌드박스에서 실패한 명령을 밖에서 다시 돌리지 못하게 한다. Windows에서는 샌드박스가 돌지 않으므로 PC는 macOS나 Linux를 쓴다.<br>
▶️ PC에서 도는 모델은 고객 자료로 더 학습시키지 않는다.

**하네스에서 끄는 기능**은 운영하는 쪽이 PC에 깔아 두는 관리 설정으로 걸어, 실행 안에서 다시 켜지 못하게 한다.

| 끄는 기능 | 끄는 까닭 | 대신하는 것 |
|---|---|---|
| 회사 밖으로 보내는 사용 통계와 오류 보고 | 회사 밖으로 나가는 길을 모델 호출 하나로 줄인다 | 사용량은 상주 프로그램이 실행 결과에서 센다 |
| 자동 업데이트 | 시험하지 않은 버전으로 바뀐다 | 운영하는 쪽이 시험한 버전으로 고정하고, 모든 PC를 같게 맞춘다 |
| 대화 기록 저장 | PC 디스크에 암호화 없이 남아, 키를 지워 내용을 없애는 약속을 지킬 수 없다 | 멈춘 일은 사내 서버의 기록을 넣은 새 실행으로 잇는다 |
| 자동 대화 압축 | 처음 넣은 조건과 원문이 요약으로 바뀐다 | 넣는 양은 상주 프로그램이 정한다 |
| 자동 기억 | 고객 정보가 고객 폴더 밖, PC 디스크의 하네스 기억 파일에 암호화 없이 쌓인다 | 기억은 서버 MCP 서버로만 읽고 쓴다 |
| 내장 웹 가져오기와 웹 검색 | 훅만 거치고, 업무 계정 권한으로 한 번 더 막을 수 없다 | 바깥 자료는 MCP 서버의 조회 도구로만 받는다 |

**사내 서버: 고객 번호는 업무 토큰에서만 꺼낸다.**

▶️ 서버 MCP 서버는 고객 번호를 요청 내용이 아니라 업무 토큰에서 꺼낸다. 모델이 다른 고객 번호를 적어 보내도 바뀌지 않는다.<br>
▶️ 기억, 진행 상태, 판단 근거, 검색 색인, 지식 그래프는 PostgreSQL의 행 수준 접근 제어로 고객을 가른다. 고객 번호가 정해지지 않은 요청은 빈 결과를 받는다.<br>
▶️ 서버 MCP 서버는 이 규칙을 건너뛰는 계정으로 붙지 않고, 표를 만든 계정에도 규칙을 건다. 고객 번호는 저장소에서 하는 작업 한 묶음 안에서만 두어, 다음 요청이 앞 고객의 번호를 이어받지 않게 한다.<br>
▶️ 한 고객 회사 안에서도 인사팀, 감사팀처럼 볼 수 있는 사람이 다른 자료는 같은 규칙에 부서 칸을 더해 나눈다.<br>
▶️ 자료를 넣을 때 서버 MCP 서버가 나오는 사람과 회사를 뽑아 관계자 목록과 맞추고, 조각마다 어느 고객의 정보가 들어 있는지 표시한다. 권한 판정 창구는 이 표시로 이번 일에서 볼 수 없는 조각을 거른다.<br>
▶️ 법령 원문처럼 모든 고객이 함께 쓰는 공통 지식은 읽기만 한다.<br>
▶️ 업무 DB 백업은 DB를 통째로 뜨므로 고객마다 나뉘지 않는다. 그 안의 판단 근거와 개인정보는 암호문이고, 백업을 되살리는 일은 운영하는 쪽만 한다.
