# 단독 순서도 — 분기·복귀·완료 조건 재검토

[수정한 순서도](../../images/expert-definition/solo-material-relations.png) · [편집용 원본](../../도식/usage-structure-solo.mmd) · [검증 기록](solo-final-review-2026-09-23.json)

사용자가 지적한 구간뿐 아니라 전체 노드의 설명과 나가는 경로를 대조했다. 검사 후 무조건 다음 단계로 넘어가던 곳, 미확인을 성공처럼 처리하던 곳, 기다리는 대상과 종료 조건이 빠진 곳을 수정했다.

- 위험을 발견한 경우와 발견하지 못한 경우의 정리 내용을 나눴다. 진행 여부는 필요한 정보가 충분한지와 규칙·허용 한도 안에서 가능한 방법이 있는지로 판단한다.
- 반려 대상은 원래 요청한 담당자다. 도구 결과는 작업 번호로 다시 조회한다. 도착한 결과는 보고 주체·요청 대상·버전부터 재검사하고, 확보 불가·기한 초과는 보류로 끝난다.
- 반대 근거 확인은 엇갈림 발견·미발견·근거 부족으로 나뉜다. 절차 평가는 준수·위반·미확인으로 나뉘며, 시정 방법을 확인하지 못한 작업은 보류한다.
- 검사 결과의 충족·틀림·미확인과 대기 결과를 구분했다. 여러 조건이 바뀌었으면 영향을 받는 가장 앞 단계부터 다시 확인한다.
- 전달 위험의 보완·허용 불가·판단 불가, 재전달 가능 여부와 한도, 인수 거절·내용 수정·응답 없음·인수 확인을 분리했다.
- 인수 후 기록과 과정 평가는 가운데 주 흐름으로 옮겼다. 뒤늦게 발견한 문제는 시정으로 돌아가며, 평가가 끝나지 않으면 마감을 보류한다.
- 후속 효과 확인은 방법·시점 미정과 등록 실패를 구분한다. 나중의 측정에서도 근거 부족·측정 불가·추가 조치를 따로 처리한다.
- 지적 밖의 요청 답변 미수신, 장애 복구·처리 상태 미확인, 개선 적용 실패·복구 실패 경로도 추가했다. 복구한 개선안을 ‘적용하지 않았다’고 기록하던 설명을 바로잡았다.
- 작업 종류와 세부 작업의 질문을 구분하고 20개 세부 분기에 답을 붙였다. 작업 진행·기록·실행 제어는 세로로 정렬했다.

## 검증 결과

원문 재료 79개를 유지했다. 단독 상황에서 78개를 사용하고 ‘나눠 맡기기’는 미사용으로 표시한다. 원문 정의 부분의 해시도 변하지 않았다.

273개 도형과 345개 연결을 검사했다. 실행 경로 98개, 필수 확인 지점 30개, 명시적 결과 분기 21곳, 반복 행 정렬 32개가 통과했다. 진행선 309개는 아래에서 나가 위로 들어가며, 복귀선 30개는 옆면끼리 연결한다. 편집용 Mermaid의 실행 연결 339개가 정본과 일치하고 문법 검사를 통과했다.

실제 브라우저에서 전구간의 도형·문구·제목 띠·연결선 좌표를 검사했다. 관통·겹침·글자 넘침·잘못된 연결 방향은 0건이다. 연결되지 않는 교차 33곳은 선 넘김으로 표시한다. 수정 구간은 문서 표시 폭 1100px의 이미지로 직접 확인했다. 같은 목적지의 복귀선은 공통 경로로 합쳤다.

이 검사는 현재 도식에 표현한 조건과 경로를 대상으로 한다. 모든 현실 업무의 예외를 다 담았다는 뜻은 아니다. 이전 교정 이력은 검증 JSON의 revision 항목에 보존했다.

## 재현

```sh
python3 docs/도식/단독-재료-연결구조.py
PLAYWRIGHT_MODULE=/opt/homebrew/lib/node_modules/playwright node docs/도식/단독-재료-연결구조-렌더.cjs /tmp/solo-review
python3 docs/도식/단독-재료-연결구조-검증.py /tmp/solo-review --report /tmp/solo-review/check.json
python3 docs/도식/단독-재료-연결구조-Mermaid-생성.py --embed
```

분기 보완은 `단독-재료-분기교정.py`, 배치와 경로 계산은 `단독-재료-배치교정.py`에서 수행한다. 놓을 곳이 없는 연결 문구가 있으면 생성에 실패한다. 검증한 전체 PNG와 확대 미리보기를 본문 게시 파일에 반영했다.
