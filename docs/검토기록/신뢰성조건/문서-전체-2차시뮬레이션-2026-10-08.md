# 전문 판단의 신뢰성 — 2차 시뮬레이션과 비난(문서 전체)

대상은 `전문 판단의 신뢰성.md` 전체다. 1차에서 고친 조건 표가 아래쪽 절과 이어지는지, 고친 뒤에도 믿을 수 없는 판단이 남는지를 봤다.

## 돌린 관점

| 관점 | 따라간 것 |
|---|---|
| 의료·보험·금융·공공·교육 시뮬레이션 | 정신건강 위기, 피부 판독, 대출 심사, 손해사정, 긴급복지, 서술형 채점, 감염병 신고 |
| 법률·노무·세무·회계 재시뮬레이션 | 대여금 준비서면, 상담만 한 근로자와 회사, 괴롭힘 조사 담당자가 행위자, 성실신고확인, 공동 임금체불 사건 |
| 조건에서 구현까지 추적 | 조건 표 70개 단위를 잘못, 원인, 갖춰야 할 조건, 재료, 기록, 수식, 사용 구조까지 따라감 |
| 기술 사실 검증 | Docling, OpenSearch, Qwen3, PostgreSQL, LightRAG, Jev, OPA, Pydantic, Decimal, SKOS |
| 공격자와 꾀부리는 에이전트 | 기록 고치기, 충돌 확인 악용, 폴더 넘나들기, 결과물 링크로 새기, 숨긴 글, 쪼개기, 승인 창 속이기, 인용 문맥 왜곡, 기억 오염 |
| 검토자와 만드는 AI | 긴 행, 겹치는 절, 두 AI가 다르게 만들 자리, 순서도와 본문 차이 |
| 돈 낸 고객과 운영자 | 표시가 너무 많음, 과한 재판단, 쏠림 확인의 단위, 자격 업무가 늦게 드러남 |

## 고친 것

| 묶음 | 고친 곳 |
|---|---|
| 이해 충돌 확인이 고객별 조회 제한에 막힘 | 고객 행, 갖춰야 할 조건, 기록, 권한 표에 이름과 건 이름만 담은 명부와 쟁점별 결론 목록을 둠 |
| 기억 오염과 다른 고객 값 사용 | 기억에 어느 건에서 왔는지 남기고, 원문으로 다시 확인한 방법과 공개 사실만 다른 업무에 씀 |
| 실행 기록과 앞 단계 기록을 에이전트가 고칠 수 있음 | 실행 기록은 에이전트 밖, 덧붙이기만, 작업 폴더 밖에 둠 |
| 보고 대조가 한쪽만 봄 | 처리 건수와 확인 범위를 실행 기록에서 뽑고, 기록에 남은 변경이 보고에 다 있는지도 대조함 |
| 숨긴 글을 찾는 재료가 없음 | Docling 절에 쪽을 그림으로 그려 견주는 코드로 따로 뽑게 함 |
| 결과물 링크로 자료가 새는 길 | 권한 검사를 결과물을 내보내기 전에도 하고, 링크와 그림 주소를 밖으로 보내는 행동으로 검사함 |
| 행동 쪼개기로 한도 피하기 | 한도는 같은 대상과 목적으로 이미 실행한 몫을 합쳐 잼 |
| 승인 창을 에이전트가 씀 | 실행 프로그램이 미리 돌려 본 실제 대상과 값을 따로 보여 주고, 바뀌면 다시 결정받음 |
| 인용은 맞는데 문맥이 틀림 | 누구의 말인지와 뒤의 단서를 확인하고, 규칙 문장은 원문 그대로 인용함 |
| 별도 검토가 같은 모델이나 고른 사실에 기댐 | 검토용 다른 모델을 재료에 넣고, 찾은 자료 전체를 주고, 다른 모델이 없으면 그렇게 밝힘 |
| 시험과 품질 기준을 만드는 쪽이 정하거나 고침 | 결과를 만들지 않는 쪽이 정하고, 만드는 쪽에는 읽기만 허용함 |
| 주장 결과물과 공정 업무의 경계 | 공정 업무를 남이 믿고 쓰도록 확인하거나 평가하는 일로 정하고, 주장 결과물의 예를 바꿈. 고객 진술은 주장의 근거로 씀 |
| 맡긴 담당자가 당사자 | 조직 안 그 위의 결정권자에게 넘김 |
| 비밀 예외 | 자기 방어를 더함 |
| 여러 고객에게 같은 판단을 함께 적용 | 미리 알린 기준으로 나눔 |
| 공동 의뢰에서 이해가 갈림 | 할 수 있는 방법을 알리고 답을 받아 운영하는 쪽 책임자가 정함 |
| 치우친 시험 자료 | 확인된 업무 범위를 업무 종류와 대상으로 정함 |
| 자격 업무가 늦게 드러남 | 맡을 때 가려 알리고, 넘길 곳이 없으면 결론을 내지 않은 부분으로 남김 |
| 급한 일 | 찾은 만큼으로 판단하고 다시 볼 때를 적음 |
| 생명이 걸린 기다림 | 답할 사람과 답이 없을 때 할 조치를 미리 허락받음 |
| 형식적인 사람 재검토 | 결론을 바꿀 권한이 있는 사람이 직접 본 것만 셈 |
| 표시가 너무 많아 다시 검토하게 됨 | 결과물 맨 앞에 그대로 쓸 결론과 확인할 것을 나눠 적음 |
| 과한 재판단과 재확인 | 다른 모델 재판단의 대상을 위험 범위로 정하고, 뺀 자료 재판단과 한 번에 하며, 틀린 곳의 재확인은 같은 원인을 쓴 부분으로 좁힘 |
| 쏠림 확인의 시점과 방법 | 업무마다 모을 시점과 견줄 방법, 넘으면 안 되는 차이를 미리 정함 |
| 기록 표에 새 항목 칸이 없음 | 위험 범위, 업무 종류, 충돌 확인 결과, 동의, 확인 주체, 단단함, 기한, 모델과 기준 판본, 낸 곳을 넣고 보관 기간을 정함 |
| 수식이 정의 1 재료를 부르지 않음 | 장기 기억, 변경 감시, 법·의무 기준, 대안·전략 판단, 비용·위험 한도, 사람에게 넘기기, 대기·후속 관리, 업무 능력 시험을 넣음 |
| 순서도와 본문 | 미확정을 '판단이 서지 않음'으로 맞추고, 검토가 결과물 초안을 대조하게 노드 글을 바꿈 |
| 기술 사실 | Docling의 HWP 미지원, PostgreSQL 행별 접근 제어의 주인 계정 예외, OpenSearch 3.9, Pydantic strict 모드, Decimal 끝수, 재귀 조회 멈춤 |
