# 전문 판단의 신뢰성 — 4차 시뮬레이션과 비난(문서 전체)

3차에서 넣은 장치를 겨냥해 네 관점(섞인 직종 사례 여덟, 공격자와 나쁜 운영자, 일관성과 기술 사실, 법과 직업윤리)으로 봤다.

## 고친 것

| 묶음 | 고친 곳 |
|---|---|
| 다시 판단할 대상을 만든 쪽이 피해를 작게 재서 피함 | 피해는 실행 제어가 그 판단을 쓰는 대상 전체로 재고, 잴 수 없거나 검토 모델이 대상이라 보면 대상 |
| 미리 허락한 한도 안의 되돌릴 수 없는 행동까지 모두 재판단 | 한도 밖의 되돌릴 수 없는 행동만 대상 |
| 골라 대조와 모든 결과물 대조가 부딪힘 | 코드 대조는 모든 건, 다른 모델의 품질 대조만 골라 함, 골라 본 건이 통과하면 묶음 통과 |
| 명부에서 충돌이 나온 뒤 누가 정하는지 없음 | 책임자가 판정과 동의 절차를 맡고, 실행 제어는 그 판정이 있어야 시작하게 함. 옛 이름, 다른 표기, 지배 관계 회사로도 조회 |
| 업무 종류를 에이전트가 고름, 기본값을 느슨하게 정함 | 업무 종류는 맡긴 사람이 확인, 걸치면 엄한 쪽. 기본값은 법과 직업 기준보다 느슨하지 않게, 쓴 값과 그 때문에 빠지는 확인을 알림 |
| 다른 회사 모델이 같은 버릇을 물려받음 | 남의 모델을 고친 것과 주 모델의 답으로 학습한 모델은 다른 모델로 세지 않음 |
| 맨 앞 결론의 기준 | 기한 때문에 못 찾은 곳, 단단함이 한쪽으로 모이지 않은 해석은 올리지 않음 |
| 재판단 물음에 바라는 결론이 넘어감 | 쟁점과 바라는 결론을 나눠 적고, 재판단 모델이 반대 자료를 따로 찾음. 주장 결과물은 결론을 두고 받치는 사실과 계산만 재판단 |
| 평가받는 쪽 자료의 항목 뽑기가 지시를 그대로 넘김 | 숫자, 날짜, 선택지로 뽑고 원문 위치를 코드로 맞춤. 글 항목에 기댄 결론은 재판단 |
| 숨긴 글 검사가 글꼴 바꿔치기와 그림 줄이기를 놓침 | OCR과 파일 글을 견주고, 줄인 그림도 읽음. 숨긴 글과 메타데이터는 문서에 관한 사실로 쓸 수 있음 |
| 모델이 쓴 글에 섞인 비공개 값 | 그런 자료를 본 모델의 글은 섞인 것으로 보고 맡긴 사람이 정함 |
| 변경 대조의 범위 | 쓸 수 있는 모든 곳, 건마다 계정, 기록이 없으면 전후 상태, 그것도 못 하면 되돌릴 수 없는 행동 |
| 대상 목록의 조건, 범위 표현 | 조건은 맡긴 사람이 확인, 범위 문장에는 'N건 중 M건' |
| 미리 허락한 글의 내용 | 정해 둔 서식의 칸만 채운 경우만 미리 허락 |
| 비밀 유지의 대상과 예외 | 고객이 아닌 사람의 비밀도 지킴, 곧 생기거나 뚜렷한 위협, 미리 등록한 공식 연락처, 거부할 권리, 법이 먼저 정한 신고 |
| 공정해야 하는 일, 상담만 한 사람, 조직 담당자 | 행정 처분과 민원 결정을 넣음, 일을 맡기려고 상담한 사람으로 좁힘, 법 위반을 바로잡지 않으면 윗선으로 |
| 대외 결과물에 꼭 남길 기재 | 서식과 법이 요구한 기재와 생성형 AI 표시는 결과물에 남김 |
| 기록과 명부의 보관 | 실행 기록은 실행 제어만 씀, 명부는 확인 의무가 남는 동안 보관, 삭제 요구 처리, 감시 목록의 끝 |
| 시험 범위 | 적용하는 나라의 법과 자료의 언어도 넣고, 확인 대상 여부는 가리기 전 자료로 |
| 기술 사실 | Claude Code 격리는 셸에만 걸리므로 파일 도구는 권한 규칙으로 막음, 실행 기록은 PostToolUse 훅으로 남김 |
| 기한 계산 | 법이나 계약이 가리키는 곳의 휴일과 시간대 |
| 말 | '다시 판단할 조건'을 '결론을 다시 볼 조건'으로 나눔, 오탈자 |
| 수식 | 업무별 정보, 조직 규칙, 플랫폼·제출처 규정, 사람과 소통, 항목 뽑는 모델을 넣음 |
