# 전문 판단의 신뢰성 — 5차 시뮬레이션과 비난(마무리 판정)

기준을 좁혔다. 현실에서 흔하고, 문서를 글자대로 따라도 막히지 않으며, 믿고 진행하면 손해가 나는 것만 냈다. 세 관점(흔한 업무 열 가지, 흔한 공격과 사용자가 걱정한 여덟 가지, 모순과 사실과 읽힘)으로 봤다.

## 고친 것

| 묶음 | 고친 곳 |
|---|---|
| 조건 표가 '무엇'과 '어떻게'를 섞어 너무 김 | 조건 표에는 지킬 것만 남기고, 방법은 갖춰야 할 조건과 재료 설명으로 옮김 |
| Word 변경 추적의 옮긴 글과 표 속 글을 Docling이 빠뜨림 | 변경을 따로 뽑아 알리고 받아들인 판으로 읽음. 화면엔 보이는데 추출에서 빠진 글은 OCR 글로 넘김 |
| 내보내는 파일에 메모와 변경 기록이 남음 | 최종 파일의 변경 추적, 메모, 문서 속성, 숨긴 글을 지운 뒤 내보냄 |
| 평가받는 쪽 자료의 정해 둔 항목 밖 내용을 아무도 못 봄 | 특약, 예외, 부속 합의를 원문 그대로 뽑는 칸을 늘 둠 |
| 앞일 예상의 맨 앞 기준과 단단함 | 예상 범위 어느 끝이어도 처리 방향이 같을 때만 맨 앞. '한쪽으로 모임'은 반대 근거마다 까닭을 적을 때만 |
| 응대 답장이 모두 사람에게 감 | 정해 둔 주제 안의 답은 별도 모델이 약속과 금액을 뽑아 실행 제어가 맞춰 본 뒤 미리 허락으로 처리 |
| 건마다 계정을 줄 수 없는 곳 | 한 번에 한 건만 실행해 변경 기록을 가림 |
| 위험을 말한 사람 본인에게 줄 조치 | 109 같은 도움 연락처를 바로 알림 |
| 실행 기록 훅의 기술 사실 | Claude Code는 PostToolUse와 PostToolUseFailure, Codex는 훅이 걸리지 않는 내장 도구를 끔. 격리 밖의 MCP 서버도 막음 |
| 허용 주소로 남의 계정에 보내기 | 받는 계정은 실행 제어가 넣은 자격 증명으로만, 웹 열기는 받은 주소만 |
| '확인'과 '없다'가 실행 기록에 묶이지 않음 | 읽거나 조회한 실행 기록 항목에 잇고, 실패한 조회에 기댄 것은 미확인 |
| 조사 깊이 | 찾을 곳마다 정해 둔 깊이까지 |
| 시험 정답을 시험받는 쪽이 읽음 | 정답과 채점 코드는 읽지도 못함 |
| 쟁점별 결론 목록의 결론 칸에 고객 값 | 결론도 일반 문장으로 |
| 동명이인을 같은 대상으로 이음 | 이름 말고 식별값 하나 이상이 맞아야 같은 대상 |
| 골라 대조할 건을 앞에서부터 고름 | 묶음이 다 나온 뒤 무작위 |
| 남의 글을 출처 없이 옮겨 실음 | 한 문장 이상 겹치면 출처를 붙이고, 사용 조건이 막으면 내보내지 않음 |
| 가릴 내용과 주장 결과물이 부딪힘 | 지시와 금지 특성은 늘 가리고, 바라는 결론은 재판단에서만 뺌 |
| 고객이 아닌 사람의 비밀을 이번 업무 결과물에도 못 씀 | 결과물을 맡긴 사람과 받는 기관에 내는 데 필요한 만큼은 씀 |
| 숨긴 글을 다루는 말이 세 곳에서 다름 | 모두 모델에 넘기지 않고 사실과 위치만 넘김 |
| 재판단 대상 정의가 세 곳에서 다름 | 검증 행 한 곳에 모으고 평가받는 쪽 글에 기댄 판단을 넣음 |
| 피해를 재는 법이 한 곳에만 있음 | 갖춰야 할 조건의 질문과 범위 행으로 옮겨 모든 기준이 같이 씀 |
| 갈렸다가 맞춘 결론, 충돌 없는 건의 판정 대기, 반박만으로 결론 바꾸기 | 각각 맨 앞에 올릴 수 있게, 충돌이 나온 건만 기다리게, 바꾸지 않게 고침 |
| 수식 | 예측, 결과물 만들기·수정, 사용자 지정 규칙을 넣음 |

## 판정

세 관점 가운데 하나는 새로 더할 조건이나 재료가 없다고 판정했다. 나머지 둘은 위 구멍을 막으면 사용자가 걱정한 여덟 가지가 모두 막힌다고 판정했다.
