1. **사실**: 제품·기능·버전·표준·법령·숫자가 실제와 맞나. 오늘은 2026-09-30이고 네 기억보다 최신 제품(예: Claude Opus 5.5, GPT-6 Astra, MiMo-V2.6-Pro, Qwen3.8-Flash-Next 등)이 있을 수 있다. **기억으로 고치지 말고 웹에서 공식 문서를 열어 확인**한다. 확인 못 하면 고치지 말고 기록에 "미확인"으로 남긴다.
2. **전문가 실무**: 그 재료가 다루는 일을 실제 전문가(변호사·회계사·세무사·운영 엔지니어·보안 담당 등)가 보면 틀린 규칙·위험한 기본값·빠진 예외가 있나. 법률 내용은 law.go.kr 원문으로 확인.
3. **설계 건전성**: 이대로 만들면 돌아가나. 우회 경로(예: 훅만 믿으면 셸로 우회), 경쟁 상태, 두 번 실행, 실패 시 멈춤 없음, 불가능한 기본값, 기술이 실제로 그 기능을 공식 지원하는지.
4. **일관성**: 맡은 구간 안에서, 그리고 다른 재료·정의 1과 같은 대상·숫자·이름·기본값을 다르게 말하는 곳(재시도 횟수, 결과 불명 조회 간격, 판정 값, 보관 기간, 부품 이름 등). 다른 구간은 읽어서 대조만 하고 고치지 않는다(그 구간 일꾼이 따로 있다) — 어긋남은 기록에 적는다.
5. **뜻이 바뀐 곳**: 직전 커밋 4420e4f("문장 단위로 다시 씀, 뜻은 그대로")가 실제로 뜻·설계·숫자를 바꾸거나 내용을 잃은 곳을 찾는다. `git show 4420e4f^:"전문가 에이전트 정의 2.md"` 와 현재 파일의 맡은 구간을 견준다. 바뀐 쪽이 더 맞으면 두고 기록만, 틀리거나 잃었으면 되살린다.
6. **검토자 눈**: 판정에 필요한데 빠진 것, 읽어도 뜻을 모를 낱말.

- 맡은 구간 안만 고친다. 여러 일꾼이 같은 파일을 동시에 고친다. **행 단위 Edit만** 쓰고, 편집 직전에 그 부분을 다시 읽는다. 절 통째 교체·파일 통째 쓰기·`git checkout`·`git show HEAD:… >` 금지.
- 문체는 지금 문서와 같게: 한 문장에 한 가지, 서술 문장, 쉬운 한국어, 표 모양 유지. 출처 URL·확인 날짜·"이번에 고쳤다" 같은 작업 이력, 로컬 파일 링크·내부 링크는 문서에 넣지 않는다. 근거는 검토 기록 파일에만.
- 그림(PNG)·mermaid 도형 배치는 고치지 않는다(글과 어긋나면 보고만). 순서도 노드 글자는 고쳐도 된다.
- 커밋·푸시하지 않는다.
- 🟢(취향·사소)는 기록만.
