### R1. SeaweedFS 마스터 서버 HTTP와 볼륨 서버 HTTP로 잠긴 원본을 통째로 지울 수 있음

- 위치: 자료가 사는 자리 글머리 "Object Lock은 S3 접속으로 들어온 요청에만 걸린다 … SeaweedFS의 파일 서버나 관리 명령으로 원본을 바로 지우는 길은 막는다. 파일 서버의 HTTP 접속은 끈다. SeaweedFS 부품끼리 쓰는 내부 통신은 서로 인증서를 확인하게 잠그고", 평가와 운영 합격 기준 다섯째 줄.
- 무엇이 틀렸나: 막은 길은 파일 서버(필러) HTTP와 gRPC 관리 명령뿐이었음. SeaweedFS 마스터 서버의 HTTP에는 `/col/delete?collection=<이름>`이 있고, 컬렉션 하나의 볼륨을 통째로 지움. S3 칸 하나는 컬렉션 하나에 담기므로("Each bucket is stored in one collection … A bucket can be deleted efficiently by deleting the whole collection"), 이 요청 하나로 Object Lock(규정 준수 모드 포함)을 거치지 않고 고객 저장 칸·보존 칸·공개 원본 칸의 원본이 모두 사라짐. 이 경로를 막는 것은 `guard.white_list`(IP 목록)뿐이고 기본값은 비어 있어 아무나 부를 수 있음. 볼륨 서버 HTTP의 DELETE도 같은 IP 목록과 쓰기 JWT로만 막힘. 문서대로 만들면 법정 보존 자료까지 운영자가 지울 수 있고, 합격 기준 시험은 이 길을 보지 않아 거짓 통과함. 파일 서버의 목록 저장소(필러 메타데이터)를 고쳐도 S3에서 원본이 사라짐.
- 근거:

### R2. ① 개선 판본이 시험 통과 기록과 사람 승인 없이 실제 고객 건에 나감

- 위치: 능력 개선·확장 환경별 정답 "판본과 되돌리기", "10건에만 쓰기".
- 무엇이 틀렸나: 같은 재료의 관문 표와 순서도는 목적·권한·안전장치·규칙·평가 기준·시험 문항·채점 코드·업무 지식의 개념·관계·사실 주장을 건드리는 개선은 사람이 승인해야 10건에 쓴다고 정함. 수단 고르기 1도 "시험 통과 기록이 없는 판본은 기계가 막아 실제 업무에 나가지 못하게" 하라고 함. 그런데 ① 정답은 병합 때만 기계로 막고, 승인 대상도 시험지·정답·채점 코드·병합 검사 설정 넷뿐이었음. 10건 시험은 병합 전 브랜치로 실제 건을 여는 방식이라, 권한이나 안전장치 규칙을 바꾼 브랜치가 시험 기록도 승인도 없이 실제 고객 건 10개에 쓰일 수 있었음. ②·③도 시험 통과 기록만 보고 승인 기록은 보지 않았음.
- 고친 것: ① 병합 승인 대상을 관문 표와 같은 목록으로 넓힘. ① 실행 프로그램은 시험 통과 기록과, 필요하면 승인 기록이 있는 브랜치로만 건을 열고, 없으면 옛 판본으로 엶. ②·③은 승인 기록이 없는 묶음을 배포하지 않고, 사내 플랫폼은 배포된 묶음에서만 판본을 고름.

### R3. 끝난 건의 ① 대화 원본이 30일 뒤에도 지워지지 않음

- 근거: Claude Code 공식 문서 "Cleaned up automatically" — 정리 대상 목록, "Claude Code skips the age-based sweep in these cases: Bare mode … doesn't run the sweep in that session", 정리를 Claude Code 세션이 함. https://code.claude.com/docs/en/claude-directory , https://code.claude.com/docs/en/data-usage . 개인정보 보호법 제21조(법률, 시행 2026-09-11, 법제처 API `MST=283839`).

### R4. 계약 없는 사람의 개인정보를 처리방침 공개만으로 국외 이전함

- 위치: 보관 기간과 지우기 "모델 회사의 서버로 보내는 것은 개인정보의 국외 이전이므로, 다음 일곱 가지를 개인정보 처리방침에 적는다."
- 무엇이 틀렸나: 처리방침 공개만으로 동의 없이 국외로 옮길 수 있는 근거는 제28조의8 제1항 제3호 가목뿐이고, 이 호는 "정보주체와의 계약의 체결 및 이행을 위하여" 필요한 처리위탁·보관에만 걸림. 보호위원회는 이를 제15조 제1항 제4호와 같은 기준(정보주체와 맺은 계약)으로 설명함. 앞 검토가 삭제 요구를 "자료에 나오는 다른 사람"에게까지 넓혔듯이, 건의 자료에는 상대방·증인처럼 우리나 맡긴 쪽과 계약이 없는 사람의 개인정보가 늘 들어 있음. 이들에게는 제3호가 걸리지 않으므로 별도 동의(제1호), 인증(제4호), 동등성 인정(제5호) 없이 ①의 모델 회사로 보내면 제28조의8 제1항 위반임. 계약 없는 사람에게도 제3호가 걸린다는 공식 해석은 찾지 못함. 해석이 갈리는 곳이라 공통지시대로 더 안전한 쪽으로 정함.
- 근거: 개인정보 보호법 제28조의8 제1항·제2항 원문(법제처 API `MST=283839`, 시행 2026-09-11). 보호위원회 국외이전 제도 안내 https://www.pipc.go.kr/np/default/page.do?mCode=D060040010 , https://www.privacy.go.kr/front/contents/cntntsView.do?contsNo=367
- 고친 것: 동의 없이 옮길 수 있는 것은 그 정보의 주인이 우리나 처리를 맡긴 쪽과 맺은 계약을 이행하는 데 필요할 때뿐이라고 정함. 그런 계약 없이 자료에 나오기만 하는 사람의 개인정보는 일곱 가지를 알리고 국외 이전 동의를 따로 받았을 때만 ①의 모델에 넘기고, 없으면 그 건을 ②·③으로 넘김. ②·③은 사내 서버의 모델을 쓰므로 국외 이전이 생기지 않음(정의 1 AI 모델 환경 표).

### R5. 수탁자로서 모델 회사에 다시 맡길 때 맡긴 쪽의 동의가 없음

- 위치: R4와 같은 문단.
- 무엇이 틀렸나: 법·의무 기준(1648행)은 우리가 남의 개인정보 처리를 맡은 수탁자인 경우를 다룸. 그때 ①에서 건의 자료를 모델 회사 서버로 보내는 것은 맡은 처리를 제3자에게 다시 맡기는 일이고, 제26조 제6항은 "위탁자의 동의를 받아야 한다"고 정함. 정의 2 어디에도 이 동의가 없음("재위탁", "다시 위탁" 0건). 업무 권한의 "받은 권한을 바깥 업체나 다른 회사의 AI에 다시 맡긴다" 행은 권한을 넘기는 일을 다루고, 에이전트가 늘 쓰는 ① 모델 자체는 대상으로 읽히지 않음.
- 근거: 개인정보 보호법 제26조 제6항·제8항 원문(같은 판).
- 고친 것: "우리가 고객의 개인정보 처리를 맡은 쪽이면, 모델 회사로 보내는 것은 그 처리를 다시 맡기는 일이다. 그래서 맡을 때 맺는 계약서로 맡긴 쪽의 동의를 먼저 받는다."를 더함.
