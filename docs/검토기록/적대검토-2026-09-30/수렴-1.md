### R1. 분리 실행 「①의 규칙」 — 관리 설정으로 '늘 샌드박스 밖에서 도는 명령 목록'을 잠글 수 있다고 적음 (공식 지원 없음 → 검사 우회 길)
- 전: "막는다. 그 목록은 비워 둔다. 샌드박스 설정은 관리 설정으로 고정해 프로젝트 설정이 넓히지 못하게 한다"(앞 검토 최종-환경 Y4가 넣은 문장).
- 무엇이 틀렸나: Claude Code는 켜기·끄기 같은 값만 관리 설정 값으로 고정한다. `excludedCommands` 같은 목록 설정은 모든 설정 층의 항목을 합치고, 이 목록을 관리 설정만 따르게 잠그는 장치는 없다. 그래서 이번 건 폴더에 든 `.claude/settings.json`(고객이 준 파일 묶음에 들어올 수 있음)이나 개인 설정에 명령 하나만 적혀도 그 명령은 샌드박스 밖에서 돈다. 샌드박스 밖 명령은 읽기 제한과 네트워크 허용 목록을 받지 않으므로 고객 자료를 밖으로 보낼 길이 생긴다.
- 근거: https://code.claude.com/docs/en/sandboxing "For boolean keys such as `enabled` and `failIfUnavailable`, Claude Code uses the managed value … For array keys such as `excludedCommands` and `allowRead`, Claude Code merges entries from every scope", "`excludedCommands` has no equivalent managed-only lockdown, so a developer can always append entries that run additional commands outside the sandbox". 막을 공식 수단: https://code.claude.com/docs/en/cli-reference `--setting-sources` "Comma-separated list of setting sources to load (`user`, `project`, `local`)". 실행 중인 명령이 설정 파일을 고치는 길은 샌드박스의 보호 경로가 막음(같은 sandboxing 문서 Protected paths).
- 고친 것: "켜고 끄는 샌드박스 설정은 관리 설정으로 고정한다. 그 목록처럼 여러 값을 담는 설정은 관리 설정으로 잠기지 않고, 모든 설정 층의 값이 합쳐진다. 그래서 하네스를 감싼 실행 프로그램이 이번 건 폴더에 든 프로젝트 설정을 읽지 않게 하네스를 띄우고, 그 운영체제 사용자의 개인 설정 파일은 그 프로그램이 건마다 새로 쓴다."
- 같은 뿌리(정의 1 「공통 기준을 만드는 방법」 환경별 차이 ①): "샌드박스 밖에서 다시 돌리는 길은 끈다"는 다시 돌리기만 끄고 목록 길을 남김 → "샌드박스 밖에서 명령을 돌리는 길은 모두 끈다". 1~1100행은 손대지 않음.

### R2. 업무 도구·시스템 「환경별 정답」 화면만 있을 때 — 모델이 쓰기 되는 계정으로 로그인한 브라우저를 직접 다룸 (연결부 검사 우회, 승인 없는 제출)
- 전(①): "브라우저는 그 건에 허락된 계정으로만 로그인한 빈 상태에서 시작한다"(앞 검토 정의2-환경 R2가 넣은 문장). ②·③: "Playwright를 격리 컨테이너에서 돌린다".
- 무엇이 틀렸나: Playwright는 MCP 서버로 하네스에 붙고, 모델이 클릭·입력을 직접 보낸다. ①에서 이 길에는 연결부가 없고 훅은 돕기만 한다. 화면으로만 내는 곳(전자 제출 창구, 웹 결제 화면 등)에서 그 건 계정이 쓰기를 할 수 있으면, 모델이 제출 버튼을 누르는 순간 최신 권한·승인·한도·첨부 검사 없이 되돌릴 수 없는 행동이 나간다. 같은 절의 "①에서 발송, 제출, 기록 쓰기를 한다 | 전용 도구로만 한다", "①의 셸과 브라우저 | 같은 로그인 세션으로 이 검사를 건너뛰지 못하게 막는다", 안전장치 「검사 수단 고르기」 1 "검사를 피해 가는 길을 막을 수 없는 도구에는, 그 검사를 거쳐야 쓸 수 있는 권한을 주지 않는다"와 정면으로 어긋나는데, 정답 칸이 그 길을 만든다.
- 고친 것(①): "로그인 상태도 열쇠다. 모델이 직접 다루는 브라우저는 로그인하지 않은 빈 상태나, 그 건에 허락된 계정 가운데 읽기만 되는 계정으로 로그인한 빈 상태에서 시작한다. 쓰기가 되는 계정이 필요한 화면 일은 직종이 화면마다 미리 짜 두고 시험한 조작 순서로 한다. 그 순서는 연결부가 돌린다. 연결부는 최신 권한을 확인하고, 쓰는 일이면 승인, 한도와 첨부 본문까지 확인한 뒤에 돌린다. 모델은 채울 값만 넘긴다." ②·③: "로그인 상태와 쓰기가 되는 계정이 필요한 화면 일은 ①과 같이 다룬다." 셸 CLI에 읽기 열쇠만 주는 같은 칸의 규칙, 실행 제어의 "답이 하나로 정해진 걸음은 코드가 맡는다"와 맞음.
- 구간 밖 같은 뿌리(보고만): 결과 품질 평가 ① "웹 화면은 … Playwright로 연다. 브라우저는 그 건에 허락된 계정으로만 로그인한 빈 상태에서 시작한다"(4624행 근처). 결과물을 열어 보는 일에도 쓰기 되는 계정이면 같은 길이 열린다. 같은 규칙(읽기만 되는 계정 또는 연결부가 돌리는 조작 순서)으로 맞춰야 함.
