2. "허용된 자료와 방법을 사용한다" — 기존 카드 그림 그대로.
3. "고객의 자료와 이익을 지킨다" — 새 카드. 전문가 앞에 색이 다른 두 고객 서류철이 칸막이로 나뉘어 따로 놓여 있고, 한쪽 서류철에 작은 자물쇠가 달려 있다. 두 서류철의 종이가 섞이지 않는 모습.
4. "사실을 확인한다" — 기존 카드 그림 그대로.
둘째 줄 왼쪽부터:
5. "전문 기준을 적용한다" — 기존 그림.
6. "반대 근거를 검토한다" — 기존 그림.
7. "대안과 영향을 비교한다" — 기존 그림.

9. "결론과 처리 방향을 정한다" — 기존 그림.

12. "상황이 바뀌면 판단을 갱신한다" — 기존 그림.
위 열두 제목을 글자 하나 빠짐없이 정확히 쓴다. 기존 열 제목은 표현을 바꾸지 않는다. 모든 조건을 갖추면 결과가 무조건 성공한다고 표현하지 않는다. 워터마크나 장식 구호 없음.

1. 제목: 질문을 잘못 이해한다
   설명: 회계연도 질문에 1월부터 12월까지 답한다
2. 제목: 대상을 혼동한다
   설명: 동명이인의 판결을 상대방 이력으로 쓴다
3. 제목: 종류나 단위를 잘못 정한다
   설명: 천 원 단위를 원으로 읽는다
4. 제목: 권한을 벗어난다
   설명: 다른 고객의 계약 단가를 가져다 쓴다
5. 제목: 시점이 맞지 않는 자료를 쓴다
   설명: 개정 전 세율이나 오래된 환율을 쓴다
6. 제목: 사실이 아닌 내용을 근거로 쓴다
   설명: 목표 매출을 실제 매출로 답한다
7. 제목: 기준의 우선순위를 잘못 정한다
   설명: 법에 어긋나는 사내 규정을 먼저 적용한다
8. 제목: 필요한 자료를 빠뜨린다
   설명: 본문만 읽고 해지를 제한하는 별첨을 놓친다
9. 제목: 사실이나 처리 결과를 잘못 연결한다
   설명: 2건만 처리됐는데 3건 모두 완료로 보고한다
10. 제목: 규칙을 잘못 적용하거나 계산을 틀린다
   설명: 예외에 해당하는데 원칙을 적용한다
11. 제목: 근거 없는 내용을 만들어 낸다
   설명: 원문의 ‘할 수 있다’를 ‘해야 한다’로 바꾼다
1번 말풍선은 정확히 “작년 매출은?”으로 쓴다. 달력은 4월~3월과 1월~12월을 대비한다.
2번은 동명이인 두 사람의 판결을 혼동하는 모습이다. 애플과 사과 농가를 사용하지 않는다.
7번은 법에 어긋나는 사내 규정을 먼저 고르는 모습이다. 외운 지식을 우선하는 사례로 바꾸지 않는다.
9번 실제 처리 결과는 “2건 완료”, “1건 오류” 두 줄이다. 잘못된 보고는 “3건 모두 완료”이다. 건수와 항목 번호를 혼동하지 않는다.
```

   구현 기술: 온톨로지와 지식 그래프

   구현 기술: Docling과 주 모델
3. 재료: 정보·자료 찾기 / 현재 값·상태 확인
   구현 기술: RAG, 원본 시스템 조회
4. 재료: 정보·자료 찾기
   구현 기술: GraphRAG
5. 재료: AI 모델
   구현 기술: 주 모델, 필요한 경우 Jev
6. 재료: 기준 적용·판정 / 결과 검증·재검증 / 반대 근거·다시 확인
   구현 기술: 주 모델과 별도 검토

   구현 기술: Python 계산 코드
8. 재료: 현재 진행 상태 / 판단 근거 기록
   구현 기술: 업무별 기록과 Pydantic

업무 기록이 내용을 보관하고 Pydantic은 형식을 검사한다. Pydantic이 진실을 판별하거나 기록을 저장하는 시스템처럼 그리지 않는다.
계산 카드에는 Decimal 표시를 넣을 수 있다.
그림 밑에 추가 구호나 요약 문구를 넣지 않는다.
```

2 "허용된 자료와 현재 값 확인"

4 "조건과 예외 대조"
5 "필요한 수치를 코드로 계산"

왼쪽 "설명만 맡음" / "결론과 근거 전달".
