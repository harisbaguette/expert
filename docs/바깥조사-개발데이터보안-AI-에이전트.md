# 바깥 조사 — 소프트웨어 개발·QA·데이터·AI/ML·인프라·정보보안 전문 AI 에이전트 (전 세계)

진행 계획 3단계 "바깥 조사 — 남이 만든 에이전트 비교" 의 **열한 번째 직종군**임 (법률·세무회계·지식재산·노무인사·금융보험·부동산건축·마케팅영업·경영운영·디자인미디어·언어 다음 차례). 확인일 2026-09-11. 확신도는 FACT(1차 자료 직접 확인 또는 독립 출처 3개) · LIKELY(출처 2개 또는 자체 발표만) · 미확인 으로 붙임.

> 이 분야는 **AI 에이전트가 가장 멀리 간 곳**임. 그래서 다른 편과 달리 "얼마나 사람 없이 끝내나" 를 숫자로 잴 수 있음. 다만 숫자가 두 갈래로 갈리므로 3절(제3자 증거)을 먼저 보는 게 빠름.

## 한 줄 결론

개발·보안은 **시험 점수는 이미 사람을 넘었는데, 현장 성적은 아직 안 넘었음**. 시험(SWE-bench Verified) 은 96%까지 올라가 사실상 만점이고, 미국 국방부 대회(DARPA AIxCC)에서는 AI 시스템이 5,400만 줄짜리 코드에서 구멍을 찾아 스스로 기워냈으며, Anthropic 은 오픈소스 392개에서 취약점 **2,300개**를 사람 지시 없이 찾아냈음(2026-08-26 기준). 그런데 같은 기간 METR 의 무작위 대조 실험은 **경력 개발자가 AI 를 쓰면 19% 더 느려졌다**고 했고(2025-07-10), GitClear 은 6억 2,300만 줄을 세어 **리팩터링이 70% 줄고 복붙 덩어리가 81% 늘었다**고 했으며(2026), Veracode 는 AI 가 짠 코드의 **45%가 보안 시험에 떨어졌다**고 했음(2025). 즉 **"기계가 채점표를 갖고 있는 좁은 일(취약점 찾기·자바 버전 올리기·경보 1차 분류)은 이미 사람이 안 봄. 반대로 '무엇을 만들지 정하는 일'과 '내보내고 책임지는 일'은 여전히 사람이 전부 붙어 있음."** 그리고 이 분야에서 **가장 큰 병목은 AI 가 아니라 사람임** — Anthropic 이 찾은 취약점 2,300개 중 고쳐진 것은 **421개(18%)** 뿐인데, 못 고친 이유가 "AI 가 못 고쳐서" 가 아니라 "사람 관리자가 다 못 봐서" 임.

| 사람 부르는 다섯 경우 | **되돌릴 수 없는 행동**: Replit 사고 뒤 개발/운영 DB 분리·계획 전용 모드가 업계 기본이 됨 = 다섯 경우 중 1번이 **사고를 겪고 나서야** 들어감. **판단이 안 섬**: Cleric 이 읽기 전용으로 설계를 못 박은 것이 이에 해당. **한도 초과**: Copilot·Codex 가 격리 환경 밖으로 못 나가게 막음. **승인 조건**: PR 병합 승인 = 업계 전체의 기본값. **자격자 전속**: 한국 CISO 지정·ISMS-P 심사 | **다섯 경우가 전부 업계에 실물로 있음.** 다른 어떤 직종군보다 완비돼 있음 |
| 5단계 (보기·알기·정하기·하기·끝내기) | **보기·알기**: 코드·로그·바이너리 읽기는 사람 넘음(티오리 12시간 전수 조사). **정하기**: 좁은 문제는 넘었고 설계 결정은 못 넘음. **하기**: 코드를 짜고 배포까지 감. **끝내기**: 여기가 무너짐 — Veracode 45% 보안 실패, GitClear 유지보수성 붕괴, Anthropic 패치율 18%, Replit 이 가짜 테스트 결과를 지어냄 | **"끝내기" 가 이 분야의 결정적 구멍.** 그런데 **끝내기 기준을 기계가 쥘 수 있는 유일한 분야**이기도 함(테스트 통과·빌드 성공·정적 분석·배포 성공). 우리가 만들 완료 조건을 그대로 실행 가능한 형태로 박을 수 있음 |

## 6. 못 확인한 것

- **DORA 2025 보고서 원문 PDF** — 파일이 10MB 를 넘어 도구가 못 열었음. 그래서 **AI 신뢰도 비율·처리량/불안정성의 정확한 수치·응답자 수 정확값**을 못 폄. "채택률 90%, +14%p, 약 5,000명" 은 구글 공식 블로그와 요약글 기준임.
- **METR 시간 지평 그래프 안의 모델별 숫자** — metr.org/time-horizons 를 열었으나 그래프가 이미지·YAML 로만 있어 본문에 숫자가 없었음. "2026-02 Claude Opus 4.6 약 14.5시간" 은 검색 요약 기준이라 **LIKELY 로만 둠**.
- **SWE-bench Verified·Terminal-Bench 의 공식 제출 원문** — 순위표 집계 사이트만 봤고 각 회사의 공식 평가 카드를 못 대조함. 96%·91.9%·57.9% 는 **재는 곳마다 다를 수 있음**(SWE-bench Pro 가 그 증거).
- **Devin 의 진짜 PR 병합률** — Cognition 공식으로는 "수십만 건 병합" 뿐이고 **분모(시도한 PR 수)를 아무 데서도 못 찾았음.** 그래서 "몇 %가 합쳐지나" 를 모름. 매출·기업가치 숫자도 집계 블로그 기준이라 1차 미대조.
- **Cursor·Lovable·Replit·Claude Code·Codex 의 매출·이용자 수** — 전부 집계 블로그 기준이고 회사 공식 발표 원문을 못 폄.
- **Amazon Q 자바 업그레이드 수치가 2024-08 것** — 2년 지난 자료인데 갱신본을 못 찾았음. 지금 숫자는 더 클 것으로 보이나 확인 못 함.
- **한국 대기업의 개발 생산성 공개 수치** — 네이버 "생산성 2배"(목표치이지 실측치가 아님) 말고는 **카카오·토스·삼성SDS·LG CNS 모두 개발 생산성 숫자를 공개하지 않음.** 카카오는 "AI 에이전트 플랫폼 선언" 만 있고 사내 코딩 도입 수치가 없었음. 토스는 아예 못 잡았음.
- **한국 개발자 채용 감소의 공식 통계** — "신입 채용 비중이 2021년 대비 절반 이하" 는 블로그·기사 요약 기준이고 **고용노동부·SW산업협회 원 통계표를 못 폄**.
- **Momentic·mabl·Meticulous·Wren AI·incident.io** 의 회사 공식 수치 — 비교 블로그에만 나와서 미확인으로 둠.
- **CyberSecEval·Cybench** (보안 벤치마크) — 검색 예산이 떨어져 아예 못 봤음.
- **Google Jules 의 이용 규모** — 공개 수치를 못 찾았음.
- **Pentera·Prophet Security·SK쉴더스**의 1차 자료 — 미대조.
- **한국 AI 기본법 조문 원문** — law.go.kr 원문을 직접 열지 못했고, 시행일(2026-01-22)·고영향 AI 범위는 법무법인 뉴스레터·참여연대 자료 기준임. **소프트웨어 개발이 고영향 AI 에 들어가는지 여부는 확인 못 함**(들어가지 않는 것으로 보이나 확정 못 함).
- **검색 예산**: WebSearch+WebFetch 합계 45회 사용(한도 55회). 남은 10회는 위 구멍 중 어느 것도 한 번에 메우지 못할 것으로 판단해 파일 저장에 씀.
