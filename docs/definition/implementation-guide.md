# 재료별 구상과 조립

<!-- 이 파일과 materials.md에서 정의 2를 생성한다. -->

이 문서는 [정의 1](전문가%20에이전트%20정의.md)의 재료를 실제 업무로 조립할 때 필요한 계약을 설명한다. 재료의 정본은 [materials.md](docs/materials.md), 실행은 [runtime.md](docs/runtime.md), 대체 판정은 [evaluation.md](docs/evaluation.md)다. 아래 재료별 설명은 정본에서 생성하므로 같은 책임을 다른 문장으로 중복 관리하지 않는다.

현재 범위는 화면·문서·시스템·통신 안에서 끝나는 과업이다. 실제 수행에 필요한 현장 자료가 제공되지 않았다면 미확인 상태로 남기고, 새 현장 수행을 온라인 과업의 완료로 세지 않는다. [166개 직무의 범위 대장](docs/definition/occupation-scopes.csv)은 온라인 위임 단위·필요 입력·제외 범위·고유 실패 기준을 정리한 설계 자료이며, 실제 능력 인증 목록이 아니다.

이전 구상의 전체 내용은 [변경 전 보관본](docs/archive/definition-2-before-v2.txt)에 보존했다. 거기에 있는 공급자·가격·표본 수·폴더 수·고정 횟수·예전 분류는 현재의 채택 결정이 아니다. 유용한 기술 후보를 재사용할 때도 아래 계약과 실제 시험으로 확인한다.

## 조립의 단위

`공통 재료·계약 + 직무별 지식·방법·도구·평가 + 개별 위임의 목표·권한·자료·기한`

| 층 | 담는 내용 | 변경 책임과 확인 |
|---|---|---|
| 공통 정의 | 재료·하위 책임·입출력·실패·변경·평가 계약 | 기준선 판본과 영향받는 직무의 조립·회귀 검사 |
| 직무 정의 | 핵심 객체·방법·질문·예외·숙련 사례·도구·허용 결과 | 해당 분야 검토와 새 과제 시험 |
| 개별 위임 | 당사자·성과·권한·입력·기한·예산·인수 조건 | 정당한 결정권자의 범위와 유효한 증거 |
| 실행 상태 | 현재 판단·작업·대기·이미 일어난 외부 효과 | 원천 대사·변경 전파·내구 저장 |

단어 목록이나 직무명만으로 필요한 기능을 고르지 않는다. 요구의 의미와 실제 환경을 확인하고, 구조화할 수 있는 단위·판본·권한·필수 참조는 검사기로 확인한다. 선언한 요구가 잘못될 수 있으므로 M34·M43·M44에서 문제 정의와 요구 자체를 다시 검토한다.

## 직무별로 반드시 채울 것

| 구체화할 것 | 내용과 증거 | 담당 |
|---|---|---|
| 문제와 성과 | 원하는 결과, 원인·대안 설명, 가치 충돌, 하지 않을 일, 결정권 | M17·M31·M34·M36·M38 |
| 전문 지식 | 객체·관계·단위·인과·방법·전제·예외·반례 | M21 |
| 숙련 판단 | 본 단서·버린 대안·선택 이유·판단 전환 조건, 개발 사례 밖 적용 | M22·M34 |
| 실제 작업 | 입력에서 결과까지의 계산·실험·제작·대화·시스템 행동 | M07·M09·M10·M38·M52–M56 |
| 요구별 연결 | 선행 조건·담당·자료·행동·검사·인수·실패 후 다음 경로 | M25·M35·M41 |
| 완료·비교 | 허용 결론·치명적 누락·성과 시점·사람 기여·숙련 전문가 기준선 | M36·M40·M42–M49·M51 |

법률은 요건·주장·항변·증거·절차를, 감사는 주장별 증거와 추정을, 상담은 사례 이해·개입·관계 변화를, 창작은 의도·구성·표현·연속성을 구체화한다. 같은 일반 지침에서 직무 이름만 바꾼 것을 전문 지식으로 세지 않는다. 지식 문장 수나 숙련자 인터뷰 시간을 보편 합격선으로 쓰지 않는다.

## 하위 책임과 실행 시점

M10의 연결·격리, M18의 근거·판본, M27의 법·직업 의무, M28의 계약·플랫폼, M54의 실제·모의 실험은 [하위 책임 계약](docs/materials.md#하위-책임과-지원-증거)의 키로 추적한다. 각 키의 적용 여부·활성 조건·수행 시점·지원 범위·검증 증거를 따로 둔다. 사용한 경로의 필수 하위 책임이 모두 충족되어야 상위 재료가 그 경로에서 합격한다.

| 상태 | 뜻 |
|---|---|
| 구현 planned / implemented | 아직 구상 중인지 실행 수단이 있는지 |
| 검증 unverified / passed / failed / stale | 시험 여부·결과와 현재 조건에서의 유효성 |
| 적용 required / conditional / not_applicable | 이번 업무에서 필수인지, 조건 판단이 필요한지, 근거를 갖고 제외했는지 |

모의 시험만 passed면 실제 실험을 지원한다고 표시하지 않는다. 다른 형식·환경·난도나 새 조합으로 지원을 넓히려면 그 범위의 증거가 필요하다. 조건이 불명이면 먼저 조건을 확인할 진단 경로를 준비하되, 진단의 권한을 본 실행에 전용하지 않는다.

## 실행 구성을 고르는 방법

위임형·고용형·운영형은 업무를 맡기는 관계다. 순차·병렬·반복·위임·공동 작성·독립 검토는 실행 방법이다. 실시간·긴급·장기·여러 사건은 시간과 상태의 조건이다. 이 세 축을 별도로 조합한다. 사람이 요청했다는 이유로 일회성이 되거나, 신호로 시작했다는 이유로 고용형이 되지 않는다.

| 실행 방법 | 사용 조건 | 조합 때 확인할 것 |
|---|---|---|
| 단독 | 한 실행자가 자원·지식·기한을 충족 | 지원 범위·검증의 독립성 |
| 순차 | 앞선 결과가 다음 작업의 전제 | 조건부 의존·실패·대체·일정 |
| 병렬 | 충돌 없이 독립 진행 가능 | 공유 파일·상태·예산·외부 행동의 소유권 |
| 반복·탐색 | 관측으로 대안·품질을 개선 | 정보 가치·오류 원인·누적 예산·중단·재계획 |
| 분담·공동 작업 | 여러 전문성 또는 작업량을 나눠야 함 | 공유 근거·비밀 경계·상호 질의·이견·통합 책임 |
| 독립 검토 | 주요 판단의 반례·오류를 찾을 필요 | 평가자의 실제 오류 검출·헛반박·공통 오류 |
| 사람 협력 | 사실 응답·권한 행사·전문 판단·자격 행위가 필요 | 목적·수신자·기한·인수·사람 기여와 총비용 |

순차 안에 병렬이 들어가고, 병렬 결과를 순차 통합하며, 일부만 반복할 수 있다. 유형 개수나 같은 층이라는 이유로 합법적인 조합을 금지하지 않는다. 모든 작업을 무조건 병렬화하지도 않는다. 변경이 생기면 영향을 받는 의존·목표·권한·예산·기한을 다시 계산한다. 재계획 횟수 자체를 실패로 세지 않고 그 필요성과 결과를 평가한다.

여러 사건은 원래 건을 무조건 맨 앞에 두거나 고객별로 독립 최적화하지 않는다. 기한·기대 손실·자원·위임 우선순위·공통 충격을 함께 고려한다. 공동 상태가 있어도 고객별 비밀과 권한을 합치지 않는다.

실시간 경로는 충분한 맥락·필수 의미 검사·취소·정정·연결 복구를 지연 예산 안에서 수행한다. 깊은 판단을 분리할 수 있지만 새 사실을 무시하거나 모든 검증을 사후로 미루지 않는다. 기한 내 가능한 범위와 대체 응답을 정의한다. 긴급 조치 역시 현재 위임·한도·대상·복구 조건을 지킨다.

## 실패와 다음 담당

모든 책임은 성공 출력 외에 확정 실패·불명·대기·취소의 출력을 가진다. 실패에 원인 후보·영향받는 요구·시도 기록·다음 담당·재개 증거를 붙인다. 아래 공통 배선으로 연결하되, 실제 의미 판단은 해당 직무에서 검증한다.

| 실패 종류 | 다음 담당 | 재개하거나 끝낼 조건 |
|---|---|---|
| 입력을 못 읽거나 값·근거가 충돌 | M07·M18·M19 → M34·M35 | 재취득·대체 근거 또는 불확실성 아래의 정당한 결정 |
| 전문 지식·방법 부족 | M21·M22·M34 → M50·M49 | 새 지식·방법의 평가 통과, 확보 실패면 M39와 미완료 |
| 요구·목표·자원 양립 불가 | M34·M35·M33 | 권한 있는 범위 변경 또는 달성 불가·대안 보고 |
| 권한·규칙·한도 미충족 | M27–M33·M39 | 유효한 승인·범위 변경 또는 해당 실행 중단 |
| 도구·수신·저장소 장애 | M57·M10·M06·M03 | 현재 외부 상태·권한·실행 세대·예산 대사 후 복구 |
| 외부 실행 불명·일부 성공 | M56·M25·M42 | 원천 대사, 성공분 보존, 허용된 잔여 실행·보상 |
| 결과 오류·낡은 검사 증거 | M42·M43·M44 → 원인 담당 | 관련 파생물 수정·재검증; 검사 불가는 합격 제외 |
| 반복 실패·지연 성과 악화 | M48·M51 → M50·M49 | 원인·수정·회귀·새 과제 증거, 필요하면 이전 판본 복구 |
| 무응답·미회수·인수 실패 | M06·M25·M35·M39·M40 | 대기 기한·대체 경로·객관적 인수 또는 미완료·후속 책임 |

하위 작업이 실패해도 무관한 경로까지 일괄 중지하지 않는다. 반대로 실패한 필수 작업을 빠뜨리고 전체 완료를 선언하지 않는다. 종료 상태·목표 달성·검증·사후 성과를 각각 기록한다. 조합의 모든 대기는 [대기 계약](docs/runtime.md#대기와-무응답)을 따른다.

## 모델·도구·저장 기술의 선택

| 선택 대상 | 채택 근거 | 남겨야 할 제한 |
|---|---|---|
| 모델·호출 설정 | 실제 배치 환경의 전문 품질·불확실성·지연·총비용 비교 | 입력·도구 지원, 판본 고정 가능성, 데이터 이동, 변경 후 평가 |
| 실행기 | 내구 실행·취소·재개·권한·예산·외부 대사 | 외부 서비스의 멱등성 한계와 불명 상태 |
| 검색·지식 | 대상 자료의 재현율·예외·반대 근거·시점·격리 | 못 찾은 범위·접근 불가·검색과 판단의 차이 |
| 저장 | 구조화된 상태·이력·객체·권한·복구·삭제 요구 | 보존 기간·외부 사본·백업·변경 전파 |
| 전문 도구 | 형식·판본·작업별 생성·읽기·수정·실행·인수 | 라이선스·플러그인·자원·미지원·손실 있는 변환 |
| 검증기 | 알려진 오류·정상 결과의 검출·헛막음과 실제 추가 가치 | 모델·원천·구현을 공유한 공통 오류 |

모델 이름·요금·캐시·추론 설정은 버전별 기술 결정 기록에 실제 확인한 출처·일자와 함께 둔다. 공급자가 다르다는 이유만으로 독립성이 보장되거나, 등급이 높다는 이유로 업무 합격이 되지 않는다. 고정된 등급·캐시 수명·가격을 공통 정의에 넣지 않는다. 모델 교체 때 필요한 어댑터 수정은 허용하되 계약과 회귀 증거를 확인한다.

모델이 강해져도 권한·예산 검사와 내구 기록은 필요하다. 자연어 문제 정의·전문 해석은 모델과 직무 내용이 맡고, 결정적 계산·형식·인증·저장은 검증 가능한 코드와 도구로 수행한다. 능력 부족의 원인이 모델인지 자료·방법·도구·연결인지 분석한 뒤 수정한다.

## 파일·폴더와 저장 배치

계통 9개를 폴더 9개와 일대일 대응시키지 않는다. 코드·자료·지식·설정·증거의 생애주기와 접근 경계에 맞춰 배치하고 ID·참조로 연결한다. 아래는 구현 예이며 특정 제품·배치의 채택 결정이 아니다.

```text
contracts/     책임·입출력·상태·검증 계약
jobs/          직무별 범위·지식 참조·도구·평가 설정
knowledge/     검증된 원리·방법·숙련 사례
runtime/       실행·도구·저장·권한·감시 구현
evals/         개발·회귀·보호된 신규 과제의 분리된 정의
evidence/      실행·외부 결과·검사·사람 기여의 참조
```

진행 중 사실·행동·승인·외부 영수증·검사·대기는 구조화된 레코드로 관리한다. 원문과 큰 파일은 객체 저장소에 두고 무결성·위치·접근권을 연결할 수 있다. 선언한 보존과 설명 기간을 함께 지키며, 삭제 뒤 백업·검색·캐시·지연 이벤트로 정보가 부활하지 않게 한다. 실제 표와 거래 순서는 [저장·격리·삭제 계약](docs/runtime.md#저장-구조)을 따른다.

성능·비용·장비 규모는 입력 크기·동시성·긴 작업·실시간 비율·보존량·검색·모델 호출·외부 대기·복구를 측정해 산정한다. 평균만으로 피크 자원과 꼬리 지연을 정하지 않는다. 자료를 확보하는 비용과 초기 구축·사람 지원 비용도 포함한다.

## 구축과 배치의 관문

| 단계 | 완료 근거 |
|---|---|
| 구조 정의 | 필요한 책임·하위 책임·입출력·실패·대기·변경·검증의 주인이 있고 반례에서 연결이 끊기지 않음 |
| 직무 구체화 | 실제 온라인 과업의 핵심 객체·방법·자료·도구·자산·품질·실패 기준이 채워짐 |
| 최소 실행 | 그 과업의 접수부터 실제 작업·외부 확인·인수까지 실행, 누적 예산·권한·복구 포함 |
| 능력 검증 | 회귀와 보호된 새 과제를 구분하고 같은 조건의 숙련 전문가와 비교 |
| 운영 | 사람 기여·실제 비용·지연 성과·변경·장애를 추적하고 이탈 범위 제한 |
| 다음 직무 | 공통부 재사용과 추가 내용·연동·시험을 구분하고 새 조합을 다시 검증 |

모든 재료를 같은 순서로 구축해야 하는 것은 아니다. 첫 과업에 실시간·협업·계산·실험이 필요하면 첫 실행 전에 준비한다. 어려운 직무를 영구 제외하지 않으며 쉬운 직무의 성적을 다른 직무에 전이하지 않는다.

정의 완료·구현 완료·전문 능력 입증을 별도 상태로 보고한다. 실제 제품이나 166개 전문 에이전트를 구현하지 않은 문서 정합성 검사를 대체 성적으로 바꾸지 않는다. 최종 판정은 [평가 규약의 전체 관문](docs/evaluation.md#최종-합격과-주장)을 따른다.
