# 사용 구조 재설계 검토 — 2026-09-21

## 적용한 최종 요청

목적은 세 상황에서 전체가 어떻게 움직이고 79개 재료가 어디에 사용되는지, 각 상황의 한 그림 안에서 확인하는 것이다. 고정 가로·세로 규격과 Mermaid 단일 형식 제약은 최신 요청에 따라 적용하지 않았다. 사용 구조에는 세 제목과 세 그림만 둔다. 별도 설명표·상세 보기·두 번째 그림을 읽어야 하는 구조로 나누지 않는다.

## 표현과 의미

- 단독: 한 전문가의 요청 이해, 자료·기준 적용, 방법 선택, 필요한 재료 조합, 검증과 후속 작업을 연결했다. `나눠 맡기기`는 미사용 이유를 표시했다.
- 오케스트레이션: 총괄의 배정, 시작 조건을 갖춘 담당들의 분담, 담당별 재료 사용, 결과·실패·미응답의 회수, 검증한 중간 결과의 다음 담당 전달을 연결했다.
- 복합: 전체 총괄 아래 건별 목표·완료 조건, 건별 총괄의 내부 배정·회수, 전체 회수를 구별했다. 검증한 결과를 다른 건의 입력으로 넘길 때 건별 권한·선행 조건·공유 자원·예약분을 다시 확인한다.
- 자료·규칙·상시 기반은 적용 범위와 연결 대상을 표시했다. 회색 적용선과 묶음의 소속 관계를 실행 순서로 해석하지 않는다. 실제 사용과 결과 전달은 화살표로 표시한다.
- 실무 내부의 선은 함께 사용할 때의 입력·결과 관계다. 네 목적의 재료를 모두 실행하는 고정 절차가 아니다. 역할 분담도 고정 인원·직업이 아닌 예시이며 업무에 따라 담당을 합치거나 나눈다.
- 규칙은 법적 관계를 먼저 확인하고, 충돌하는 조항의 위계를 적용하며, 남는 조건과 예외의 결정 권한을 유지한다.
- 사람에게 결정받는 다섯 조건을 원문과 대조했다. 준비·검증을 마친 뒤 요청하며, 답변 주체·권한·승인 대상을 확인한다. 유효하지 않거나 거절·기한 종료이면 실행하지 않고 보류한다.
- 결과 검증은 중간·최종 결과 모두에 적용한다. 문제 있음, 미확인, 문제없음의 행선지를 구분한다. 검증한 중간 결과는 다음 입력으로, 최종 결과는 인수로 연결한다.
- 인수 미응답은 후속 확인, 반려·수정 요청은 재검증, 거절·기한 종료는 보류로 연결한다. 재계획은 완료분을 유지하고 바뀐 범위의 현재 조건을 다시 확인한다.
- 실제 성과와 실패·보류 기록을 학습에 사용한다. 개선안은 격리 시험과 업무 능력 시험을 거쳐 통과한 내용만 저장·적용한다.

정식 표의 이름·구분·조건, 한 도형 한 재료, 분기 라벨, 잘못된 분기, 종료 도형의 후속 실행 유무, 화살촉이 도형 경계에 닿는지, 전체 그림의 연결을 검사했다. 묶음을 포함한 연결 검사와 실제 실행 경로 검사는 구분했다. 소속 관계를 실행 경로로 간주해 통과시키지 않는다.
