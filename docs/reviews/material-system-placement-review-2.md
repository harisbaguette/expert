# 재료 50개의 계통 배치 재검토

- 검토일: 2026-09-14 · 대상: 본문 「계통별 재료」 9계통 50행 · 기준 판본: 커밋 8586cf9
- 앞선 검토: [재료 55개의 계통 배치 검토](material-system-placement-review.md)(2026-09-11, 10개 이동 반영). 그 뒤 행 합침·이름 변경으로 50행이 됐으므로 처음부터 다시 판정했다
- 잣대: 각 계통 소개문이 밝힌 책임 경계(아래 표)와 본문 목표. 재료의 소속은 **주된 산출물과 책임**으로 정하고, 어떤 도구로 구현하는지와 누가 그 결과를 쓰는지는 소속의 근거로 삼지 않았다
- 이번 검토에서 본문을 고치지 않았다. 옮길 행이 없고, 유일한 구조 제안(실무의 빈자리)은 ✅ 확정 표에 행을 더하는 일이라 결정을 기다린다

## 총평

| 항목 | 결과 |
|---|---|
| 옮길 행 | 0행 |
| 경계가 흔들려 소개문에 경계를 적어야 할 행 | 8행 (아래 표) |
| 계통을 늘리거나 합칠 필요 | 없음. 9계통 유지 |
| 빈자리 | 실무에 1행 — 실제 시스템의 상태를 바꾸는 처리(거래·접수·설정 변경)를 맡는 행이 없음. 제안만 하고 반영하지 않음 |

## 계통별 책임 경계 (판정에 쓴 잣대)

| 계통 | 소개문에서 읽은 경계 | 이 계통이 아닌 것 |
|---|---|---|
| 환경 | 일을 할 수 있게 하는 기반. 두뇌·실행 제어·보는 그릇·격리·통로·도구 연결 | 무엇을 할지 정하는 일, 실제 결과를 만드는 일 |
| 자료·검색 | 밖에서 가져오는 자료를 확보하고 믿을 수 있게 관리 | 이미 아는 것(지식), 일하며 쌓은 것(기억) |
| 지식·경험 | 이미 알고 있어서 바로 꺼내 쓰는 것 | 밖에서 가져오는 자료, 이번 건에서 새로 쌓은 것 |
| 기억·진행 상태 | 실제로 일하면서 새로 쌓는 것 | 원래 아는 것, 왜 그렇게 판단했는지의 증거 |
| 규칙·권한 | 무엇을 지켜야 하고 어디까지 해도 되는지, 그리고 그것을 강제하는 것 | 그 안에서 무엇을 먼저 할지 |
| 행동 체계 | 허용된 안에서 어떻게 판단하고 진행하고 끝내고 사람에게 넘길지 | 실제 작업 수행, 규칙 자체 |
| 실무 | 실제 결과를 만드는 작업 수행 | 결과가 맞는지 확인 |
| 검증·평가 | 판단과 결과가 제대로 됐는지 확인하고 증거를 남김 | 에이전트 자체를 바꾸는 일 |
| 학습·개선 | 같은 문제가 반복되지 않게 에이전트 자체를 바꿈 | 이번 결과를 고치는 일, 나아졌는지 재는 일 |

## 계통을 늘리거나 합칠지

| 후보 | 판정 | 이유 |
|---|---|---|
| 「기록·감사」 신설 — 판단 근거 기록·현재 진행 상태·장기 기억·성과 추적을 모음 | 안 함 | 네 기록은 쓰는 이유가 다르다(증거·지금 상태·다음 일·성과). 이유별로 흩어 둔 지금이 주인이 분명하고, 모으면 "기록"이라는 모양만 같아진다 |
| 「사람·관계」 신설 — 실시간 대화·사람과 소통·사람에게 넘기기·결과 전달·확인을 모음 | 안 함 | 통로는 환경, 수행은 실무, 판정은 행동 체계로 가른 잣대가 다른 계통과 같다. 상대가 사람이라는 이유로 모으면 잣대가 둘이 된다 |
| 「실행·행동」 신설 — 업무 도구·시스템·결과 전달·확인·판단·실행 반복을 모음 | 안 함 | 세 행은 연결 장치·전달·실행 제어로 이미 서로 다른 계통의 책임이다. 빈자리는 계통이 아니라 실무의 행 하나다(아래) |
| 지식·경험 + 기억·진행 상태 합침 — 각 2행뿐 | 안 함 | 원래 아는 것과 일하며 쌓는 것은 누가 갱신하고 어떻게 검증하는지가 다르다. 행이 적어도 경계가 목표(사람 없이 일하며 쌓기)에 직접 닿는다 |
| 검증·평가 + 학습·개선 합침 | 안 함 | 재는 쪽과 고치는 쪽을 나눠야 스스로 채점하는 문제를 막는다. 소개문이 이미 이 이유로 갈라 두었다 |

## 경계가 흔들리는 8행 — 유지하되 소개문에 경계를 적을 것

| 재료 | 현 계통 | 끌리는 계통 | 유지 이유 | 적어야 할 경계 |
|---|---|---|---|---|
| 현재 작업 정보 | 환경 | 기억·진행 상태 | 모델이 지금 보는 **그릇**이다. 무엇을 남길지의 내용이 아니다 | 그릇은 환경, 담을 내용은 현재 진행 상태 |
| 나눠 맡기기 | 환경 | 행동 체계 | 여러 AI를 돌리고 결과를 모으는 **장치**다. 나눌지 말지의 결정이 아니다 | 나눌지와 누가 맡을지는 업무 절차·실행 계획 |
| 재사용 자료 | 자료·검색 | 실무 | 서식·부품의 확보와 권리·호환 관리는 자료 관리다 | 실제로 가져다 쓰는 일은 결과물 만들기·수정 |
| 자료의 출처·버전 | 자료·검색 | 검증·평가 | 남의 자료를 믿을지 정하는 **입력 관리**다 | 검증·평가는 우리 판단과 결과를 확인하는 곳 |
| 표현 방식·스타일 | 규칙·권한 | 지식·경험 | 지켜야 할 **기준**이지 익힌 기법이 아니다 | 표현 기법은 업무 지식, 서식 파일은 재사용 자료 |
| 안전장치 | 규칙·권한 | 환경 | 규칙·권한·한도를 **강제하는 장치**라 규칙 옆에 있어야 규칙이 바뀔 때 같이 바뀐다 | 실제 격리 공간은 안전한 분리 실행 |
| 판단 근거 기록 | 검증·평가 | 기억·진행 상태 | **왜** 그렇게 했는지의 증거다. 어디까지 했는지의 상태가 아니다 | 상태는 현재 진행 상태, 다음 일에 쓸 것은 장기 기억 |
| 성과 추적 | 검증·평가 | 학습·개선 | 나아졌는지 **재는** 일이다. 고치는 일이 아니다 | 잰 결과를 받아 고치는 것은 학습·개선 |

## 실무의 빈자리 — 제안 (반영하지 않음)

| 항목 | 내용 |
|---|---|
| 없는 것 | 실제 시스템의 상태를 바꾸는 처리를 맡는 실무 행. 전자신고 제출, 송금 실행, 주문 입력, 서버 설정 변경처럼 결과물 파일이 아니라 **시스템 상태 변화가 결과인 일** |
| 지금은 누가 하나 | 업무 도구·시스템(환경)이 "값을 입력하거나 제출한다"까지 맡고, 결과 전달·확인(실무)이 됐는지 확인한다. 연결 장치가 실무 일을 하고 있고, 무엇을 언제 어떤 값으로 처리할지 정하는 주인이 없다 |
| 왜 문제인가 | 목표가 "온라인·컴퓨터 안에서 시작해 끝나는 일"이라 이런 처리가 업무의 끝인 직종이 많다. 결과물 만들기·수정은 "결과물을 만든다"이고, 결과 전달·확인은 "전달한다"라 둘 다 시스템 처리 자체를 맡지 않는다 |
| 제안 | 실무에 「시스템 처리·실행」 1행(조건부). 하는 일: 실제 시스템에서 거래·접수·설정 변경 같은 처리를 정해진 값과 순서로 실행하고 처리 결과를 받아 온다. 연결은 업무 도구·시스템, 실행 전 검사는 안전장치, 되돌릴 지점은 판단·실행 반복이 맡는다 |
| 반영하지 않은 이유 | ✅ 확정 표에 행을 더하는 일이라 결정을 기다린다. 대안은 업무 도구·시스템의 하는 일을 "연결"로 좁히고 결과 전달·확인을 "처리와 전달"로 넓히는 것이나, 두 행의 뜻이 바뀌므로 같은 결정이 필요하다 |

| 부족한 능력 보완 | 학습·개선 | 유지 | 에이전트 자체를 바꿈 |

## 확인 근거와 한계

읽은 것은 본문 「계통별 재료」의 아홉 소개문과 50행의 한마디로·하는 일·예시·구분·비고 전부, 그리고 앞선 배치 검토 문서다. 판정은 각 행의 책임을 소개문 경계에 대고 하나씩 내린 것이며, 구현 가능성이나 실제 성능은 범위 밖이다. 「유지」는 소속 판정일 뿐 그 행의 내용이 충분하다는 뜻이 아니다. 내용의 구멍은 [재료별 비판 검토](material-harsh-critique-review.md)에서 다뤘다.
