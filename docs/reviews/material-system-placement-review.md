# 재료 55개의 계통 배치 검토

검토일: 2026-09-11. 대상은 현재 작업 폴더의 진행 계획, 재료 정본, 두 정의 문서의 계통별 요약과 재료별 구상이다. 아래는 재배치 전 정의에 근거한 검토 기록이다. 사용자 승인에 따라 2026-09-11 재료 10개를 옮기고 4개의 책임·설명을 보완했다. 재료 정본·두 정의 문서·구현 경로 예시·전개 그림·현행 대조표에 반영했다. 아래의 ‘검토 당시’ 값은 변경 전 배치를 보존한다.

55개를 모두 확인했다. **재배치 권고 10개, 현 위치를 유지하되 책임·설명을 보완할 것 4개, 현 위치 유지 41개**다. 이름과 계통은 세 문서 사이에 일치한다. 문제는 문서 간 배치 불일치보다, 배치된 계통의 뜻과 실제 책임 사이의 불일치다.

## 판정 기준

[재료 정본](../materials.md)은 재료를 기능과 책임의 목록으로 정의하고, 한 책임을 한 재료가 소유하도록 정한다. 따라서 주된 출력과 책임으로 계통을 판단했다. 어떤 도구로 구현하는지, 언제 호출되는지, 다른 계통이 그 결과를 사용하는지는 소속을 정하는 기준과 구별했다.

| 계통 | 이 검토에서 적용한 책임 경계 |
|---|---|
| 환경 | 모델 호출, 실행 제어, 복원, 입력창, 통신, 도구 연결, 격리 실행 등 업무를 수행할 기반 제공 |
| 자료·검색 | 원본을 확보·읽기·조회하고 출처·판본을 관리. M55를 유지하려면 재사용 업무 자산의 확보·관리까지 계통 설명에 명시 |
| 지식·경험 | 개념·방법·숙련 사례와 적용 한계를 판단에 제공 |
| 기억·상태 | 이번 건과 다음 건에서 이어 쓸 사실·결정·약속·진행 상태 유지 |
| 규칙·권한 | 지켜야 할 요구·제약·선호·권한·한도 정의와 적용 |
| 행동 체계 | 판단·순서·완료·착수·사람 이관의 기준과 실행 계약 결정 |
| 실무 | 실제 제작·가공·계산·실험·상호작용·인도를 수행하고 전체 업무 진행을 연결 |
| 검증·평가 | 결과·과정·위험·능력·실제 성과를 확인하고 검증 근거 제공 |
| 학습·개선 | 확인된 실패와 부족함의 원인을 찾아 지속적으로 쓸 지식·규칙·도구·정의를 개선 |

이는 프로젝트의 6항·9계통을 유지하면서 책임 기준을 일관되게 적용한 설계 판단이다. 특정 재료의 유일한 업계 표준 위치라는 주장은 아니다. 같은 구현을 공유하거나 여러 계통에서 호출하는 것은 가능하다.

## 재배치 권고 10개

| M52 데이터 처리 | 환경 → 실무 | 수집·정제·결합·집계한 데이터셋과 처리 작업을 산출한다. 데이터에 접근하는 기반을 넘어서 업무 결과를 생산한다 |
| M53 계산·분석·최적화 | 환경 → 실무 | 계산·예측·최적화와 실패 후 대체 풀이를 수행한다. 계산 도구 연결은 M10, 방법 지식은 M21, 계산의 실제 수행은 M53이다 |
| M54 실험·시뮬레이션 | 환경 → 실무 | 업무상 가설과 대안을 비교하는 실험을 설계·실행·분석하고 새 증거를 만든다. 실험할 공간인 M11과 책임이 다르다 |
| M23 정체성·작풍 | 지식·경험 → 규칙·권한 | 상세 구상은 말투·금기·발행 약속을 정하고, 모든 산출물에 적용하며, 위반한 결과물은 내보내지 않는다고 정의한다. 현재 내용은 익힌 표현 기법보다 지켜야 할 표현 기준이다 |
| M38 상대 응대 | 행동 체계 → 실무 | 현재 책임은 응대 원칙을 정하는 데 그치지 않고 설명·교육·협상·상담·코칭·중재를 실제로 수행하며 상대 반응에 대응하는 것이다 |
| M40 보고·납품·인수 | 행동 체계 → 실무 | 실제 전달, 수신 환경 확인, 현장 인도·시운전·인수 확인까지 맡는다. 완료·인수 기준을 정하는 M36과 그 기준대로 인도하는 M40을 구별한다 |
| M49 고정 시험 | 학습·개선 → 검증·평가 | 주된 출력은 고정 판본의 회귀·새 과제·복합 업무 평가 결과다. 개선 과정에서 사용한다고 시험 자체가 개선 책임이 되지는 않는다. M50이 시험을 요청하고 결과를 받아 반영 여부를 정하면 된다 |
| M51 성과 추적 | 학습·개선 → 검증·평가 | 실제 성과·지연 손실·사람 기여·비용의 측정과 귀속을 맡는다. 개선하지 않는 업무에서도 목표 달성 여부를 판정하는 데 필요하다. 측정 결과는 M48·M50에 넘기고, 지속 정의의 변경은 M50이 소유한다 |

특히 **M09·M52·M53·M54와 M38·M40**은 현재 구상이 실제 업무 수행까지 명시한다. 이들을 환경 또는 규칙 아래에 놓으면 실무에는 M41의 전체 흐름 하나만 남고, 실제로 일을 하는 기능은 다른 계통에 흩어진다.

M07과 M52는 모두 자료를 다루지만 결과가 다르다. 엑셀의 셀·수식·참조를 읽는 일은 M07, 여러 표를 결합하고 중복을 제거해 새 데이터셋을 만드는 일은 M52, 그 데이터로 예측하는 일은 M53, 결과를 편집 가능한 보고서로 만드는 일은 M09다.

M54도 이름에 ‘실험’이 들어간다는 이유로 검증·평가에 두지 않는다. 고객 업무의 새 증거를 만드는 실험은 M54, 에이전트 변경 후 기존 능력이 유지됐는지 재는 시험은 M49다. M53의 업무용 예측 모델 학습도 고객 업무의 산출물을 만드는 실무이며, 에이전트 자신의 능력을 개선하는 M50과 구별한다.

M23의 좋은·나쁜 예시는 표현 기준을 설명하는 근거로 연결할 수 있다. 예시를 활용한다는 사실만으로 기준의 소속이 지식·경험이 되지는 않는다. 표현 기법·숙련 사례는 M21·M22, 실제 재사용 파일은 M55, 현재 적용할 작풍 기준은 M23이 맡는 구성이 일관된다.

## 확인 근거와 한계

직접 읽은 핵심 근거는 [진행 계획](../../진행-계획.md), [재료 정본](../materials.md), [정의 문서의 계통별 설명](<../../전문가 에이전트 정의.md>), [55개 재료의 상세 책임](<../../전문가 에이전트 정의 2.md>), [그림 생성기의 TERM_SYSTEMS](../전개-수식-gen.py)다. 기존 [모델 기본 능력 검토](api-model-builtins-review.md)와 [바깥 대조 종합](../바깥조사-종합-수식대조.md)도 참고했다. 재료가 필요하다는 결론과 그 재료의 소속이 적절하다는 결론은 별도로 판단했다.

외부 자료에서는 회귀 평가와 운영 성과 관측이 개선에 신호를 제공하는 관계를 확인했다. 이를 참고해 M49·M51의 측정·평가 책임과 M50의 개선 책임을 구별했다. 이 문서의 계통 이동은 그 관계를 현 재료 정의에 적용한 판단이다. [Anthropic: Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents).

LangGraph는 체크포인터를 통한 실행 상태 보존과 스토어를 통한 장기 기억을 구별한다. 이 프로젝트에서는 저장 메커니즘을 M03, 보존할 업무 정보의 의미와 수명을 M24·M25가 나누어 맡으므로 현 배치를 유지할 수 있다. LangGraph 자체가 같은 9계통을 사용한다는 뜻은 아니다. [LangChain: Persistence](https://docs.langchain.com/oss/python/langgraph/persistence).

자료 정본의 M01–M55 누락·중복과 두 정의 문서의 55개 이름·계통을 읽기 전용 코드로 대조했고 일치했다. 그 확인은 배치의 의미상 타당성을 증명하지 않으므로, 위 전수 판정은 각 재료의 책임을 별도로 읽고 내렸다. 실제 구현의 성능·정확도·전문가 대체 가능성은 이번 검토 범위가 아니다.

검토 중 기존 그림 생성기의 요약 대조 함수가 `**이름** ✅` 형식의 여섯 행을 읽지 못하는 문제도 확인했다. 해당 표기를 허용한 별도 읽기 전용 대조에서는 55개 이름·계통이 일치했다. 이는 계통 배치와 별개의 기존 파서 문제였으며, 재배치 반영 때 선택적인 완료 표시를 허용하도록 수정했다.

반영 범위는 materials.md, 두 정의 문서의 표·상세 구상·구현 경로, 계통 수 설명, 그림 생성기와 그림, 진행 계획과 현행 55개 대조표다. 과거 조사 요약에는 당시 분류임을 표시했고, 과거 실험의 판본 스냅샷은 당시 배치를 보존했다. 재료 ID·이름·사용 시점은 유지한다.

반영 후 재료 정본·요약표·상세 구상·구현 경로 예시·업계 55개 대조표·SVG의 55개 소속이 일치함을 확인했다. 이동한 ID는 권고한 10개와 같으며, 이름·완료 표시·사용 시점의 변경과 재료 누락·중복은 없다. 그림 생성과 `git diff --check`를 통과했고, SVG를 실제 렌더링해 세 구간의 전체 폭에서 글자 겹침·잘림이 없는 것을 확인했다.
