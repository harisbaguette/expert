# 정의 2 현행화 검토 — 2026-09-16

## 검토 범위

확정된 [정의 1](<../../전문가 에이전트 정의.md>)을 기준으로 [정의 2](<../../전문가 에이전트 정의 2.md>)와 [진행 계획](../../진행-계획.md)을 갱신했다. 정의 1은 수정하지 않는다. 기술 확인일은 2026-09-16이며 제품의 공식 문서·요금표·릴리스·저장소를 근거로 삼았다.

이번 결과는 문서의 구성·정합성과 공식 기술 자료에 대한 검토다. 실제 프로그램 구현, 해당 계정의 이용 가능 여부, 성능·비용 측정, 숙련 전문가와의 비교 시험을 완료했다는 뜻은 아니다.

## 유지·보완한 실행 조건

설명을 줄이면서도 다음 조건은 본문 또는 [실행과 데이터](../runtime.md)에 유지했다.

- 외부 요청의 결과를 모르면 원래 요청으로 조회·대조한다. 확인 전 새 요청으로 같은 거래를 반복하지 않는다.
- 병렬 작업은 성공한 부분을 보존하고 필수 결과의 합류 조건을 확인한다. 대기·재개·담당 변경 때 기존 비용·시도·약속을 이어받는다.
- 권한 철회는 대기·예약·재시도에도 반영한다. 사전 위임 안의 행동에 같은 승인을 반복해서 요구하지 않는다.
- 사용 비용에 진행 중·예약·결과 미확정 비용을 합산하고 검증·복구에 필요한 여유를 둔다.
- 지식의 원문·판본·적용 조건·예외·이견을 보존한다. 정정·철회는 파생 지식·결과·진행 건의 재검토로 이어진다.
- 원본의 구조·편집 기능·권리·연결 자산을 보존하고, 전달·인수·사후 성과를 따로 확인한다.
- 고객 경계를 검색·기억·캐시·로그·학습에도 적용한다. 삭제·철회는 파생물과 백업 복원까지 추적한다.
- 실행 종료·목표 달성·검증 결과·사후 성과를 다른 상태로 기록한다.
- 사람의 승인·서명과 전문 분석·수정을 구분하고 평가와 총비용에 포함한다.
- 개발에 사용한 사례와 공개하지 않은 평가 자료를 분리한다. 기존 사례 검토를 실제 전문가 구현·실증으로 세지 않는다.

## 업무 순서에 추가한 것

| 위치 | 보완한 단계와 이유 |
|---|---|
| 설계와 병행 | 자료·계정·이용 권리·보관 조건을 확보하고 핵심 연결을 작은 시험으로 확인. 개발 끝에 필수 접근 불가를 발견하지 않게 함 |
| 개발 전 | 비교 전문가·채점자·평가 자료·예산을 확보하고 합격 기준을 고정. 개발 자료와 새 평가 자료를 분리 |
| 설계 마무리 | 요구→재료→실행→검사→인수의 연결, 핵심 시험 결과, 미정 사항과 보완 담당을 함께 검토 |
| 개발 | 공통 기반, 단일 업무, 복합 업무를 나누고 권한·한도·실패·복구·모델 교체를 시험 |
| 운영 전 변경 시험 | 데이터 구조·규칙·도구·흐름을 바꿀 때 대기 중인 업무의 이전·종료·인계와 되돌림을 확인 |
| 공장 시험 | 요구가 다른 복수 직종을 같은 절차로 조립하고 추가 작업량·재사용 범위·기존 직종의 영향을 확인 |
| 배포 | 실제 자료·진행 건을 이전하고 담당·감시·지원·중지·복구·되돌림을 확인한 뒤 제한 운영에서 확대 여부 결정 |
| 운영·종료 | 실제 성과·지연 손실·사람 기여를 추적하고, 서비스 종료 때 미결 업무·약속·자료·계정을 인계·정리 |

시험용 직무의 조사·선정은 공통 기반 개발 전에 진행하고, 실제 운영할 첫 직종의 선정은 별도 판단으로 남겼다. 뒤늦게 확정되는 성과는 배포 이후에도 추적한다. 기존 진행 표시인 재료별 구상 완료와 사용 구조 설계 진행 중은 유지했다.

실제 계정·전문 도구 연결, 한국어 자료 검색, 중복 실행·권한 철회·복구, 모델 비교, 비용·부하, 숙련 전문가 비교는 진행 계획에 남아 있다. 이 검토만으로 제품 선정이나 전문가 대체 판정을 확정하지 않는다.
