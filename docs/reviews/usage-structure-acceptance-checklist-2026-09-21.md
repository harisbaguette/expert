# 사용 구조 완료 체크리스트

작성일: 2026-09-21. 대상: `전문가 에이전트 정의.md`의 `사용 구조`.

완료의 뜻: 처음 보는 독자가 상황별 하나의 Mermaid 안에서 **누가, 어떤 조건에서, 어떤 재료를 사용하고, 무엇을 받아 무엇을 만들며, 그 결과를 어디에 넘기는지** 따라갈 수 있다. 도형 수·명칭 수·문법 통과·교차 검사만으로 완료 처리하지 않는다.

아래 기준은 2026-09-21 수정본에 대조했다. 검토 범위와 근거는 마지막의 검사 기록에 남겼다. 이 문서는 검토용이며 본문의 순서도에 긴 설명이나 점검표를 추가하는 용도가 아니다.

## 먼저 인정해야 할 잘못

1. **목표 대신 쉬운 검사에 합격했다.** 사용자는 재료의 조합 관계를 원했는데, 재료 이름 79개와 연결 수를 확인하고 목표까지 충족한 것처럼 보고했다.
2. **일렬 나열을 없애면서 관계까지 감췄다.** 상시 재료를 순서대로 실행하는 오류를 고치다가, 실무 재료 22개를 카드 묶음으로 만들고 실제 연결을 생략했다. ‘필요한 재료만 조합’은 독자가 보고 싶었던 내용을 대신할 수 없다.
3. **설명이 해야 할 일을 독자에게 넘겼다.** 재료를 고르는 조건, 앞 결과를 다음 재료에 넘기는 방식, 실패 뒤의 행선지를 독자가 문구에서 추론해야 한다.
4. **상황 차이를 끝까지 펼치지 않았다.** 총괄과 전문가의 분담은 보이지만, 담당별 재료 사용과 중간 결과 교환은 큰 처리 상자에 남겨 두었다.
5. **검증 범위를 과장해 전달했다.** 렌더 검사와 재료 포함 검사는 통과했지만 이해도와 관계의 충분성은 별개의 문제였다. 최종 저장 전에 이 차이로 스스로 불합격시켰어야 했다.

- [x] **C2** 한 재료의 결과가 다음 재료의 입력이 되는 관계가 실제 연결로 드러난다. 무엇을 넘기는지 불분명한 선에는 짧은 전달 내용을 표시한다.

- [x] **C7** 회색 적용선을 쓰면 어느 동작에 어떤 재료가 어떤 역할로 적용되는지 명확하다. 실행·분기·결과 전달을 회색선이나 ‘함께 사용’이라는 문구로 대체하지 않는다.

## 4. 세 상황의 차이

- [x] **D1 단독** 한 전문가가 선택·실행·검증·수정·전달을 담당하며, 그 과정에서 재료가 어떻게 조합되는지 보인다.
- [x] **D2 오케스트레이션** 총괄이 정한 작업·입력·권한·완료 조건이 각 전문가에게 전달되고, 전문가별로 자기 재료를 적용하는 경로가 보인다.
- [x] **D3 오케스트레이션** 독립 작업의 병렬성과 선행 결과를 기다리는 작업의 의존성을 구별한다. 필요한 중간 결과가 어느 전문가에게 넘어가는지 보인다.
- [x] **D4 오케스트레이션** 결과 회수 뒤 누락·중복·이견·실패를 확인한다. 담당 보완과 분담·전략 변경의 행선지를 구별하며 일부 성공을 전체 성공으로 처리하지 않는다.
- [x] **D5 복합** 전체 총괄·건별 총괄·각 건의 전문가 역할을 구별한다. 여러 건을 순서대로 나열한 것으로 복합 처리를 대신하지 않는다.
- [x] **D6 복합** 건 사이 선행 결과·공유 조건·허용된 자원 공유·충돌·변경 영향을 다룬다. 검증된 결과·근거·버전이 후속 건으로 전달되고, 선행 결과가 무효이면 후속 실행이 차단·보완되는 관계가 보인다.

- [x] **E2** 해결되지 않는 충돌·권한 부족·한도 초과에는 허용 범위의 재계획, 유효한 사람의 결정, 보류·중단으로 이어지는 관계가 있다. 승인 거절 뒤 같은 실행을 우회하여 계속하지 않는다.

- [x] **E4** 안전·시험·변경 감시 등의 필수 동작이 단순 설명에 묻히지 않는다. 접촉 전 위험 확인, 통과한 판본만 사용, 규칙 분쟁 시 추적, 변경 영향을 받은 결과의 재검증이 필요한 곳에 적용된다.

## 이번 수정의 우선순위

먼저 C1–C7의 재료 관계와 D1–D6의 상황별 차이를 설계한다. 다음으로 E·F의 분기와 실패·복귀를 연결한다. 그 의미가 맞는 상태에서 G의 화면을 정리하고 H로 판정한다. 재료는 B로 전 과정에서 보존한다. 선과 폭부터 고친 뒤 의미를 끼워 맞추는 일을 반복하지 않는다.
