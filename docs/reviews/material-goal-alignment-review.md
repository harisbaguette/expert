# 계통별 재료의 목표 적합성 검토

검토일: 2026-09-14. 본문의 `계통별 재료` 9계통·53개 행 전체를 읽고, `docs/materials.md`의 M01–M55 전체와 대조했다. 목표·전문가 능력·업무 처리 흐름, 실행 계약과 평가 규약, 기존 배치 검토, 상세 구상의 항목 구성, SVG·HTML·그림 생성기도 함께 확인했다.

**판정: 구성 방향은 목표에 맞지만, 현재 문서 묶음 전체를 정의 완료로 판정하기에는 보완이 필요하다.**

판단·실행·검증·기억·개선의 담당 자리는 갖춰져 있다. 문제는 쉬운 설명으로 바꾸면서 중요한 책임과 합격 조건 일부가 약해졌고, 요약·세부 정의·그림 사이의 대응이 끊긴 것이다. 상당수 보완 근거는 이미 세부 문서에 있으므로 기존 책임을 명확히 연결하는 것으로 해결할 수 있다.

이 검토는 정의의 목표 적합성을 확인한 것이다. 53개 재료의 구현 성능이나 166개 직무의 실제 전문가 대체 능력을 실증한 결과가 아니다. 본문에 있던 작업 중 변경을 포함해 검토했으며, 기존 정의 파일은 수정하지 않았다.

R01 — 53개로 통합하는 구성 자체는 가능하다. 다만 현행 정본은 55개를 유지하고, 이름과 분류의 정본이라고 명시한다. 본문에는 안정적인 ID나 세부 정의로 가는 링크가 없다. 실제로 생성기의 `load_materials()`는 통과했지만 `validate_summary()`는 `본문에 정본에 없는 재료가 있습니다: AI 모델`에서 실패했다. 이 문제를 고쳐도 생성기는 본문을 4열로 가정하고 있어 6열 표 및 바뀐 계통명·이름의 대응을 함께 고쳐야 한다. SVG 내부 제목은 여전히 55개이며, HTML의 재료 표도 옛 이름을 사용하는 55행·4열이다. 이름의 별칭·통합·분리를 명시적으로 연결하고 생성·대조 계약을 함께 갱신해야 한다.

R02 — `변경 후 다시 시험`은 예전 시험의 재실행만 설명한다. 이것으로는 목표인 처음 보는 상황의 해결 능력을 확인할 수 없다. `결과물 평가`는 다른 평가자의 확인을 선택 사항으로 설명하고, `성과 추적`은 사람의 분석·수정 기여와 동일 조건의 전문가 비교를 설명하지 않는다. `반대 근거·다시 확인`도 다른 AI나 다른 방법이 같은 결론을 냈다는 사실과 독립적으로 타당성을 확인했다는 사실을 구별해야 한다. 기존 M43·M46·M49·M51과 evaluation.md의 기준을 간략히 연결해, 고정 시험·처음 보는 과제·검사자의 신뢰성·실제 성과·사람 기여를 모두 평가하도록 정의해야 한다. 외부의 사후 채점과 업무 중 사람의 수정도 구별한다.

R03 — `서버가 꺼졌다 켜져도 8건째부터 다시 처리`는 외부 상태와 저장 기록이 일치할 때의 예다. 외부 시스템에서는 8건째가 이미 처리됐는데 응답이나 저장만 유실될 수 있다. 마지막 기록 지점에서 바로 다시 실행하면 중복 처리 위험이 남는다. 현재 상태에 복원 책임을 합치더라도 ‘성공·실패·결과 불명 구별 → 외부 처리 여부 확인 → 중복 없이 재개’는 유지해야 한다. 또한 원천·요구·승인이 바뀌면 영향을 받는 결과와 이전 검사 통과를 무효화하고 다시 검증해야 한다. 세부 실행 계약과 기존 합성 모형은 이미 이 구분을 갖고 있다.

R04 — `결과를 상대가 바로 쓸 수 있게`라는 목표는 잘 잡았다. 그러나 하는 일과 비고는 전달 여부·수신 여부 확인까지 설명한다. 예를 들어 계산표 파일을 받았어도 수식을 바꿔 재계산할 수 없으면 업무 인수는 끝난 것이 아니다. 요구된 범위에서 열기·편집·재계산·재생·실행과 외부 상태를 확인하고, 전달·승인 대기·인수·사후 성과를 구별해야 한다. 매번 사람에게 확인을 요청한다는 뜻은 아니며, 위임된 완료 조건에 맞는 증거로 확인한다.

R05 — `지금 어떤 버전`과 `새 자료로 바꾼다`만 따르면 과거 건에 현재 자료를 적용하는 해석이 가능하다. 현재 시세가 필요한 경우와 과거 시점의 계약·규정·가격을 복원해야 하는 경우를 구별해야 한다. 원래 자료를 보존하고 관측 시점·효력 시점·대상 업무에 맞는 판본을 선택한다. 공식 원천 여부와 그 내용이 실제 사실인지도 별도 확인이 필요하다. 이 책임은 기존 M18·M20 안에서 보완할 수 있다.

R06 — `업무 지식`이 기본 원리를 아는 것, `실전 경험·감각`이 일을 많이 하며 생기는 판단력이라는 설명은 이해하기 쉽다. 에이전트를 구성하려면 여기에 숙련자의 판단 단서·버린 대안·선택 이유·적용 한계·판단을 바꿀 조건을 확보해 실제 업무에 쓰는 연결이 필요하다. `부족한 능력 보완`도 도구나 지식을 확보하는 데서 끝내지 않고, 실제 작업·새 과제·기존 기능 검증을 통과한 뒤 적용하고 잘못된 변경을 되돌릴 수 있게 해야 한다. 자신의 성공 경험만으로 판단 규칙을 강화하지 않도록 근거와 결과를 검토한다. 이 내용은 M21·M22·M50에 이미 있어 새 재료를 만들 필요가 없다.

R07 — `필요한 업무만`이라는 요약에는 무엇을 보고 필요하다고 판단하는지, 조건을 모르면 어떻게 하는지가 없다. 조건이 참이면 필수이며, 불명이면 확인할 자료·진단과 해당 경로의 대기를 연결해야 한다. 진단 자체를 본 조건이 확인될 때까지 기다리게 해서는 안 된다. 공통 정의·직무 정의·개별 위임을 적용하는 방법도 연결해야 한다. 본문에는 쓰는 법을 짧게 안내하고 materials.md·runtime.md의 기존 조립 계약으로 연결하면 된다. 기술 필드를 모두 본문에 복사할 필요는 없다.

R08 — 환경 설명은 ‘무엇을 알고 어떻게 판단하는지가 아니라 … 장치’라고 하지만 바로 아래 AI 모델의 책임은 판단이다. 환경에 판단 엔진과 실행 기반을 둔다는 설명으로 맞추는 편이 일관된다. `업무 도구·시스템`은 도구 연결·실행 결과 반환과 실무의 제작·계산 책임을 구별하면 더 명확하다. `심사·승인 기준`도 현재 M13의 좁은 별칭이므로, 제출하지 않는 서비스 운영 중 적용되는 정책·계약 원문을 어디서 확보하는지 M28과 함께 연결해야 한다.

**범위에 관한 추가 확인**

현재 목표는 화면·문서·시스템·통신 안에서 끝나는 업무다. 그런데 세부 정의 M40에는 시공물·시술·공연의 현장 인도·시운전까지 남아 있다. 온라인 업무와 직접 현장 수행을 구별하고, 후자를 다룰 계획이 있다면 향후 범위로 표시해야 한다. 도면 검토·구조 계산·영상 편집처럼 컴퓨터 안에서 수행하는 예시는 현재 범위와 양립한다.

**실행한 확인과 한계**

| 확인 | 실제 결과 | 증명하는 범위 |
|---|---|---|
| 본문 표 구조 | 9계통·53행, 모든 행 6열, 이름 중복 없음 | 구조·개수 |
| 적용 구분 | 상시 17·단계별 14·조건부 22, 합계 53 | 표시의 완전성 |
| 세부 재료 ID | M01–M55 누락·중복 없이 55개 | 세부 정본 내부 구조 |
| 생성기의 본문 대조 | AI 모델 이름에서 ValueError 재현 | 현재 본문으로 그림을 재생성하는 기존 경로가 실패함 |
| SVG 내용 | 내부 제목 55개, 저장·이어받기·현황 자료 등 기존 이름 유지 | 본문과 설명·표기의 차이 |
| HTML 내용 | 세부 정본 이름에 대응하는 55행, 각 4열 | 최신 본문과 다른 내용·표 구조 |
| 기존 합성 계약 모형 재실행 | 8개 모형·42개 구성·계약 생략 비교군 반례 19개, 기존 JSON과 일치 | 열거된 가상 구성의 계약 검사 |

합성 모형은 기존 함수를 메모리에서 호출해 실행했고 원래 결과 JSON은 덮어쓰지 않았다. 여기에는 은행 응답 유실, 변경 전파, 공동 일정, 통합 전략, 결합 손실, 삭제 후 재처리, 도구 지원, 조건 판정의 순환 대기가 포함된다. 이 결과로 현재 요약의 누락이 자동 검증된 것이거나 실제 AI 성능이 입증됐다고 해석하지 않는다.

기본 `python3`의 XML 모듈은 로컬 라이브러리 연결 오류가 있어 SVG·HTML 확인은 `/usr/bin/python3`로 완료했다. 이는 이 문서의 결함에 포함하지 않았다. 화면 렌더링 품질과 실제 외부 도구 연동·전문 업무 실행은 이번 검토에서 시험하지 않았다.

2026-09-11의 계통 배치 검토는 당시 판본의 기록이다. 당시의 55개 일치 판정을 현재 53개 본문의 검증 결과로 재사용할 수 없다.
