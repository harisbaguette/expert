# 계통별 재료의 5축 비판 검토

검토일: 2026-09-15. 대상: 사용자가 말한 ‘정의 1’에 해당하는 [전문가 에이전트 정의.md](../../../전문가%20에이전트%20정의.md)의 현재 작업본, [재료 상세](../../materials.md), [실행 계약](../../runtime.md), [평가 규약](../../evaluation.md).

## 결론

**9계통은 공통 설계의 기준으로 유지할 만하다. 그러나 현재 문서를 최종 완성본으로 동결하거나, 이 재료들이 166개 전문가와 모든 복잡한 사건을 대체하기에 충분하다고 판정할 수는 없다.**

새 계통이나 M58을 반드시 추가해야 하는 독립 책임은 이번 검토에서 확인하지 못했다. 대신 이미 있는 책임을 실제 흐름에 연결하지 못한 곳, 하위 책임의 상태를 구분하는 규약이 덜 명확한 곳, 목표와 대체 판정이 어긋나는 곳이 확인됐다. 이는 단순히 ‘실험을 더 해 봐야 한다’는 문제에 앞서 고쳐야 할 정의 문제다.

| 사용자 질문 | 판정 | 이유 |
|---|---|---|
| 나누거나 합쳐야 하나 | 계통은 유지. 하위 책임의 독립 관리와 경계 보완 필요 | 본문에서 나눈 책임이 상세에서는 하나의 ID에 묶인다. 업무 단계·적용 조건·실행 시점도 구별해야 한다 |
| 업무 프로세스에서 빠졌나 | 큰 단계는 있다. 변경·불명·대기 경로에 누락이 있다 | 재료·실행 계약에 있는 책임 일부가 본문 순서도에서는 우회되거나 표현되지 않는다 |
| 목표로 보면 빠졌거나 틀렸나 | 대체 판정과 직무 범위에 수정이 필요하다 | 무개입·서명·검사 기록만으로 전문성과 성과를 입증할 수 없고, 직업 전체와 온라인 과업은 범위가 다르다 |
| 범용적으로 166개 전문가를 대체하나 | 공통 틀로 사용할 수 있다는 가설은 타당. 대체 능력은 미입증 | 직무별 지식·방법·도구·데이터·평가가 실제로 채워졌다는 증거가 없다 |
| 전문가별 복잡한 사건을 전부 해결하나 | 보장할 수 없다 | 목표가 양립하지 않거나 핵심 증거가 없거나 외부 결정에 달린 사건도 있다. 적절한 대응과 목표 달성은 구별해야 한다 |

## 1. 확인한 범위와 증거의 수준

본문 재료 행을 집계하면 다음과 같다.

| 계통 | 본문 설명 항목 |
|---|---:|
| 환경 | 10 |
| 자료·검색 | 11 |
| 지식·경험 | 2 |
| 기억·진행 상태 | 2 |
| 규칙·권한 | 11 |
| 행동 체계 | 5 |
| 실무 | 8 |
| 검증·평가 | 8 |
| 학습·개선 | 2 |
| 합계 | 59 |

세부 책임은 M01–M57이며, 본문과의 59 대 57 차이는 [대응표](../../materials.md#본문과-세부-책임의-대응)에 설명되어 있다. 숫자가 다르다는 것 자체는 결함이 아니다. 본문 표 밖의 M41 업무 처리 흐름도 포함해 검토했다.

직무 검토 CSV와 동적 모의 CSV는 각각 166행이고, 직무별 파일도 166개다. 위임형 58·고용형 80·운영형 28이라는 목록 구성과 모의 결과 집계를 확인했다. 복잡성 대조에는 법률·세무·감사·구조·의료·상담·통역·채용·운용·영업·게임·펌웨어·AI·보안·UX·생산·연구·소설·음악·SaaS·임대의 21개 사례를 상세 표본으로 읽었다. 166개 직무의 모든 세부 과업을 독립적으로 실증한 검토는 아니다.

기존 모의의 결과는 종결 경로 72·외부 결과 대기 60·목표 조정 34다. **성공률이나 대체 가능한 직무 수가 아니다.** 작성자가 사건과 응답을 가정한 탁상 모의의 분류다. [기존 실험의 한계](../직무/occupation-dynamic-simulation.md#전개-방식).

법률 심층 실험도 24개 검사 통과를 보고하지만, 실제 은행·법원·독립 법률 전문가를 호출한 시험이 아니며 핵심 법률 판단의 미완료를 명시한다. 검사 개수를 전문 사건 해결 건수로 읽을 수 없다. [법률 실험 판정](../../실험%20결과/법률%20복합사건%20심층%20실험/05_실험결과와_보완판정.md).

이번에 실행한 검사는 문서 행·CSV 집계와 Mermaid 방향 그래프의 경로 탐색이다. 실제 에이전트·외부 시스템을 시험하거나 기존 실험을 새 성능 시험으로 재실행하지 않았다.

## 2. 나누거나 합칠 것

### 계통은 유지한다

자료 확보, 재사용 전문 지식, 사건 상태, 의무·권한, 선택·계획, 실제 수행, 검증, 지속 개선은 서로 다른 책임이다. 행이 적다는 이유로 지식·경험과 기억을 합치거나, 같은 기록을 쓴다는 이유로 상태·감사·성과를 합칠 근거는 약하다. 자료형과 프로그램이 같아도 책임은 다를 수 있다.

다만 9계통은 책임을 찾기 위한 분류다. 반드시 9개 실행 서비스나 고정된 처리 단계로 구현해야 하는 구조는 아니다. 같은 함수·저장소를 공유해도 결정 책임과 검사 증거를 구분하면 된다.

| 대상 | 권고 | 이유·필요 보완 |
|---|---|---|
| M10 도구 연결 / 격리 실행 | 하위 책임을 독립 관리 | 접속 성공이 격리 성공을 뜻하지 않는다. 두 책임의 적용·실패·검증 상태를 따로 표현해야 한다 |
| M18 근거 신뢰성 / 시점·판본 | 분리한 본문 유지, 하위 검사 식별 | 최신 자료도 거짓일 수 있고, 신뢰할 수 있는 자료도 해당 시점에는 적용되지 않을 수 있다 |
| M27 법·의무 / 직업 윤리·의무 | 분리 유지, 겹치는 의무는 같은 근거 참조 | 적용 근거·역할·예외가 다르다. 중복 의무를 두 번 정의할 필요는 없다 |
| M28 계약 / 플랫폼·제출처 규정 | 분리 유지, 변경권과 판본 독립 관리 | 의뢰인이 바꿀 수 있는 계약 조건과 외부 서비스의 조건을 혼동하면 안 된다 |
| M54 실제 실험 / 모의 시험 | 분리 유지, 증거·지원 상태 분리 | 모의 상대와의 협상 성공이 실제 상대의 수락을 증명하지 않는다 |
| M03 저장·복원 / M25 사건 상태 | 본문 통합 설명은 허용, 세부 책임은 유지 | 저장 복원 성공과 업무상 올바른 상태 복원은 서로 다른 검사다 |
| M12·M13 규칙 원문 | 공통 확보·판본 코드 공유 가능 | 법령·기관·플랫폼별 출처 차이를 지우는 통합은 필요 없다 |
| M21 업무 지식 / M22 숙련 사례 / M34 판단 / M35 계획 | 책임 유지, 구체 입출력 연결 | 아는 원리, 사례의 적용 조건, 이번 선택, 이번 작업 순서는 다르다 |
| M42 결과 검증 / M46 결과물 평가 | 유지, 검사 중복 정리 | 요구 위반·결함 검출과 전문가 수준·목적 적합성 평가는 구별된다. 같은 기능 검사는 유효한 증거를 재사용할 수 있다 |
| M37 업무상 감지 / M57 운영 감시 | 분리 유지 | 고객의 기회·기한과 에이전트 자체의 장애는 감시 대상과 복구 책임이 다르다 |
| M50 능력 보완 | 유지, 미해결 업무의 포괄 담당으로 쓰지 않음 | 능력 부족을 기록하거나 도구를 추가한 사실만으로 전문성이 생기지 않는다 |

### 하위 책임 상태의 규약을 닫아야 한다

[재료 상태 형식](../../materials.md#쓰는-법)은 `id`와 `implementation_status`, `evidence` 등을 제시한다. 반면 M10·M18·M27·M28·M54는 하위 책임을 별도로 추적하라고 한다. 방향은 맞지만, 같은 ID 아래 상반된 상태를 어떻게 식별·집계할지까지는 명확하지 않다.

예를 들어 M54의 모의 시험만 검증됐는데 실제 실험도 지원한다고 읽히면 안 된다. 상위 ID는 유지하더라도 **하위 책임 식별자 + 지원 범위 + 적용 조건 + 담당 + 구현 상태 + 증거**를 별도로 기록하고, 상위 합격은 이번 업무에 필요한 하위 책임의 합격으로 계산해야 한다. 새 번호를 늘리는 것보다 이 규약을 정하는 편이 정확하다.

### 적용 여부와 언제 수행하는지를 분리해야 한다

본문·대응표의 ‘사람에게 넘기기’는 상시지만 상세 M39는 조건부다. ‘자료 찾기’도 본문은 단계별, 상세 M19는 조건부다. 회사·계약 규칙 역시 적용 조건과 유지 시점이 서로 다른 관점으로 섞여 있다.

이는 모두 같은 종류의 오류라는 뜻은 아니다. ‘조건을 확인하는 책임은 계속 유지하고 실제 이관은 필요한 때만 한다’면 양립할 수 있다. 다만 현재 표는 그 해석을 구현자에게 맡긴다. 이미 있는 `applicability`와 활성 조건에 더해, 해당 책임의 **수행 시점·재검토 신호**를 분리해 연결해야 한다. 두 표가 다른 동작을 만들지 않아야 한다.

## 3. 업무 프로세스에서 실제로 빠진 연결

문제 정의·의도 파악·정보 가치·협상·성과 귀속·능력 부족 대응은 이미 있다. 이를 새 재료의 누락으로 다시 지적하는 것은 부정확하다. 아래는 본문 순서도와 상세 계약 사이에서 확인한 구체적인 차이다.

| 발견 | 본문 순서도의 근거 | 반례와 보완 |
|---|---|---|
| 요청의 긴급도 확인 우회 | `REQ → CASE_TYPE → INTAKE_CHECK`; 신호만 `HARM`으로 진입 | ‘지금 중복 결제가 계속된다’는 직접 요청도 긴급도 판정이 필요하다. 진입 경로별 분류를 공통 긴급도·권한 검사로 연결해야 한다 |
| 기존 건의 새 자료·권한 재검토 우회 | `LOAD_CASE → CASE_CHANGED → OPTIONS`, 변경 질문은 목표·업무 범위만 확인 | 목표는 같아도 증거가 정정되거나 위임이 철회될 수 있다. 사실·권한·규칙·환경·의존 변경을 검사해 영향을 받는 단계로 돌아가야 한다 |
| 실행 결과가 두 갈래뿐 | `EXEC_FAIL`의 예/아니오 뒤 복구 또는 결과 확인 | 응답 유실·일부 성공은 확정 실패와 다르다. [M56 계약](../../runtime.md#시스템-처리실행의-계약)의 성공·확정 실패·불명·일부 성공·취소 상태를 연결해야 한다 |
| 대기에서 반복 요청으로 돌아가는 경로 | `INTENT_WAIT → INTENT_ASK`, `DECISION_RECEIVED → ESCALATE → DECISION_RECEIVED` | 응답이 없는 의뢰인·마지막 승인권자를 만나면 기한 만료·대체 담당·제한적 계속·중단 상태가 필요하다. 다음 승인자가 항상 존재한다고 가정하면 안 된다 |
| 결과 전달 뒤 무응답 경로 부재 | `RESPONSE`에 완료 확인·새 요청·수정 요청만 있음 | 의뢰인이 답하지 않아도 이미 정한 자동 인수 조건에 따라 완료하거나, 합의한 기한까지 대기·미완료로 기록할 수 있어야 한다 |

행 번호 기준으로 직접 요청의 우회는 본문 588–619행, 기존 건의 우회는 614–658행, 실행의 이분법은 686–696행, 대기는 632–639·681–685행, 전달 후 응답은 725–728행에서 확인했다.

이 결과는 **도식을 그대로 실행 명세로 삼을 때 생기는 누락**이다. 실제 구현이 이러한 결함을 일으켰다는 관측은 아니다. 상세 규약은 상당 부분을 이미 다루므로 신규 계통을 만들 필요 없이 M06·M18·M25·M31·M35·M39·M40·M41·M56의 연결을 본문에도 일치시키면 된다.

단계별로 남겨야 할 핵심 결과도 명확해야 한다.

| 업무 단계 | 핵심 결과 | 주 책임 |
|---|---|---|
| 접수·의도·문제 정의 | 원하는 성과, 막는 원인, 하지 않을 일, 결정권, 미확인 조건 | M17·M31·M34·M36·M38 |
| 자료·가설 | 사실·주장·가설·대안 설명, 결론을 바꿀 증거와 확보 방법 | M07·M18·M19·M21·M22·M34 |
| 판단·설계 | 목표 우선순위, 대안, 선택 이유, 조건별 다음 행동 | M34·M35·M36 |
| 전문 수행 | 실제 산출물 또는 외부 상태 변화 | M09·M38·M52–M54·M56 |
| 검증·재계획 | 결함, 전제 변경, 영향받는 판단·파생물·검사 | M25·M42–M46 |
| 인수·성과·종료 | 인수 증거, 남은 의무, 실제 성과, 사람 기여 | M36·M40·M47·M51 |

## 4. 목표 기준으로 틀리거나 모호한 부분

### 대체 판정 도식의 합격 조건이 부족하다

본문 ‘대체의 뜻’ 도식은 사람 개입, 자격자 수정·서명, 완료 조건, 기계 확인, 기록 여부를 검사한 뒤 ‘대체다’에 도달한다. **숙련 전문가와의 품질·성과 비교, 총비용·기한, 장기 성과가 이 경로의 명시적 관문에 없다.**

틀린 완료 기준을 설정한 에이전트도 그 기준만 자동 검사하면 이 도식에서는 통과할 수 있다. 또한 ‘판단이 안 서서 사람을 부름’을 예외로 돌려 대체 판정에서 제외하면, 어려운 일을 사람에게 넘길수록 분모가 쉬워지는 문제가 생긴다.

상세 [평가 규약](../../evaluation.md#최종-합격과-주장)은 이 문제를 이미 처리한다. 범위·절대 품질·인간 비교·자율성·비용·기한·지속성 관문을 본문 판정에도 반영하고, 승인·사실 응답·전문 판단 보충을 구별해 기록해야 한다. 사람을 부를 사유가 정당하다는 것과 AI가 그 사건을 독립 해결했다는 것은 별개다.

### 전문가를 가르는 설명과 실제 목록이 어긋난다

본문은 조언·심사·감사·교육·소개를 하는 역할을 전문가 바깥으로 설명하면서, 목록에는 회계사 감사·전략·채용·상담 등이 들어 있다. 성과는 문서나 물건뿐 아니라 판단·평가 의견·교육·행동 변화로도 정의될 수 있다. 현재 실무 M38과 평가 규약도 이를 인정한다.

전문가의 기준은 ‘결과물이 물건처럼 나오는가’가 아니라 **해당 판단과 수행의 품질에 책임지고, 그 업무에 맞는 성과를 낼 수 있는가**로 정합시켜야 한다. 166이라는 숫자는 선정한 목록의 크기이며 전문 업무 전체를 빠짐없이 포괄한다는 증거가 아니다.

### 온라인 과업 대체와 직업 전체 대체를 구별해야 한다

현재 목표는 화면·문서·시스템·통신 안에서 끝나는 업무다. 그런데 직무 사례에는 현장 실측·실기기 시험·실제 진료·생산 현장 실행·수선처럼 이 범위를 넘는 의존도 있다. 과거 기록은 범위 변경 전의 가정을 보존하고 있으므로, 그 기록 전체를 현재 지원 범위로 읽으면 안 된다.

각 직무 아래 ‘원자료가 제공된 분석·설계’와 ‘새 현장 사실을 만들어 내는 수행’을 구별해야 한다. 외부 인력에게 일을 맡겼다는 이유만으로 그 부분까지 AI의 독립 수행으로 포함할 수 없다. 이 조건은 재료를 추가해 해결할 문제가 아니라 대체 주장의 대상 범위를 정할 문제다.

### 구성 개념식은 성능 방정식이 아니다

`환경 × 지식 × 규칙 × 실무 × 검증 × 학습`은 필요한 요소의 관계를 설명하는 비유로 사용할 수 있다. 측정 단위·함수·조건이 정의되지 않은 상태에서는 성능을 계산하거나 충분성을 증명하는 식이 아니다.

[과거 바깥조사 종합](../../바깥조사/바깥조사-종합-수식대조.md)은 현장 실패가 곱셈식을 ‘실증’했다고 주장한다. 실패 사례를 여섯 상자 중 하나에 넣을 수 있다는 관측으로 특정 수학적 결합 법칙을 검증할 수는 없다. 특히 현재 학습·개선은 조건부인데, 한 번의 정해진 업무에서도 학습 실행이 없으면 전체 능력이 0이라는 해석은 맞지 않는다. 지속 개선의 필요성과 매 건 모든 기능의 실행은 별개다.

### 기준선 확정의 근거 기록이 끝나지 않았다

[기준선 검토 파일](material-baseline-review.md)은 통과 기준과 초기 발견을 적고 ‘검토와 보완 결과는 아래에 기록한다’에서 끝난다. 반면 본문·재료·평가는 이 파일을 기준선 판정 근거로 참조한다. 현재 작업본에서는 **무엇을 검사했고 어떤 반례가 해결됐으며 무엇이 남았는지**의 최종 기록이 비어 있다. ‘정의 확정’ 표시가 그 증거를 대신할 수 없다.

## 5. 166개 전문가를 대체하는 범용성

범용성을 세 가지로 나눠 판단해야 한다.

| 범용성 | 현재 판단 |
|---|---|
| 다양한 일을 이 구조로 설명할 수 있는가 | 검토한 직무·사건의 책임을 배치할 수 있다. 공통 설계로 쓸 근거가 있다 |
| 공통 구성과 직무 내용을 조립해 실제로 실행할 수 있는가 | 계약은 있지만 직무별 내용·연동·누락 없는 조립의 실증은 별도다 |
| 조립한 에이전트가 숙련 전문가를 대체하는가 | 해당 업무 분포·환경·기간에서 인간 비교와 무전문개입 성과가 필요하다. 현재 기록은 이를 입증하지 않는다 |

‘업무 지식’ 항목이 있다는 것은 각 직업의 전문 지식이 채워졌다는 뜻이 아니다. ‘실전 경험’ 항목도 20년 경력의 숙련성을 담았다는 증거가 아니다. 도구 사용 성공과 해당 분야에서 좋은 전략을 고르는 능력도 별도다.

직무별 핵심은 달라진다. 법률은 요건·주장·증거·절차, 감사는 주장별 증거 충분성, 상담은 사례 이해·개입·관계 변화, 구조는 모형·하중·경계조건, 창작은 표현 의도·구성·일관성, 운영은 고객·현금·가동·장기 의사결정이 필요하다. 공통 재료가 이러한 내용을 넣을 자리는 제공하지만 내용을 자동 생성·검증해 주는 것은 아니다.

따라서 권고할 주장은 **‘166개 직무의 온라인 과업을 구체화할 공통 구조’**다. 실제 대체 주장은 다음 단위로 증거를 붙여 확장해야 한다.

`직무 × 세부 과업 × 난도 × 관할 × 입력 조건 × 도구·모델·환경 판본 × 위임 조건`

## 6. 복잡한 사건을 전부 해결할 수 있는가

‘잘 대응할 수 있음’, ‘맡은 범위를 완료함’, ‘의뢰인이 원하는 외부 결과를 얻음’은 다른 판정이다. 서로 양립하지 않는 목표, 접근할 수 없는 핵심 사실, 상대방의 거절, 기관의 결정, 시간·자원 제약은 재료 목록으로 제거되지 않는다. 성공을 보장할 수 없는 사건에서 불확실성을 밝히고 좋은 대안을 고르는 것도 전문 수행이지만, 이를 원래 목표의 성공으로 바꾸면 안 된다.

다음은 이번 검토에서 구성한 추가 시험 요구다. **실행 성적이 아니라 앞으로 탈락을 판정할 반례 조건**이다.

| 복합 반례 | 관련 재료 | 반드시 구별할 실패 |
|---|---|---|
| 같은 목표를 진행하다 핵심 증거 정정과 위임 철회가 동시에 도착 | M18·M25·M27·M31·M35 | 목표가 안 바뀌었다는 이유로 이전 판단·권한 재사용 |
| 요청자가 직접 알린 진행 중 사고 | M06·M31·M37·M41·M57 | 요청 진입 경로에서 긴급도 확인 누락 |
| 송금 응답 유실 뒤 승인 철회·멱등 키 만료·일부 반환 | M03·M31·M33·M42·M56 | 불명을 실패로 처리해 재송금하거나 보상 권한을 자동 가정 |
| 새 조합에서 모의 시험만 통과, 실제 수행은 미검증 | M10·M35·M49·M50·M54 | 상위 재료의 verified를 미검증 하위 작업에 전이 |
| 법무·회계·자금이 각자 좋은 안을 내지만 공통 현금 제약 위반 | M25·M33·M34·M35·M53 | 개별 정답을 합쳐 전체 정답으로 간주 |
| 승인권자가 끝까지 답하지 않고 다음 승인권자도 없음 | M06·M25·M35·M39 | 무한 요청·대기 또는 응답 부재를 승인으로 해석 |
| 전문 도구는 정상이나 입력 모형·문제 정의가 틀림 | M21·M22·M34·M43·M46 | 계산·렌더·빌드 성공을 전문 판단 성공으로 처리 |
| 상담·영업에서 상대 반응이 예측과 다르고 동의하지 않음 | M22·M34·M38·M46·M51 | 유창한 대화나 모의 상대의 수락을 실제 행동 변화로 처리 |
| 실시간 통역에서 숫자·부정어가 불명확하고 검증 기한이 짧음 | M07·M08·M38·M42 | 사후 문장 정확성으로 실시간 오역·지연을 가림 |
| 장기 운영 중 조건이 바뀌고 드문 손실이 뒤늦게 드러남 | M20·M24·M25·M33·M49·M51·M57 | 단기 평균 성과로 장기 실패·사람 기여·비용을 누락 |

이 반례들 역시 현재 책임에 배정할 수 있다. 그러나 **배정할 수 있다는 사실은 해결 알고리즘이 있고 작동한다는 증거가 아니다.** ‘정의가 포괄한다’는 주장을 확인할 때에도 입력·판단·실행·외부 확인·실패 후 다음 담당까지 구체화해야 한다.

## 7. 최종안으로 확정하기 위한 권고

구조는 9계통을 유지하되 다음 작업을 완료한 뒤 기준선을 확정하는 편이 타당하다.

1. 본문의 대체 판정을 상세 평가 규약과 일치시킨다. 정당한 이관도 전문 기여·원래 배정 건수에서 숨기지 않는다.
2. 기존 건 재개, 직접 요청의 긴급도, 불명·부분 성공, 무응답·기한 만료 경로를 업무 흐름에 연결한다.
3. 나눈 하위 책임의 상태·증거·지원 범위와 적용 조건·수행 시점의 관리 규약을 확정한다.
4. 직무별 온라인 과업의 포함·제외·외부 의존을 명시하고, 실제 전문 지식·방법·도구·검사 내용을 채운다.
5. 기준선 검토에 실제 결과와 남은 반례를 기록한다. 기존 탁상 모의와 새 구조 검사의 판본을 구별한다.
6. 이후 직무별 보호된 새 과제와 숙련 전문가 비교로 능력을 검증한다. 실제 목표·전문 개입·비용·지연 성과를 함께 평가한다.

외부 평가 자료도 같은 구분을 뒷받침한다. Anthropic의 [에이전트 평가 설명](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)은 대화 기록과 실제 환경의 최종 상태를 구분하고, 과업에 맞는 코드·모델·사람 평가와 반복 시도를 설명한다. NIST의 [유효성·신뢰성 설명](https://airc.nist.gov/airmf-resources/airmf/3-sec-characteristics/)은 명시한 사용 조건에서의 객관적 증거와 지속적인 시험·관측을 요구한다. 이 자료들이 현재 9계통이나 57개 책임의 완전성을 보증하는 것은 아니다.

**최종 판단: 계통의 큰 방향은 유지할 수 있다. 현재 남은 일은 일부 책임의 세분 관리, 업무 흐름의 연결 보완, 대체 판정의 정합화, 직무별 실제 전문성의 충족이다. ‘완벽한 재료이므로 모든 사건을 해결한다’는 결론은 성립하지 않는다.**
