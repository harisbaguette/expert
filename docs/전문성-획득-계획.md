# 전문가 노하우 획득 체계 — 착수 계획

작성: 2026-10-20 · 대상: 기존 전문가 공장의 전문성 획득 부분  
현재 완료: 목표·범위, 기존 직무 연결, 입력별 기술 구성안, 우선 분야와 작업 순서  
남은 실행: 입력별 기술 연구의 구체화, 추출기 개발, 공통 스킬·에이전트 제작, 분야별 지식·실무 연결

## 1. 무엇을 만들 것인가

**분야나 전문가의 결과물·자료를 주면, 필요한 지식과 설명되지 않은 노하우를 확보해 실제 일을 맡길 수 있는 전문가를 만드는 공통 기능**을 만든다. 최종 목표는 기존 정의의 20년차급 업무 수행 능력이다.

사용자가 “분석 방법은 이것으로 하라”, “이 자료도 찾아라”라고 지시하지 않아도 입력을 살펴 필요한 방법과 추가 자료를 고르게 한다. 결과물에서 알아낸 방법, 책·강의에서 얻은 지식, 실제 작업 중 얻은 경험을 함께 쌓는다.

지금 만들어야 할 것은 여섯 묶음이다.

| 만들 것 | 끝났을 때 생기는 것 |
|---|---|
| 공통 노하우 역설계 스킬·에이전트 | 분야와 자료를 받으면 조사·분석 방법을 고르고 전문 지식을 만드는 담당과 작업 방법 |
| 입력 종류별 분석 방법과 실행 도구 | 개발물·사이트·글·영상·편집 원본·통계 등에서 노하우를 얻는 경로 |
| 원본·근거·지식 저장 구조 | 알아낸 내용이 어디서 나왔고 언제·어디에 통하는지 찾는 저장소 |
| 실무서·실행 스킬 제작 기능 | 지식을 실제 작업 순서·도구·템플릿·예외 대응으로 바꾸는 기능 |
| 우선 분야별 전문성 묶음 | 네이버·구글 SEO, 블로그·사이트, 유튜브, 광고, SNS, 전략, 전자책의 지식과 실행법 |
| 경험 축적과 확장 기능 | 일을 하다 얻은 수정·복구 요령을 다음 작업과 다른 분야에서 재사용하는 기능 |

스킬과 에이전트의 이름을 만드는 것과 전문성이 갖춰지는 것은 상태를 따로 기록한다. 조사한 기술도 실제 연결·실행 전에는 구현 완료로 표시하지 않는다.

정의의 직무 166개와 직무별 문서 166개의 ID·파일 대응을 확인했다. 직무별 본문을 모두 심층 검토한 것은 아니다. 읽은 마케팅·블로거·유튜버 사례는 **작성자의 탁상 모의**라고 명시되어 있으므로, 실제 전문가의 작업 기록이나 이미 확보한 노하우로 계산하지 않는다.

기존 공장 초안의 시험용 첫 직종 선정은 이 계획으로 변경하지 않는다. 사용자가 이번에 지정한 마케팅·콘텐츠 분야를 **전문성 획득의 우선 대상**으로 추가한다.

## 3. 입력에 따라 어떻게 다르게 할 것인가

단순 파일 확장자만으로 방법을 고정하지 않는다. 다음 세 가지를 함께 본다.

- 무엇이 들어 있는가: 완성품, 설명 자료, 편집 구조, 행동, 시간 변화, 성과.
- 얼마나 관찰할 수 있는가: 최종 결과만, 여러 결과, 원본, 실행 가능, 상세 기록.
- 무엇을 배워야 하는가: 제작법, 선택 기준, 품질 감각, 운영법, 예외·복구.

한 자료에 여러 방법을 사용할 수 있다. 완성 영상은 장면·편집 분석을 하고, 그 영상의 편집 원본은 타임라인·효과를 분석하고, 채널 통계가 있으면 시청 반응과 연결한다.

## 4. 공통 스킬과 에이전트의 구체적인 역할

제작할 기본 구성은 **공통 스킬 1개 + 책임을 가진 에이전트 1개 + 입력별 방법·실행 모듈**이다. 처음부터 직무 166개마다 새 에이전트를 만들 필요는 없다. 서로 함께 일해야 하는 분야는 기존 담당을 강화하고 필요한 전문성 묶음을 연결한다.

| 구성 | 제안 이름 | 책임 |
|---|---|---|
| 공통 스킬 | kh-skill-expertise-extraction | 입력별 분석 방법, 자료 확보, 노하우 추출, 근거·조건·예외 정리, 지식 인계 방법 |
| 에이전트 | kh_team_expertise_extraction | 받은 분야·대상에서 필요한 노하우를 확보하고 부족한 부분을 찾아 보완하는 일의 책임 |
| 방법 자료 | references/ 아래 입력별 문서 | 실제 받은 입력에 해당하는 부분만 읽음 |
| 실행 코드 | parser·분석·저장·변환 모듈 | 반복 가능한 파일·수치·로그 처리를 수행 |
| 분야별 묶음 | P01~P18 | 특정 분야의 능력 목록·자료·방법·실무서·스킬·도구 |

### 받을 것과 돌려줄 것

입력은 분야 또는 전문가, 결과물·자료, 배우려는 능력, 실제 업무 목적이다. 사용자가 모두 적지 않아도 대화와 파일에서 직접 확인할 수 있는 것은 찾는다.

결과는 다음으로 구성한다.

1. 실제 확보한 원본과 근거 위치.
2. 알아낸 개념·제작법·판단 기준·품질 기준·조건·예외.
3. 아직 여러 설명이 가능한 가설과 다음에 필요한 자료.
4. 사람이 읽는 실무서.
5. AI가 사용하는 실행 스킬·스크립트·템플릿.
6. 어떤 업무에 적용했으며 무엇이 부족한지의 기록.

### 언제 선택되는가

- “이 사람의 결과물에서 일하는 방법을 알아내라.”
- “이 프로그램·사이트·영상의 제작 노하우를 얻어라.”
- “이 분야 전문가를 만들기 위해 필요한 전문성을 확보하라.”
- “자료와 사례는 있는데 AI가 실제 일을 잘하지 못한다. 부족한 방법을 찾아라.”

이미 준비된 분야에서 일반 콘텐츠나 프로그램을 만드는 요청은 해당 제작 담당이 처리한다. 그 과정에서 전문성이 부족하면 이 획득 경로를 이용한다.

### 기존 담당과의 관계

- kh-skill-expertise: 분야 역량 전체를 구축·고도화하는 기존 입구. 새 역설계 경로와 자료 축적 경로를 함께 사용할 수 있게 연결한다.
- kh-skill-reverse-engineer / kh-skill-reverse-engineering: 개발물·파일·프로토콜의 동작 분석에 재사용한다.
- 마케팅·영상·글·개발·디자인 담당: 획득한 지식을 실제 결과물에 적용한다.
- kh-skill-agent-builder: 정본·설치·선택 경로를 갖추는 제작 기준으로 사용한다.

현재 Astra 세션에서는 같은 전문 기준을 직접 적용한다. 에이전트 파일을 설계한다는 이유로 하위 에이전트를 생성하거나 외부 AI에 판단을 위임하지 않는다.

제작 작업 EA-A01에는 설정 저장소의 정본·설치본·등록·선택 경로까지 포함한다. 이 착수 계획만으로 새 스킬·에이전트가 설치되었다고 보고하지 않는다.

## 5. 전문 지식은 어떻게 보관하고 쓰게 할 것인가

~~~mermaid
flowchart TD
    A["분야와 자료"] --> B["필요한 자료 확보"]
    B --> C["입력에 맞는 방법으로 노하우 추출"]
    C --> D["원본과 연결된 전문 지식"]
    D --> E["실무서·실행 스킬·도구"]
    E --> F["현재 업무에 적용"]
    F --> G["수정·실패·복구 경험"]
    G --> D
    G --> B
~~~

원본 파일과 기존 PostgreSQL 설계를 기본으로 한다. 업무 지식의 뜻과 관계는 기존 OWL/SHACL 설계에 연결한다. 관계 검색이 필요하면 기존 관계표를 먼저 쓰고, 실제 부족한 기능이 확인되는 곳에서 LightRAG 같은 추가 엔진을 선택한다. GraphRAG·Graphiti·Hindsight 등 후보를 전부 한꺼번에 넣지 않는다.

지식 한 건에는 원본 위치, 실제 관찰인지 추론인지, 통하는 조건, 쓰지 않을 조건, 행동 순서, 도구·설정, 결과물, 예외·복구, 시간·버전이 연결되어야 한다. 세련미 같은 감각은 비교 예시·채택/기각·수정 전후도 보존한다.

실무서와 실행 스킬은 같은 근거에서 만든다. 실행 모델에 따라 필요한 설명의 상세 수준이나 우회 방법은 달라질 수 있으므로 원 지식과 실행자별 지침을 분리한다.

모델 가중치 훈련은 실행 능력이 부족한 부분에 사용할 수 있는 후속 경로다. 모든 자료를 먼저 학습시켜야 이 공장을 시작할 수 있다는 조건을 두지 않는다.

## 7. 공개 자료만 있는 경우와 계정 자료도 있는 경우

계정 통계가 없어도 공개 결과물·작동 방식·시연·자료에서 얻을 수 있는 지식을 먼저 확보한다. 계정이 있어야 얻을 수 있는 지표를 AI가 추정해 실제 값처럼 채우지는 않는다.

| 대상 | 공개 자료에서 시작하는 경로 | 계정·원본이 있으면 더 깊게 하는 경로 |
|---|---|---|
| 네이버 검색·블로그 | 글·사이트·검색 관측·수정 이력·비교 사례 | 소유 블로그·사이트 통계, 운영 기록 |
| 구글 SEO·콘텐츠 | 사이트 구조·콘텐츠·검색 관측·버전 | Search Console의 검색어·페이지별 자료, 전환 기록 |
| 유튜브 | 영상·제목·썸네일·채널 구조·공개 반응 | 채널 Analytics·Studio의 시청·노출·수익 등 확보 가능한 상세 자료 |
| 광고 | 공개 소재·랜딩·공식 설명·운영 시연 | 광고 계정별 보고서·설정·변경·전환 기록 |
| SNS·커뮤니티 | 공개 게시물·대화·형식·계정 변화 | 소유 계정 통계·배포·유입·전환·운영 기록 |
| 전자책 | 책·목차·판매 페이지·리뷰·개정 이력 | 원고·편집 원본·판매·환불·비용·고객 반응 |

2026-10-20에 공식 자료에서 확인한 연결 조건:

- [네이버 블로그 검색 API](https://developers.naver.com/docs/serviceapi/search/blog/blog.md)는 검색 결과의 제목·링크·요약·작성일 등을 제공한다. 전문 본문이나 비공개 운영 성과를 주는 API로 취급하지 않는다. API 결과의 정렬과 실제 검색 화면의 모든 노출 영역을 같은 것으로 가정하지 않는다.
- [네이버 서치어드바이저 가이드](https://searchadvisor.naver.com/guide)는 웹사이트의 발견·색인 기본 요소를 다룬다. 네이버 블로그 운영 전체의 내부 작동 원리를 설명하는 자료로 확대하지 않는다.
- [Google Search Console Search Analytics](https://developers.google.com/webmaster-tools/v1/searchanalytics/query)는 인증된 속성의 검색 데이터를 조회한다. 임의 경쟁 사이트의 클릭·노출을 얻는 통로로 설계하지 않는다.
- [YouTube Data API](https://developers.google.com/youtube/v3/docs/videos)와 [채널 Analytics](https://developers.google.com/youtube/analytics/channel_reports)를 구분한다. 공개 조회수만으로 비공개 클릭률·시청 유지·매출까지 알았다고 기록하지 않는다. 지표 정의와 적용 시점도 저장한다.
- [네이버 Search AD API](https://github.com/naver/searchad-apidoc)와 [Google Ads API](https://developers.google.com/google-ads/api/docs/start)는 해당 광고 계정의 인증·접근 구성을 요구한다. 네이버의 검색광고 API가 다른 모든 광고 상품까지 포괄한다고 가정하지 않는다.
- [X 지표 문서](https://docs.x.com/x-api/fundamentals/metrics)는 공개 지표와 소유 게시물의 비공개·광고/자연 지표에 대한 접근을 구분한다.
- Instagram·Threads의 공식 Insights 문서는 이번 웹 도구에서 본문을 가져오지 못했다. 지원 필드·계정 조건·발행 기능은 EA-D13·EA-D14에서 다시 확인한다. 그동안 공개 콘텐츠와 사용자가 제공할 수 있는 export를 사용하는 경로를 설계한다.

실제 계정 접속·수집 호출·게시·광고 집행은 이번 작업에서 하지 않았다. 계정 연결은 필요한 작업에 도달했을 때 구체적인 범위와 함께 다룬다. 공개 자료 분석과 기술 설계를 기다리게 하는 선행조건으로 두지 않는다.

**EA-K01: 추출한 전문 지식을 담을 공통 자료 규격을 만든다.**

이미 정한 18개 입력 경우를 다시 조사하는 대신, 소스 코드·영상·글·운영 통계가 각각 어떤 지식 객체로 남는지 실제 예시와 JSON Schema로 구체화한다. 그러면 추출 도구와 스킬이 같은 형식으로 자료를 넘길 수 있다.

이 일과 독립적으로 EA-R01~R08의 방법 연구와 EA-D01~D18의 분야별 원천 조사는 시작할 수 있다. 모든 연구가 끝날 때까지 각 작업을 묶어 기다리게 하지 않는다. 실행 모듈은 자기 연구와 공통 규격·입력 보관만 선행 입력으로 사용한다.

공통 스킬·에이전트 EA-A01은 규격과 입력 진단 방법이 준비되면 제작한다. 분야별 제작 EA-P01~P18은 자기 분야 조사·필요한 실행 모듈·지식/스킬 연결을 받아 진행한다. 상세한 선행 관계는 지도에 있다.

### 분야별 묶음의 완료 모습

각 분야에는 업무별 지식, 판단·제작·운영 방법, 예외·복구, 원문과 사례, 실행 스킬·도구, 실제 적용 기록이 있어야 한다. 현재 확보한 범위와 아직 계정·자료·구현이 필요한 범위를 구분한다.

획득 방법을 설계하고 자료를 쌓는 작업을 “효과 입증을 먼저 해야 시작할 수 있다”는 절차로 바꾸지 않는다. 실제 실행과 수정은 지식을 얻고 업무에 연결하는 과정에 넣는다. 20년차 수준을 달성했다는 판단과 문서·도구를 준비했다는 상태는 구별한다.
